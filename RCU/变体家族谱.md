# RCU 变体家族谱：读侧原语全景（Linux 6.6）

> 阅读目标：把散在分册各章的读侧原语收进**一张谱系图**——v6.6 的精确名册（`rcu_read_lock` 本体 + `_bh`/`_sched` 两个等价替身 + SRCU 双读者（`nmisafe` 在而 `lite` **不在**）+ RCU Tasks **三族**（classic/rude/trace——既有 tasks_rcu.md 只写了 classic，rude/trace 系本谱新增））；★**v5.0 三味统一史**（`_bh`/`_sched` 头注释原文："Before v5.0, rcu_read_lock() and rcu_read_lock_bh() were **unrelated**"——独立 `rcu_state` 时代的死旁支）；等待面的 expedited 与 **poll 三段式**（`get_state`/`start_poll`/`poll_state`——"零开销等"的第四种姿势）；六维选型决策表。全部对照 v6.6 当轮核对。前置：[基本概念](docs/基本概念.md)｜[tree RCU](tree_rcu.md)｜[preempt RCU](preempt_rcu.md)｜[SRCU](srcu.md)｜[tasks RCU](tasks_rcu.md)。

## 一、谱系总图

```
                       RCU 家族（v6.6 现役）
                              │
        ┌──────────┬──────────┼──────────────┬─────────────┐
   普通 RCU        RCU-bh    RCU-sched       SRCU         RCU Tasks（三族）
   rcu_read_      rcu_read_ rcu_read_       srcu_read_    classic / rude / trace
   lock()         lock_bh() lock_sched()    lock()        （tasks.h 三处
        │             │          │              │          DEFINE_RCU_TASKS）
        └──────┬─────┴────┬─────┘              │
           统一 GP（v5.0 起）            独立 per-struct GP
           （preempt 容忍度双形态）        （可睡眠读者）
```

★关键事实：左三支**不再是独立 GP 引擎**——v5.0 起三者共享同一 grace period（见 §三），`_bh`/`_sched` 退化为"顺带禁软中断/禁抢占"的等价替身；真正各自为政的只有 SRCU（每 `srcu_struct` 一个 GP）与 RCU Tasks 三族（task 级 GP）。

## 二、读侧名册（v6.6 逐项）

### 2.1 rcu_read_lock()（include/linux/rcupdate.h:745-752）

```c
static __always_inline void rcu_read_lock(void)
{
	__rcu_read_lock();          /* 双形态：PREEMPT_RCU=n → preempt_disable；
	                                PREEMPT_RCU=y → 嵌套计数（读者可被抢占！）*/
	__acquire(RCU);
	rcu_lock_acquire(&rcu_lock_map);
	RCU_LOCKDEP_WARN(!rcu_is_watching(),
			 "rcu_read_lock() used illegally while idle");
}
```

头注释的三块金子：
- **语义保证**："synchronize_rcu() is guaranteed to block until after all the other CPUs exit their critical sections"——读侧跨 CPU 的全序承诺
- **★v5.0 强化**："In v5.0 and later kernels, synchronize_rcu() and call_rcu() **also wait for regions of code with preemption disabled**, including regions of code with interrupts or softirqs disabled. In pre-v5.0 kernels, which define synchronize_sched(), only code enclosed within rcu_read_lock() and rcu_read_unlock() are guaranteed to be waited for."
- 紧随其后的彩蛋注释："So where is **rcu_write_lock()**? It does not exist, as there is no way for writers to lock out RCU readers. **This is a feature, not a bug** -- this property is what provides RCU's performance benefits."

`rcu_read_unlock()` 注释另许了一条免死金牌："In recent kernels that have consolidated synchronize_sched() and synchronize_rcu_bh() into synchronize_rcu(), this deadlock immunity also extends to the scheduler's runqueue and priority-inheritance spinlocks, courtesy of the quiescent-state deferral that is carried out when rcu_read_unlock() is invoked with interrupts disabled."

### 2.2 rcu_read_lock_bh()（:786-806）

```
语义：local_bh_disable() + lockdep 映射（无独立 GP！）
头注释原文："This is equivalent to rcu_read_lock(), but also disables
 softirqs. Note that anything else that disables softirqs can also
 serve as an RCU read-side critical section. However, please note
 that this equivalence applies only to v5.0 and later. Before v5.0,
 rcu_read_lock() and rcu_read_lock_bh() were unrelated."
约束："must occur in the same context"（跨任务/上下文配对非法）
```

### 2.3 rcu_read_lock_sched()（:826-844）

```
语义：preempt_disable() + lockdep 映射（同无独立 GP）
头注释原文："Read-side critical sections can also be introduced by
 anything else that disables preemption, including local_irq_disable()
 and friends."——禁抢占即读侧（irq 关闭区域自然覆盖）
变体：rcu_read_lock_sched_notrace()（:847-851）——"Used by lockdep and
 tracing: cannot be traced, cannot call lockdep."（自举免递归）
```

### 2.4 SRCU 双读者（include/linux/srcu.h）

| 读者 | 行号 | 语义 | 备注 |
| :--- | :--- | :--- | :--- |
| `srcu_read_lock()` | :210-218 | 返回 idx（配对 unlock 用）；**可睡眠** | 同上下文配对约束（头注释原话 "it is illegal to invoke srcu_read_unlock() in an irq handler if the matching srcu_read_lock() was invoked in process context"）；间接等 GP 技巧——"one way to indirectly wait on an SRCU grace period is to acquire a mutex that is held elsewhere while calling synchronize_srcu()" |
| `srcu_read_lock_nmisafe()` | :226-233 | NMI 安全（`srcu_check_nmi_safety(ssp, true)`） | ★6.6 **有**此变体 |
| `srcu_read_lock_notrace()` | :236+ | notrace 免递归 | 追踪子系统自举用 |
| ~~`srcu_read_lock_lite()`~~ | — | **6.6 无**（更晚版本才加） | 谱系精确性：勿混淆 |

### 2.5 RCU Tasks 三族（kernel/rcu/tasks.h）

三处 `DEFINE_RCU_TASKS`（:1010/:1188-1189/:1357-1358）——**三族共享骨架、各自 GP 语义**：

| 族 | DEFINE 名 | GP 等待谁 | 读侧原语 | 适用 |
| :--- | :--- | :--- | :--- | :--- |
| **RCU Tasks**（classic） | `rcu_tasks`（:1010） | "RCU Tasks"——**任意任务的一次调度**（voluntary 上下文切换） | 无显式读原语——**用户态代码全程都是读者** | 替 synchronize_sched 清理 kprobe 蹦床等（[tasks_rcu.md](tasks_rcu.md) 详） |
| **RCU Tasks Rude** | `rcu_tasks_rude`（:1188） | "RCU Tasks Rude"——preempt_disable 区域 | 亦无显式原语——禁抢占即读侧 | 等价老 RCU-sched 的 task 视角版 |
| **RCU Tasks Trace** | `rcu_tasks_trace`（:1357） | "RCU Tasks Trace"——显式读区 | **`rcu_read_lock_trace()`**（rcupdate_trace.h:52-60） | BPF/tracing 需要轻量可抢占读侧 |

`rcu_read_lock_trace()` 的实现精华（rcupdate_trace.h:52-60）：

```c
	WRITE_ONCE(t->trc_reader_nesting, READ_ONCE(t->trc_reader_nesting) + 1);
	barrier();
	if (IS_ENABLED(CONFIG_TASKS_TRACE_RCU_READ_MB) &&
	    t->trc_reader_special.b.need_mb)
		smp_mb(); // Pairs with update-side barriers
```

——普通读者**只需一次嵌套计数自增**；memory barrier 是可选项（`CONFIG_TASKS_TRACE_RCU_READ_MB`，IPI 免费配送时才需要）。

tasks.h 自带的适用性说明（:832）："Finally, this implementation does not support **high call_rcu_tasks() invocation rates**"——吞吐是三族共同的短板。

## 三、★v5.0 三味统一史（死旁支考古）

```
史前（<5.0）：三个独立 rcu_state
    rcu_state（rcu_preempt/rcu_sched 分立）+ rcu_bh_state
    —— rcu_read_lock_bh 的 GP 与 rcu_read_lock 的互不相认
现代（≥5.0）：单 rcu_state（tree.c）
    rcu_read_lock / _bh / _sched 的读侧互相可见
    —— 头注释原话："Before v5.0, rcu_read_lock() and
       rcu_read_lock_sched() were unrelated."
死旁支名录：synchronize_sched / synchronize_rcu_bh / call_rcu_sched
    （v6.6 全树仅存历史注释里的提及）
幸存的语义分层：
    抢占容忍度：PREEMPT_RCU=y 的 rcu_read_lock 可睡眠化边界
                （[preempt_rcu.md](preempt_rcu.md)）
    上下文代价：_bh 顺带禁软中断 / _sched 顺带禁抢占——
                "替身"的价值只剩读侧副作用
```

## 四、写侧与等待面：四个消费姿势

```
① call_rcu 家族：异步——回调延后 GP（kfree_rcu/kvfree_rcu 批量化）
② synchronize 家族：阻塞等待（synchronize_rcu / synchronize_srcu /
                    synchronize_rcu_tasks*）
③ expedited 家族：加急——IPI 主动催 QS
    synchronize_rcu_expedited（rcutree.h:36）
    start_poll_synchronize_rcu_expedited（rcutree.h:78）
④ ★poll 三段式（rcutree.h / rcutiny.h:35-49）：零开销等
    cookie = get_state_synchronize_rcu()        /* 只取号 */
    ...干别的活...
    if (poll_state_synchronize_rcu(cookie))     /* 只查询——GP 已过？
        /* 无需等待，继续 */                     /*   未过也不等！*/
    else
        cond/synchronize 兜底
    ——把"等待"拆成"取号+轮询"，轮询不中再付费等待
```

## 五、六维选型决策表

| 原语 | 可睡眠 | NMI | 抢占容忍 | 读侧开销 | GP 粒度 | 典型场景 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| `rcu_read_lock`（!PREEMPT） | ✗ | ✗ | 禁抢占 | ~0（preempt_disable） | 全局 | 热路径指针读 |
| `rcu_read_lock`（PREEMPT_RCU） | ✗ | ✗ | **可被抢占** | 计数自增 | 全局 | 低延迟内核热路径 |
| `rcu_read_lock_bh` | ✗ | ✗ | 禁软中断 | local_bh_disable | 全局（同①） | 网络收包路径 |
| `rcu_read_lock_sched` | ✗ | ✗ | 禁抢占 | preempt_disable | 全局（同①） | 任何禁抢占区 |
| `rcu_read_lock_sched_notrace` | ✗ | ✗ | 同上 | 同上-锁dep | 同上 | tracing 自举 |
| `srcu_read_lock` | **✓** | ✗ | 全容忍 | idx 自增+计数 | per-struct | 驱动/可睡眠读 |
| `srcu_read_lock_nmisafe` | ✓ | **✓** | 全容忍 | 同上+无锁约束 | per-struct | NMI（perf/hardlockup） |
| （RCU Tasks classic） | ✓（用户态即读者） | — | — | **0**（无需原语） | task 级 | 低频全系统清理 |
| （RCU Tasks Rude） | ✗ | — | 禁抢占即读侧 | 0 | task 级 | 替老 RCU-sched |
| `rcu_read_lock_trace` | ✓（可抢占） | ✗ | 全容忍 | **计数自增**（MB 可选） | task 级 | BPF/tracing |

选型口诀：**热路径要零开销→普通 RCU（PREEMPT 形态定抢占容忍）；要睡→SRCU；NMI 里要读→SRCU 的 nmisafe；tracing 要轻→Tasks Trace；全系统清理→Tasks classic。**

## 六、观测实战

```bash
# 1) 家族自检——rcutorture 逐类型灌压（kernel/rcu/rcutorture.c:127 默认 "rcu"）
#   可选 torture_type：rcu / srcu / srcud / tasks / tasks_rude / tasks_trace...
modprobe rcutorture torture_type=srcu  # 对应 .rst 镜像（RCU/torture.rst）详表
rmmod rcutorture && dmesg | tail        # 自检结论（SUCCESS/FAILURE）

# 2) GP 卡顿定位（各族共用 stall 告警家族——RCU/stallwarn.rst 镜像）
dmesg | grep -i 'rcu.*stall\|self-detected'

# 3) 读侧违规
dmesg | grep 'used illegally while idle'   # §二 的 RCU_LOCKDEP_WARN 触发
#   例：idle 循环里进读区（!rcu_is_watching）——lockdep CONFIG_PROVE_RCU

# 4) expedited 的 IPI 开销观测
grep expedited /proc/vmstat? —— 正确位面：
cat /sys/kernel/debug/tracing/events/rcu/trace_rcu_exp/...  # expedited tracepoint
```

## 七、思考题

1. v5.0 统一后 `rcu_read_lock_bh` 还剩什么独立价值？（提示：GP 已共享；剩余价值=读侧副作用（禁软中断）与 lockdep 映射（rcu_bh_lock_map）——选它是在选"读侧上下文代价"而非"另一种 GP"。）
2. `srcu_read_lock` 返回 idx 而 `rcu_read_lock` 无返回值——为什么 SRCU 需要配对凭证？（提示：SRCU 双相计数（读者按 idx 分桶）——unlock 必须归还进当初的桶；普通 RCU 的读侧无桶。）
3. RCU Tasks classic 为什么可以"没有读原语"？（提示：GP 等待的是**每个任务发生一次调度**——用户态/中断/任何不在读区的状态天然是"静默态"；显式原语反而是冗余。）
4. `rcu_read_lock_trace` 的 `need_mb` 为什么要做成条件执行？（提示：写侧用 IPI 强制读者 barrier 时读侧免费；IPI 不可用时才需要读侧自配——`CONFIG_TASKS_TRACE_RCU_READ_MB` 的选择即"读侧付一次 smp_mb 换写侧省 IPI"。）
5. poll 三段式与 synchronize 的本质差异在哪？（提示：poll 的两次调用之间**没有阻塞点**——把"等 GP"从时间轴上抹掉；代价是逻辑分叉（过/未过两分支都要写对）。）
6. 为什么 SRCU 需要 nmisafe 而 RCU 不需要？（提示：普通 RCU 的读侧=preempt_disable/计数——NMI 里天然可做且 QS 上报无需 NMI 参与；SRCU 的计数与唤醒路径用了可能被 NMI 打爆的原语（srcu_data 锁/唤醒）——nmisafe 换成 NMI 可用实现。）
