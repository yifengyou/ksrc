# 基本概念

如果你的目标是“作为 Linux 6.6 内核专家掌握 RCU（Read-Copy Update）”，那你需要达到的程度，不是“会用 API”，而是：

> 能从 CPU cache、一致性模型、调度器、中断、内存屏障、grace period、callback pipeline、Tree RCU 分层结构，一直理解到源码实现与性能权衡。

Linux 内核里，RCU 是最核心、最难、也是最“内核味”的并发原语之一。

它不仅是一个同步机制，而是一整套：

* 并发读优化思想
* 延迟回收机制
* 内存排序协议
* per-cpu 批处理系统
* scheduler 协同框架

在 Linux 6.6 中：

* VFS
* networking
* task list
* cgroup
* BPF
* routing table
* fdtable
* dentry cache
* namespace
* slab 回收

都大量依赖 RCU。

你如果真正掌握 RCU，基本已经进入：

> Linux kernel concurrency expert

级别。

```c

```

---

## 2. 理解核心思想

必须真正理解：

RCU ≠ 锁

而是：

* reader 不加锁
* writer copy
* old version 延迟释放

经典流程：

```text
reader:
    rcu_read_lock()
    p = rcu_dereference(gp)
    use(p)
    rcu_read_unlock()

writer:
    new = copy(old)
    modify(new)
    rcu_assign_pointer(gp, new)
    synchronize_rcu()
    free(old)
```

这是最基础的。

---

# Level 2：理解 grace period（真正入门）

这是 RCU 最核心概念。

必须理解：

> 什么叫 “所有旧 reader 都退出了”？

RCU 不追踪 reader 引用计数。

RCU 的核心是：

> grace period（宽限期）

定义：

> 所有在 GP 开始前进入 RCU read-side critical section 的 reader 全部退出。

---

## 必须理解：

### 为什么：

```c
rcu_read_lock();
```

几乎零开销？

因为：

* 不加锁
* 不原子操作
* 不 cacheline bouncing

在 PREEMPT=n 下：

```c
preempt_disable();
```

即可。

---

## 必须理解 quiescent state

这是 RCU 的灵魂。

CPU 出现以下情况：

* context switch
* idle
* user mode
* voluntary scheduling

说明：

> 之前 reader 已结束

这叫：

```text
QS = Quiescent State
```

# 二、必须掌握的核心数据结构

---

# 1. struct rcu_state

全局 RCU 状态。

源码：

```c
kernel/rcu/tree.c
include/linux/rcu_segcblist.h
```

核心字段：

```c
struct rcu_state {
    struct rcu_node node[NUM_RCU_NODES];
    unsigned long gp_seq;
}
```

表示：

* 当前 GP 编号
* RCU 树
* callback 管理

---

# 2. struct rcu_node

这是 Tree RCU 核心。

你必须理解：

RCU 为什么可扩展到几千 CPU？

答案：

> 分层树聚合

结构：

```text
                root
             /    |    \
          node  node  node
          / \    / \
        cpu cpu cpu cpu
```

每个节点：

* 管理一组 CPU
* 聚合 quiescent states
* 减少全局锁竞争

这是 Linux RCU scalability 核心。

---

# 3. struct rcu_data

per-cpu RCU 数据。

关键：

```c
struct rcu_data {
    struct rcu_segcblist cblist;
}
```

管理：

* callback 队列
* GP 状态
* dynticks
* nocb

# 三、必须理解 callback pipeline

这是很多人不会的。

---

# call_rcu() 到底发生什么？

```c
call_rcu(&head, func);
```

不是立即执行。

流程：

```text
call_rcu()
    ↓
放入 per-cpu callback list
    ↓
等待 GP 完成
    ↓
softirq/kthread 执行 callback
    ↓
func(head)
```

---

# callback 分段链表

Linux 6.6：

```text
DONE
WAIT
NEXT_READY
NEXT
```

源码：

```c
struct rcu_segcblist
```

必须深入。

这是 callback batching 核心。

# 四、必须掌握内存屏障（极其重要）

不懂 memory ordering：

> 不可能真正懂 RCU。

---

# 1. rcu_assign_pointer()

本质：

```c
smp_store_release()
```

确保：

```text
初始化对象
    happens-before
发布指针
```

---

# 2. rcu_dereference()

本质：

```c
smp_load_acquire()
```

确保：

reader 看到完整初始化对象。

---

# 3. 为什么不能直接：

```c
gp = new;
```

因为：

CPU reorder + compiler reorder。

会导致：

reader 看到未初始化字段。

这是 RCU 最核心知识之一。

因为：

所以：


# 十三、必须理解与其它机制的区别

这是面试高频。

---

# RCU vs rwlock

RCU：

* reader 极快
* writer 慢
* 最终一致

rwlock：

* reader 仍有 cache contention

---

# RCU vs seqlock

seqlock：

* reader 可能 retry

RCU：

* reader 不 retry
* 支持复杂结构

---

# RCU vs hazard pointer

用户态 lock-free 常见。

必须知道区别。
