## 一、allocator.rs：GlobalAlloc → krealloc（已核对 6.6）

```rust
struct KernelAllocator;   // 全局分配器的唯一宿主
unsafe impl GlobalAlloc for KernelAllocator {
    alloc → krealloc_aligned(null, layout, GFP_KERNEL)   // :46
    realloc → krealloc_aligned(ptr, layout, GFP_KERNEL)  // :67
    alloc_zeroed → GFP_KERNEL | __GFP_ZERO               // :70-77
}
krealloc_aligned 的三个桥接细节（:18-…）：
  ① pad_to_align()：Rust Layout 允许 size < align——先补齐再换算
  ② align > BINDINGS_ARCH_SLAB_MINALIGN：对齐超 slab 保证 →
     扩 size 走"对齐搜索"（C 侧 kmalloc 的老技巧）
  ③ 由 krealloc 一次性完成分配（realloc 语义直通）
★含义：Rust 侧的 Box/Vec（no_std 全局分配器路径）最终全部
  落在内核 slab 上——与 C 的 kmalloc 同源同池
```

## 二、error.rs：errno 的类型化（已核对）

```rust
pub struct Error(core::ffi::c_int);   // :95
// 不变式（文档原样）："The value is a valid `errno`
//  (i.e. `>= -MAX_ERRNO && < 0`)"
from_errno: 入口即校验范围（:102-103——越界 panic 式防呆）
to_result(err: c_int) -> Result   // :243 —— C 返回值的惯用收口
桥接族：From<Error> for c_int（FFI 出口）、to_ptr_err/from_ptr_err?
Result<T> = core Result<T, Error>（crate 级别名——错误处理唯一货币）
```

## 八、思考题

1. `krealloc_aligned` 为什么不直接用 `Box` 语义的实现而要自己 pad_to_align？（对照 C kmalloc 的对齐契约。）
2. `Error` 用 `c_int` 而非 `Errno` 枚举——ABI 稳定性的取舍？（提示：errno 空间随内核版本增长。）
3. `current()` 返回 `Deref` 而非 `Arc<Task>`——谁来保证借用期安全？（对照调度器的 current 宏。）
4. kunit_assert 走 FFI 而非纯 Rust panic——报告一致性的收益？（KUnit 统一收口。）
5. `AlwaysRefCounted` 的 unsafe 性从哪来？（inc_ref 的"对象必活"前提——文档 :280 的约束。）
