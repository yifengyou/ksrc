# cache

## page cache和buffer cache区别联系

在 Linux 操作系统和内核的语境下，通常提到的 **Cache 确实就是指 Page Cache（页缓存）**，而 **Buffer 指的就是 Buffer Cache（块缓存）**。

### 📌 核心定义与区别

在 Linux 内核中，这两者的分工非常明确，可以用一句话来概括：**Cache 缓存的是“文件的内容”，而 Buffer 缓存的是“文件的目录/索引（元数据）”**。

*   **Cache (Page Cache)**：主要面向文件系统。它以“页（Page，通常为 4KB）”为单位，缓存普通文件的实际数据。当你使用 `read()` 或 `write()` 读写文件时，操作的对象就是 Page Cache。
*   **Buffer (Buffer Cache)**：主要面向底层的块设备（如硬盘）。它以“块（Block，如 512B 或 4KB）”为单位，缓存文件系统的元数据（比如记录文件权限、位置的 inode、超级块等）。

为了更直观地对比，可以参考下表：

| 对比维度 | Buffer (块缓存) | Cache (页缓存) |
| :--- | :--- | :--- |
| **缓存对象** | 磁盘块的元数据（inode、目录项等） | 文件的实际数据内容 |
| **面向层级** | 面向底层的块设备（Block Device） | 面向文件系统（File System） |
| **核心作用** | 协调不同设备间的速度差异（缓冲“写”） | 减少对磁盘的重复访问（加速“读”） |

### 🔄 现代内核中的演变与融合

虽然概念上泾渭分明，但在实际的 Linux 系统（特别是 2.6 版本以后的现代内核）中，它们的界限已经变得非常模糊，这也是为什么在 `free -h` 命令中它们经常被合并显示为 `buff/cache` 的原因。

**1. 底层实现的统一**
在现代 Linux 内核中，Buffer Cache 已经被整合进了 Page Cache 的框架中。内核在管理内存时，统一以“页（Page）”为最小单位。当需要缓存底层的磁盘块（Buffer）时，内核会将这些块映射到 Page Cache 中的某个页里。也就是说，**Buffer Cache 实际上成为了 Page Cache 的一部分或底层支撑**。

**2. 统计口径的独立**
尽管底层实现融合了，但在内存统计上，内核依然保留了各自的计数器。当你查看 `/proc/meminfo` 文件时，依然能看到两个独立的字段：
*   **`Buffers`**：专门统计用于底层块设备 I/O 的内存（如文件系统的日志 journal、磁盘元数据等）。
*   **`Cached`**：专门统计用于普通文件数据读写的 Page Cache 内存。

**总结来说：**
当我们在 Linux 性能分析或日常交流中提到 Cache 和 Buffer 时，指的就是 Page Cache 和 Buffer Cache。虽然在现代内核的底层实现中，Buffer 已经“寄生”在 Page Cache 之中，但在逻辑功能和内存统计上，它们依然保留着各自明确的职责。
