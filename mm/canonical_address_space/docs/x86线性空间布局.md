# x86线性空间布局

在 x86 架构的 32 位 Linux 系统中，每个进程拥有 **4GB 的虚拟地址空间（线性地址空间）**，该空间被划分为 **用户空间（User Space）** 和 **内核空间（Kernel Space）**。这种划分是为了保障系统安全与稳定性，防止用户程序直接访问或修改内核数据。

---

## 一、整体布局（从低地址到高地址）

| 地址范围 | 区域 | 大小 | 说明 |
|----------|------|------|------|
| `0x00000000` ~ `0xBFFFFFFF` | 用户空间 | 3 GB | 每个进程私有 |
| `0xC0000000` ~ `0xFFFFFFFF` | 内核空间 | 1 GB | 所有进程共享 |

> 注：`0xC0000000 = 3 * 2^30 = 3GB`

---

## 二、用户空间详细布局

用户空间由以下主要内存段组成（从低地址向高地址排列）：

### 1. **保留区（Reserved Area）**

- 地址：0x00000000 ~ 0x00000FFF（前 4KB）
- 大小：4KB（1 页）
- 作用：禁止访问。捕获空指针解引用、越界访问，访问直接触发 SIGSEGV 段错误。 
- 权限：无读写执行权限。
- 通常不可访问，访问会触发段错误（Segmentation Fault）

### 2. **只读代码段（Text Segment / .text）**

- 地址：`0x00001000` 开始（随 ELF 加载基址变化，默认经典基址 `0x08048000`）
- 内容：程序二进制指令、常量字符串、只读数据（`.rodata`）
- 权限：**读 + 执行，禁止写，可共享（多个进程运行同一程序时共享此段）**
- 特点：
    - 多个进程执行同一程序时，代码段**物理内存共享**（写时复制 COW）
    - 大小固定，由 ELF 文件决定，运行时不增长

### 3. **只读数据段（Read-only Data Segment / .rodata）**

- 存放常量字符串、全局 const 变量等
- 只读属性，防止意外修改

### 4. **数据段（Data Segment / .data）**

- 位置：紧跟代码段之后
- 内容：**已初始化的全局变量、静态变量**（`.data` 节）
- 权限：读 + 写，不可执行
- 特点：进程私有，每个进程独立副本。
- 存放已初始化的全局变量和静态变量
- 可读写

### 5. **BSS 段（Block Started by Symbol / .bss）**

- 位置：紧跟 Data 段之后
- 内容：**未初始化全局变量、静态变量**（`.bss` 节）
- 特点：
    - ELF 文件中不占用磁盘空间，运行时内核清零分配
    - 权限：读 + 写，不可执行
- 存放未初始化或初始化为 0 的全局/静态变量
- 不占用可执行文件空间（运行时由内核清零分配）

### 6. **堆（Heap）**

- 起始地址：`brk` 指针位置，紧跟 BSS 段末尾
- 增长方向：**向上增长（低地址 → 高地址）**
- 管理接口：`malloc/free` → 底层调用 `brk()` / `mmap()`
- 特点：
    - 动态内存区，运行时手动申请/释放
    - 经典实现：小内存用 `brk` 扩展堆顶，大内存直接走匿名 mmap
    - 权限：读 + 写
- 通过 `malloc()`、`new` 等动态分配内存
- 向高地址增长
- 由程序员手动管理（或通过垃圾回收机制）

### 7. **内存映射区（Memory Mapping Segment）**

- 位置：堆上方、栈下方之间的大片空闲区域
- 地址范围：跨度极大，是用户空间**最大的动态区域**
- 用途：
    1. 动态链接库（`.so` 共享库）加载
    2. 文件内存映射（`mmap` 读/写文件）
    3. 大尺寸匿名内存分配、共享内存、动态库、栈扩展等
- 权限：根据用途可变（读/写/执行）
- 补充：现代 Linux 会把大堆分配、动态库全部放在此区域，隔离堆与栈。
- 用于：
    - 动态链接库（如 `.so` 文件）
    - `mmap()` 映射的文件或设备
    - 共享内存
- 通常位于堆和栈之间

### 8. **栈（Stack）**

- 起始地址：**高地址**（靠近 3G 边界 `0xBFFFFFFF`）
- 增长方向：**向下增长（高地址 → 低地址）**
- 大小：默认有限（默认 8MB 左右，可通过 `ulimit -s` 修改）
- 内容：
    - 函数局部变量、函数参数、返回地址、栈帧、寄存器现场
    - 命令行参数、环境变量（位于栈**最顶端**）
- 特点：
    - 线程私有：**主线程一个用户栈，每个新线程拥有独立栈**
    - 栈溢出（栈向下越界）直接触发段错误
- 边界：栈顶之上紧邻 **用户/内核空间分界线**。
- 存放函数调用时的局部变量、参数、返回地址等
- 向低地址增长（从高地址往低地址扩展）
- 每个线程有自己的栈
- 默认大小有限（可通过 `ulimit` 调整）

### 9. **命令行参数与环境变量（argv / envp）**

- 位于栈的上方（最高用户地址附近）
- 程序启动时由操作系统填充

## 三、内核空间详细布局

* 内核空间对所有进程是 **共享且一致的**，即每个进程的高 1GB 虚拟地址都映射到相同的内核物理内存。
* 这 1GB **所有进程完全共享**，进程切换时内核页表不切换，仅切换用户页表。 Linux 32 位标准内核 1G 空间，从**低地址（0xC0000000）→ 高地址（0xFFFFFFFF）** 分为 5 大固定区域，布局**内核编译时固定**。
* `PAGE_OFFSET = 0xC0000000`：内核线性空间起始地址（经典 3G/1G 分割标志）
* 物理内存 < 896MB 与 > 896MB 布局有明显区别（**高端内存 HighMem** 是重点）

### 1. **直接映射区（Direct Mapping Area）**

地址范围: `0xC0000000 ~ 0xF7FFFFFF`
修正计算：
总大小：**896MB**
- 映射规则：**线性一对一映射**
  `内核线性地址 = 物理地址 + PAGE_OFFSET(0xC0000000)`
  `物理地址 = 内核线性地址 - 0xC0000000`
  
- 地址范围：`0xC0000000` ~ `~896MB`（具体取决于配置）
- 将物理内存的前 896MB 直接线性映射（偏移 `PAGE_OFFSET = 0xC0000000`）
- 用于高效访问低地址物理内存

核心特性:
1. **无页表开销**：地址换算仅做加减法，访问极快
2. 内核**绝大多数核心数据**都放在这里：
  - 内核代码段、内核数据段、内核 BSS
  - 内核栈、进程描述符 `task_struct`
  - 伙伴系统（Buddy）、SLUB/SLUB 内存池、页描述符 `struct page`
  - 内核全局变量、硬件寄存器、DMA 缓冲区
3. 限制：**只能映射物理内存前 896MB**
   物理内存超过 896MB 的部分，无法进入直接映射区，归入 **高端内存**。

内部细分（直接映射区内部段）:
在 896MB 直接映射区内，又按 ELF 规则划分内核自身段：
1. **内核代码段 (.text)**
   内核指令、中断处理函数、系统调用入口，**只读+可执行**
2. **内核只读数据段 (.rodata)**
   内核常量、字符串，只读
3. **内核数据段 (.data)**
   内核已初始化全局变量，读写
4. **内核 BSS 段 (.bss)**
   内核未初始化全局变量，运行时清零，读写
5. **内核栈**
   每个进程/中断上下文都有独立内核栈，位于直接映射区。


### 2. **高端内存区（High Memory / vmalloc Area）**

地址范围:
`0xF8000000 ~ 0xFF7FFFFF`
大小：**120MB**

背景:
32 位 1G 内核空间中，前 896MB 固定映射物理低内存，剩余物理内存（>896MB）无法直接线性寻址，必须通过**临时页表映射**访问，这部分物理内存称为 **高端内存（HighMem）**。

功能分区:
1. **永久映射区（PKMAP）**
   少量固定页表项，用于长期映射高端物理页，数量有限。
2. **临时映射区（Fixmap / 临时内核映射）**
   大量临时页槽，内核临时借用地址访问高端内存，用完立即释放。
3. **临时页表、高端内存页表管理结构**

特点:
- 没有固定线性地址 ↔ 物理地址关系，**动态页表映射**
- 访问速度慢于直接映射区（需要修改页表）
- 大内存 32 位 Linux 必须依赖此区域访问 896MB 以上物理内存
  
- 用于映射超过 896MB 的物理内存（即“高端内存”）
- 使用 `vmalloc()` 分配，页表非连续
- 也用于模块加载、I/O 映射等

### 3. **持久内核映射区（Persistent Kernel Mappings）**

- 用于长期映射高端内存页

### 4. **固定映射区（Fixed Mappings）**

- 地址：`0xFF800000 ~ 0xFFBFFFFF`
- 作用：内核预留**固定虚拟地址**，专门映射特定硬件、特殊页面。
- 用途：
  - 早期 I/O 设备、BIOS 区域、特殊寄存器
  - 内核一些必须使用**固定地址**的功能（不随内核配置变化）
- 特点：地址编译期硬编码，不用于常规内存分配。

- 用于特殊用途（如 APIC 寄存器等硬件映射）

> 注：不同内核版本可能略有差异，但总体结构保持一致。

## 5. **内核页表自映射区（Page Tables）**

- 地址：`0xFFC00000 ~ 0xFFFFDFFF`
- 作用：**内核页表本身的线性映射**
  x86 页表也是内存页，内核把页表页映射到该区域，方便遍历、修改页表。
- 系统调用、进程地址空间切换、缺页异常都会操作此区域。

## 6. **保护区域 / 看门狗 / 预留区**
- 地址：`0xFFFFE000 ~ 0xFFFFFFFF`（最后几页）
- 用途：系统预留、异常处理、看门狗、机器检查、硬件故障上下文等。
- 普通内核内存分配不会使用这片地址。

## 四、关键特点总结

- **隔离性**：用户态无法直接访问内核空间，需通过系统调用陷入内核态。
- **共享性**：所有进程共享同一内核空间内容。
- **虚拟性**：每个进程看到的是独立的 4GB 虚拟空间，实际物理内存由 MMU 和页表管理。
- **安全性**：通过 CPU 特权级（Ring 0 / Ring 3）和页表权限位（R/W, U/S）实现保护。

---

## 地址顺序

用户空间（0 ~ 3GB）从上到下（高→低）:

```text
环境变量/命令行参数 → 用户栈 ↓ → mmap 动态库/文件映射 → 堆 ↑ → BSS → Data → Text → 零页保护区
```

内核空间（3GB ~ 4GB）从低→高:

```text
直接映射区(896MB 低物理内存) → 高端内存(HighMem) → 固定映射区 → 内核页表区 → 系统预留区
```

```text
0xFFFFFFFF  ┌──────────────────────────────┐
            │         Kernel Space         │  ← 高 1GB (0xC0000000–0xFFFFFFFF)
            │                              │
            │  fixmap                     │
            │  vmalloc area               │
            │  persistent/early ioremap    │
            │  module area (kernel modules)│
            │  direct mapping (PAGE_OFFSET)│
            │  VSYSCALL / VDSO (老版本)     │
            └──────────────────────────────┘
0xC0000000  ← PAGE_OFFSET (通常)
            ────────────────────────────────
            │         User Space           │  ← 低 3GB (0x00000000–0xBFFFFFFF)
            │                              │
            │  stack  (向下增长)            │
            │  ↓                           │
            │       (mmap 区域)             │
            │  ↑                           │
            │  heap   (向上增长)            │
            │  BSS                          │
            │  Data (.data)                 │
            │  Text (.text, .rodata)        │
            │  ELF headers / aux vector     │
            │  0x08048000 (经典 x86)         │
            └──────────────────────────────┘
0x00000000
```
