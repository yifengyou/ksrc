# x86_64五级页表线性空间布局

在 x86-64 架构下启用 **五级页表（5-level paging）** 后，虚拟地址空间从传统的 48 位扩展到 **57 位有效地址宽度**，从而将线性（虚拟）地址空间从 256 TiB 扩展至 **128 PiB**。这种扩展引入了新的 **canonical address（规范地址）** 布局，Linux 内核据此重新划分用户态与内核态的内存段。

---

## 一、总体地址空间结构（Canonical Address Layout）

x86-64 架构要求虚拟地址为 **canonical（规范）** 形式：
- 对于 **57 位有效地址**，高 7 位（bit 63–57）必须是 bit 56 的符号扩展。
- 因此整个 64 位地址空间被划分为两个 **canonical 区域**：
    - **低规范区（Lower canonical）**：`0x0000_0000_0000_0000` 到 `0x00FF_FFFF_FFFF_FFFF`
    - **高规范区（Upper canonical）**：`0xFF00_0000_0000_0000` 到 `0xFFFF_FFFF_FFFF_FFFF`
- 中间区域（`0x0100_0000_0000_0000` ~ `0xFEFF_FFFF_FFFF_FFFF`）为 **non-canonical**，访问会触发 #GP 异常。

Linux 将 **低规范区分配给用户空间**，**高规范区分配给内核空间**。

---

## 二、用户空间（User Space）

### 地址范围
- **起始**：`0x0000_0000_0000_0000`
- **结束**：`0x00FF_FFFF_FFFF_FFFF`
- **大小**：**128 PiB**

### 主要内存段及特性

| 段名 | 地址范围（典型） | 功能说明 |
|------|------------------|----------|
| **保留区 / NULL 指针保护区** | `0x0000_0000_0000_0000` ~ 几十 KiB | 防止空指针解引用；通常不可映射（通过 `vm.mmap_min_addr` 控制最低可映射地址） |
| **代码段（Text）** | 低位开始 | 存放可执行指令；通常只读、可执行 |
| **数据段（Data/BSS）** | 紧随代码段 | 初始化/未初始化全局变量；可读写 |
| **堆（Heap）** | 动态增长 | `brk`/`sbrk` 或 `malloc` 使用；向高地址增长 |
| **内存映射区（Memory Mapping Segment）** | 中高地址 | `mmap()` 映射文件或匿名内存；用于共享库、大块分配等 |
| **栈（Stack）** | 接近上限 | 用户栈；向低地址增长；支持递归和局部变量 |
| **vDSO / VVAR** | 高地址固定位置 | 内核提供的高效系统调用入口（如 `gettimeofday`）；只读 |

> 注意：具体布局受 ASLR（地址空间布局随机化）影响，但整体范围不变。

---

## 三、内核空间（Kernel Space）

### 地址范围
- **起始**：`0xFF00_0000_0000_0000`
- **结束**：`0xFFFF_FFFF_FFFF_FFFF`
- **大小**：**128 PiB**

### 主要内存段及特性（自低向高）

| 段名 | 地址范围（近似） | 功能说明 |
|------|------------------|----------|
| **直接映射区（Direct Mapping of Physical Memory）** | `0xFF00_0000_0000_0000` 开始 | 物理内存的线性映射（`__pa ↔ __va` 转换）；每个物理页在此有唯一虚拟地址；大小受限于实际 RAM（但预留巨大空间） |
| **vmalloc 区** | 直接映射区之上 | 内核动态非连续内存分配（`vmalloc()`）；用于大块或需页对齐的内存（如模块、I/O 映射） |
| **KASAN 影子区（若启用）** | 可能位于 vmalloc 附近 | Kernel Address Sanitizer 使用的元数据区 |
| **内核模块（Modules）** | 通常在 vmalloc 区 | 可加载内核模块的代码和数据 |
| **固定映射区（Fixed Mappings）** | 高地址 | 编译期确定的特殊用途映射（如 APIC、ACPI 表） |
| **CPU 入口区（CPU Entry Area）** | 接近最高地址 | per-CPU 的 IDT、GDT、TSS、入口跳板代码等；用于中断/异常处理 |
| **内核文本（Kernel Text）** | `0xFFFFFFFF_8000_0000` 起（兼容旧布局） | 内核 `.text`, `.rodata`, `.data` 等；只读或可写；部分仍使用传统 48 位偏移以兼容性 |

> 注：尽管启用了 5-level paging，内核文本段仍常保持在传统 48 位高地址（如 `0xFFFF_8000_0000_0000`），但其属于高规范区的一部分。

---

## 四、关键特性对比（四级 vs 五级页表）

| 特性 | 四级页表（48-bit） | 五级页表（57-bit） |
|------|---------------------|---------------------|
| 用户空间上限 | `0x0000_7FFF_FFFF_FFFF` (128 TiB) | `0x00FF_FFFF_FFFF_FFFF` (128 PiB) |
| 内核空间下限 | `0xFFFF_8000_0000_0000` | `0xFF00_0000_0000_0000` |
| 总虚拟地址空间 | 256 TiB | 256 PiB（128 PiB 用户 + 128 PiB 内核） |
| 页表层级 | PML4 → PDPT → PD → PT | PML5 → PML4 → PDPT → PD → PT |
| 支持 CPU | Intel Ice Lake+, AMD Zen 4+ | 同左 |
| Linux 默认启用 | ≤ 5.4 | ≥ 5.5 |
