# 核心数据结构

genirq 的全部行为都围绕五个结构体展开：`irq_desc`（中断描述符）→ 内嵌 `irq_data`（芯片视角的数据）→ 指向 `irq_chip`（芯片操作）与 `irq_domain`（翻译层）→ `action` 链（驱动 handler）。本章以 Linux 6.6 真实定义为准逐字段解读，并梳理贯穿其中的状态位体系与 per-CPU 统计。

### 🗺️ 结构关系总图

```
                    irq_domain (include/linux/irqdomain.h)
                   ┌─────────────────────────────────┐
                   │ ops(host_data, fwnode, parent)  │
                   │ revmap: linear[] + radix_tree   │
                   └───────▲──────────────┬──────────┘
                           │ domain       │ 翻译 hwirq↔virq
   ┌───────────────────────┴──────────────▼───────────────────────────┐
   │ struct irq_desc (include/linux/irqdesc.h)                         │
   │ ┌──────────────────────────────────────────────────────────────┐ │
   │ │ irq_common_data: state_use_accessors(IRQD_*), affinity,     │ │
   │ │                  handler_data, msi_desc                     │ │
   │ ├──────────────────────────────────────────────────────────────┤ │
   │ │ irq_data (内嵌!): irq, hwirq, common, chip, domain,         │ │
   │ │                  parent_data(层级), chip_data                │ │──→ struct irq_chip
   │ ├──────────────────────────────────────────────────────────────┤ │    (name, ack/mask/
   │ │ handle_irq: flow handler 指针                                │ │     eoi/set_affinity...)
   │ │ action ──────────────┐                                       │ │
   │ │ depth/wake_depth     │                                       │ │
   │ │ kstat_irqs (percpu)  │                                       │ │
   │ │ lock / request_mutex │                                       │ │
   │ └─────────────────────┼──────────────────────────────────────┘ │
   └─────────────────────────┼────────────────────────────────────────┘
                             ▼
              action 链 (共享中断时的多个 irqaction)
   ┌──────────────────┐      ┌──────────────────┐
   │ struct irqaction │ next │ struct irqaction │ ...
   │ handler          │─────→│ handler          │
   │ thread_fn/thread │      │ ...              │
   │ flags / dev_id   │      └──────────────────┘
   └──────────────────┘
        │ thread (内核线程 irq/NN-name)
        ▼
   irq_thread() → thread_fn(irq, dev_id)
```

关键内嵌关系：`irq_data` 直接**内嵌**在 `irq_desc` 里（不是指针），所以 `desc->irq_data` 永远有效；`irq_data->common` 回指 `desc->irq_common_data`，`irq_data_to_desc()` 用 `container_of(common)` 反查描述符。层级 domain 时 `irq_data->parent_data` 指向上一层 domain 的 irq_data（每个 domain 层次各有一份 irq_data，见第 4 章）。

### 🗂️ struct irq_desc —— 中断描述符

```c
// include/linux/irqdesc.h (v6.6, 原文)

	struct irq_common_data	irq_common_data;

	unsigned int		status_use_accessors;
	unsigned int		core_internal_state__do_not_mess_with_it;
	unsigned int		depth;		/* nested irq disables */
	unsigned int		wake_depth;	/* nested wake enables */
	unsigned int		tot_count;
	unsigned int		irq_count;	/* For detecting broken IRQs */
	unsigned long		last_unhandled;	/* Aging timer for unhandled count */
	unsigned int		irqs_unhandled;
	atomic_t		threads_handled;
	int			threads_handled_last;

#endif
#endif
	unsigned long		threads_oneshot;
	atomic_t		threads_active;
	wait_queue_head_t	wait_for_threads;
#ifdef CONFIG_PM_SLEEP
	unsigned int		nr_actions;
	unsigned int		no_suspend_depth;
	unsigned int		cond_suspend_depth;

#endif

#endif

#endif

	struct rcu_head		rcu;
	struct kobject		kobj;

	struct mutex		request_mutex;
	int			parent_irq;

	const char		*name;

```

逐字段解读（按语义分组）：

**① 身份与流控**
- `irq_common_data` / `irq_data`：见下节。`____cacheline_internodealigned_in_smp` 保证 desc 跨 NUMA 节点不共享缓存行——中断路径对 desc 的读写极频繁。
- `handle_irq`：highlevel flow handler 指针（`handle_level_irq` 等），在 domain map/`irq_set_handler_locked()` 时设定。这是 genirq 流控的入口，第 3 章的主角。
- `name`：flow handler 名，出现在 `/proc/interrupts` 最后一列（如 "IR-IO-APIC 23-edge"里的 "edge"）。

**② 驱动注册的 action 链**
- `action`：`struct irqaction` 单链表，共享中断（IRQF_SHARED）时多个驱动的 action 串在一起，`__handle_irq_event_percpu()` 依次调用。
- `threads_oneshot`：位图，每个 IRQF_ONESHOT 的 action 占一位（`action->thread_mask`），记录"有线程被唤醒且尚未跑完，保持 masked"。`cond_unmask_irq()` 检查它决定能否提前 unmask，是 oneshot 语义的核心（第 6 章）。
- `threads_active` + `wait_for_threads`：被唤醒的 irq 线程计数与等待队列，`synchronize_irq()` 等所有线程退出后才返回。

**③ 启停深度**
- `depth`：disable 深度。`disable_irq()` 嵌套调用时 ++，`enable_irq()` --，**归零才真正 unmask 硬件**。request 成功时置 0（自动 startup，除非 IRQF_NO_AUTOEN/IRQ_NOAUTOEN）。spurious 检测杀掉中断时也 `desc->depth++`（`spurious.c`）。
- `wake_depth`：`irq_set_irq_wake(on)` 的嵌套深度，多驱动共享一条唤醒线时只有全部撤销才关唤醒。

**④ 统计（spurious 检测与 /proc/interrupts）**
- `kstat_irqs`：per-CPU 计数数组（`alloc_percpu(unsigned int)`），flow handler 里 `kstat_incr_irqs_this_cpu(desc)` 递增本 CPU 槽位。`/proc/interrupts` 的每列就来自它（见下文）。
- `tot_count`：非 percpu IRQ 的总计数（6.2 起用于 `irq_get_irqs_count()`/debugfs 汇总；percpu IRQ 直接累加 kstat_irqs）。
- `irq_count` / `irqs_unhandled` / `last_unhandled`：spurious 检测三件套。`irq_count` 累计到 100000 次检查一次 `irqs_unhandled > 99900` 则判定"卡死"并禁用该 IRQ；`last_unhandled` 是老化时间戳（10s 内连续 unhandled 才累计，孤立的杂散中断直接重置计数，防止误杀），第 3 章展开。
- `threads_handled` / `threads_handled_last`：线程化中断的**延迟 spurious 检测**——硬中断侧只记录"唤醒了线程"，线程里 `thread_fn` 返回 `IRQ_HANDLED` 才 `atomic_inc(&threads_handled)`；下次硬中断比较两次计数是否变化（`SPURIOUS_DEFERRED` 用 bit31 标记延迟检测激活）。

**⑤ SMP 与迁移**
- `affinity_hint`（`irq_apply_affinity_hint` 写，irqbalance 消费）、`affinity_notify`（亲和性变化回调，`irq_set_affinity_notifier`）；
- `pending_mask`（`CONFIG_GENERIC_PENDING_IRQ`）：迁移目标掩码。不能在 hard IRQ 里改路由的中断，先把新掩码存这里，等下一次该中断真正在本 CPU 触发时（此时处理器上已无该中断的执行流）才安全执行迁移（`__irq_move_irq()`，`kernel/irq/migration.c`）。

**⑥ 同步原语**
- `lock`（raw_spinlock_t）：保护 desc 自身字段与 chip 状态。注意 flow handler 是"锁了跑 action 再解锁"（`handle_irq_event()` 中间 `raw_spin_unlock`），让 handler 执行不持锁。
- `request_mutex`：串行化 request/free 路径（`__setup_irq()`），避免两驱动并发注册时的竞态；先拿 request_mutex 再拿 desc->lock，顺序不可颠倒。

**⑦ 其他**
- `parent_irq`：级联场景记父 IRQ 号（software resend 优化用，`CONFIG_HARDIRQS_SW_RESEND`）；
- `percpu_enabled`/`percpu_affinity`：per-CPU IRQ 的使能与亲和（percpu 中断每 CPU 独立启停）；
- `rcu`/`kobj`（SPARSE）：RCU 延迟释放 + sysfs（`/sys/kernel/irq/N/`）。

### 🧬 irq_common_data 与 irq_data —— 芯片视角

```c
// include/linux/irq.h (v6.6, 原文)
struct irq_common_data {
	unsigned int		__private state_use_accessors;
#ifdef CONFIG_NUMA
	unsigned int		node;
#endif
	void			*handler_data;
	struct msi_desc		*msi_desc;
#ifdef CONFIG_SMP
	cpumask_var_t		affinity;
#endif
#ifdef CONFIG_GENERIC_IRQ_EFFECTIVE_AFF_MASK
	cpumask_var_t		effective_affinity;
#endif
#ifdef CONFIG_GENERIC_IRQ_IPI
	unsigned int		ipi_offset;
#endif
};

struct irq_data {
	u32			mask;
	unsigned int		irq;
	unsigned long		hwirq;
	struct irq_common_data	*common;
	struct irq_chip		*chip;
	struct irq_domain	*domain;
#ifdef	CONFIG_IRQ_DOMAIN_HIERARCHY
	struct irq_data		*parent_data;
#endif
	void			*chip_data;
};
```

为什么拆成两个结构？**`irq_common_data` 在整个层级链上只有一份**（leaf 的 irq_data 和所有 parent irq_data 的 `->common` 指向同一个），存放"与具体芯片层无关"的全局状态：IRQD_* 状态位、affinity、msi_desc；**`irq_data` 每层 domain 一份**，存放该层芯片的 irq/hwirq/chip/chip_data。这样 GIC 层与 gpio 层各有自己的 hwirq 编号和 chip_data，但共享同一份 affinity。

- `mask`：预计算的寄存器位掩码（generic chip 库用，一次性算好 `1 << (hwirq % 32)` 之类）；
- `irq` / `hwirq`：Linux 逻辑号 / 本 domain 局部硬件号；
- `chip_data`：芯片私有数据（如 IO-APIC 的 `mp_chip_data`、gpio 控制器的 bank 指针），`irq_set_chip_data()` 设置；
- `handler_data`：flow handler 的私有数据（级联 demux 常用，`irq_set_handler_data()`）。

`state_use_accessors` 用 `__private` 标记强制外部代码必须用 accessor（`irqd_irq_masked(d)` 等），杜绝裸读写。它存的是 IRQD_* 位（见后文状态位表）。

### 🎛️ struct irq_chip —— 芯片回调表

```c
// include/linux/irq.h (v6.6, 节选保真)
struct irq_chip {
	const char	*name;
	unsigned int	(*irq_startup)(struct irq_data *data);
	void		(*irq_shutdown)(struct irq_data *data);
	void		(*irq_enable)(struct irq_data *data);
	void		(*irq_disable)(struct irq_data *data);

	void		(*irq_ack)(struct irq_data *data);
	void		(*irq_mask)(struct irq_data *data);
	void		(*irq_mask_ack)(struct irq_data *data);
	void		(*irq_unmask)(struct irq_data *data);
	void		(*irq_eoi)(struct irq_data *data);

	int	(*irq_set_affinity)(struct irq_data *data, const struct cpumask *dest, bool force);
	int	(*irq_retrigger)(struct irq_data *data);
	int	(*irq_set_type)(struct irq_data *data, unsigned int flow_type);
	int	(*irq_set_wake)(struct irq_data *data, unsigned int on);

	void	(*irq_bus_lock)(struct irq_data *data);
	void	(*irq_bus_sync_unlock)(struct irq_data *data);
	/* ... irq_cpu_online/offline(DEPRECATED), irq_suspend/resume/pm_shutdown,
	       irq_print_chip, irq_request/release_resources,
	       irq_compose/write_msi_msg, irq_get/set_irqchip_state,
	       irq_set_vcpu_affinity, ipi_send_single/mask,
	       irq_nmi_setup/teardown ... */
	unsigned long	flags;
};
```

回调可分六组理解：

1. **生命周期**：`startup`/`shutdown`（缺省回退到 enable/disable）、`enable`（缺省= unmask）、`disable`。`irq_startup` 是 request 后自动启用的必经点。
2. **流控原语**：`ack`/`mask`/`mask_ack`/`unmask`/`eoi`，由 flow handler 编排（第 3 章）。缺省值有讲究：`irq_enable` 为 NULL 时 core 用 `unmask` 实现 enable——所以最小芯片只实现 mask/unmask 也能工作。
3. **路由与类型**：`set_affinity`（返回 `IRQ_SET_MASK_OK` 族；`force=true` 用于 CPU hotplug——目标 CPU 尚不在 online_mask 时无条件接受）、`set_type`（触发类型，通常会顺手 `irq_set_handler_locked()` 换 flow handler）、`retrigger`（软件重发）。
4. **慢总线芯片**（如 I2C 扩展中断控制器）：寄存器访问可能睡眠，不能在 hard IRQ 里做。`irq_bus_lock`/`irq_bus_sync_unlock` 把"标记待处理"与"实际写寄存器"分离：中断发生时只置脏标记并 wake 一个线程，`irq_bus_sync_unlock`（在可睡眠上下文）统一落盘。这是 chip 层自带的"线程化"。
5. **MSI 专属**：`compose_msi_msg`（把 vector/目标地址编码成 MSI 消息）、`write_msi_msg`（写设备 MSI-X table）。
6. **虚拟化/观测**：`set_vcpu_affinity`（GICv4 直注入）、`get/set_irqchip_state`（debugfs 查芯片内部 pending/active 状态）、`ipi_send_*`。

芯片级旗标 `flags`（IRQCHIP_*）是对整块芯片的声明，例如 `IRQCHIP_EOI_IF_HANDLED`（仅当 handler 声称处理了才 EOI）、`IRQCHIP_ONESHOT_SAFE`（oneshot 无需 mask，多用于 MSI 类无状态中断）、`IRQCHIP_EOI_THREADED`（EOI 推迟到线程侧，GIC 的嵌套 irq 工作队列模式用）、`IRQCHIP_SUPPORTS_NMI`、`IRQCHIP_IMMUTABLE`（6.2 新增：热补丁/静态调用保护，芯片结构声明为不可修改）。

### 📌 struct irqaction —— 驱动的一次注册

```c
// include/linux/interrupt.h (v6.6, 原文)
struct irqaction {
	irq_handler_t		handler;
	void			*dev_id;
	void __percpu		*percpu_dev_id;
	struct irqaction	*next;
	irq_handler_t		thread_fn;
	struct task_struct	*thread;
	struct irqaction	*secondary;
	unsigned int		irq;
	unsigned int		flags;
	unsigned long		thread_flags;
	unsigned long		thread_mask;
	const char		*name;
	struct proc_dir_entry	*dir;
} ____cacheline_internodealigned_in_smp;
```

- `handler`：primary hard handler；`request_threaded_irq(irq, NULL, thread_fn, ...)` 时被替换为 `irq_default_primary_handler()`（无条件 `return IRQ_WAKE_THREAD`）。
- `thread_fn` / `thread`：线程化函数与 `irq_thread()` 内核线程（命名 `irq/%d-%s`），第 6 章。
- `secondary`：**force-threading 的产物**（`irq_setup_forced_threading()`）：本来 `handler+thread_fn` 双全的注册，被 `threadirqs` 强制线程化时，原始 handler 被移进一个 secondary action 的 thread_fn，primary 变成哑 handler——保证"原 handler 语义"在新线程里执行。
- `thread_flags`：IRQTF_* 位（kernel/irq/internals.h）：`IRQTF_RUNTHREAD`（唤醒请求，`irq_wait_for_interrupt()` 等它）、`IRQTF_AFFINITY`（线程需跟随新亲和性）、`IRQTF_FORCED_THREAD`、`IRQTF_READY`（线程已就绪，request 路径同步用）、`IRQTF_WARNED`。
- `thread_mask`：该 action 在 `desc->threads_oneshot` 里的位（oneshot 位图）。
- `percpu_dev_id`：per-CPU 注册的 cookie（handler 收到的是本 CPU 实例）。
- `dir`：`/proc/irq/N/name` 目录项。

### 🌐 struct irq_domain —— 翻译层

```c
// include/linux/irqdomain.h (v6.6, 节选保真)
struct irq_domain {
	struct list_head		link;      /* 全局 domain 链表 */
	const char			*name;
	const struct irq_domain_ops	*ops;
	void				*host_data;  /* 拥有者私有,core 不碰 */
	unsigned int			flags;     /* IRQ_DOMAIN_FLAG_* */
	unsigned int			mapcount;
	struct mutex			mutex;     /* 层级用 root 的锁 */
	struct irq_domain		*root;

	struct fwnode_handle		*fwnode;   /* DT node / ACPI IORT node */
	enum irq_domain_bus_token	bus_token;
	struct irq_domain_chip_generic	*gc;
	struct device			*dev;
	struct device			*pm_dev;
#ifdef	CONFIG_IRQ_DOMAIN_HIERARCHY
	struct irq_domain		*parent;   /* 父 domain(向上是根) */
#endif
#ifdef CONFIG_GENERIC_MSI_IRQ
	const struct msi_parent_ops	*msi_parent_ops;
#endif

	/* reverse map data. The linear map gets appended to the irq_domain */
	irq_hw_number_t			hwirq_max;
	unsigned int			revmap_size;
	struct radix_tree_root		revmap_tree;
	struct irq_data __rcu		*revmap[];   /* 柔性数组: 线性 revmap */
};
```

- `link`：挂在全局 `irq_domain_list` 上，`/sys/kernel/debug/irq/domains` 遍历它；
- `host_data`：domain 拥有者（如 GIC 驱动）的私有指针，翻译回调里取回；
- `fwnode` + `bus_token`：**匹配键**。DT 的 device_node、ACPI 的 IORT/GICv3 ITS 节点都统一包装成 `fwnode_handle`；`irq_find_matching_fwspec()` 按 fwnode+bus_token 找 domain；
- `gc`：generic chip 库（`irq_alloc_generic_chip`）的批量管理结构；
- `parent`：层级链。**child（叶子）→ parent（根，通常是根中断控制器）**；`root` 直接指根 domain，层级化后所有层共用根的 `mutex` 串行化整棵树的分配；
- revmap 三件套：`revmap[]` 柔性数组（线性表，`revmap_size` 个槽）+ `revmap_tree`（radix tree，放不进线性表的大 hwirq）+ `hwirq_max`。查表逻辑（`irq_find_mapping` 的核心）：

```c
// kernel/irq/irqdomain.c (v6.6, 节选)
if (hwirq < domain->revmap_size)              /* 线性: O(1) 数组直取 */
	data = rcu_dereference(domain->revmap[hwirq]);
else
	data = radix_tree_lookup(&domain->revmap_tree, hwirq);  /* 树: O(log n) */
```

三种 revmap 模式的选择（创建 domain 时决定）：

| 模式 | 创建接口 | 场景 | 查找复杂度 |
| :--- | :--- | :--- | :--- |
| linear | `irq_domain_create_linear(size, ...)`（size ≤ 256 建议） | gpio bank、小控制器 | O(1) |
| radix tree | `irq_domain_create_tree(...)` | GIC ITS、大 hwirq 空间 | O(log n)，RCU 读侧无锁 |
| legacy | `irq_domain_add_legacy(...)`（first_irq 起连续 virq） | x86 ISA/IO-APIC（0–15 兼容段） | 静态绑死，等价旧世界 |

`mapcount` 记录已建立映射数；归零的 domain 可被 `irq_domain_remove()`。

### 📊 per-CPU 统计与 /proc/interrupts 的数据来源

`alloc_desc()`（kernel/irq/irqdesc.c）为每个 desc 分配统计：

```c
// kernel/irq/irqdesc.c (v6.6, 节选)
desc = kzalloc_node(sizeof(*desc), GFP_KERNEL, node);
desc->kstat_irqs = alloc_percpu(unsigned int);   /* 按 nr_cpu_ids 分配 */
```

- **写入**：flow handler 里 `kstat_incr_irqs_this_cpu(desc)` → `__this_cpu_inc(*desc->kstat_irqs)`（本 CPU 槽，无锁原子性由"每 CPU 独占"保证）。
- **读出**：`/proc/interrupts`（`kernel/irq/proc.c` 的 `show_interrupts()`）遍历 `for_each_active_irq()`，对每个 desc 用 `kstat_irqs_usr()`（irqdesc.c）在 `rcu_read_lock()` 下逐 CPU 累加——desc 可能正被释放，所以读侧必须 RCU。
- per-CPU 中断（request_percpu_irq）每 CPU 独立计数；x86 的 LOC/RES/CAL/TLB/NMI 等架构行则来自 `arch_irq_stat_cpu()`（`arch/x86/kernel/irq.c` 的 `irq_stats` percpu 数组），不走 kstat_irqs。

另外 `kstat_incr_softirqs_this_cpu(vec_nr)` 给 `/proc/softirqs` 提供同风格计数（第 5 章）。

### 🚦 状态位体系：IRQ_* / IRQD_* / IRQS_* / IRQCHIP_*

四层状态位最容易混淆，一次性梳理：

| 层级 | 存放位置 | 可变时机 | 代表位 |
| :--- | :--- | :--- | :--- |
| `IRQ_*` | `desc->status_use_accessors` | 注册/固件描述时设定，运行期少变 | `IRQ_LEVEL`、`IRQ_PER_CPU`、`IRQ_NOPROBE`、`IRQ_NOAUTOEN`、`IRQ_HIDDEN` |
| `IRQD_*` | `irq_data->common->state_use_accessors` | flow handler 执行中频繁翻转 | `IRQD_IRQ_MASKED`、`IRQD_IRQ_DISABLED`、`IRQD_IRQ_INPROGRESS`、`IRQD_IRQ_STARTED`、`IRQD_ACTIVATED`、`IRQD_AFFINITY_MANAGED` |
| `IRQS_*` | `desc->core_internal_state__do_not_mess_with_it`（别名 `istate`） | flow handler 内部 | `IRQS_PENDING`、`IRQS_ONESHOT`、`IRQS_REPLAY`、`IRQS_NMI`、`IRQS_SPURIOUS_DISABLED` |
| `IRQCHIP_*` | `chip->flags` | 芯片静态声明 | `IRQCHIP_EOI_IF_HANDLED`、`IRQCHIP_ONESHOT_SAFE` |

**IRQD_*（per-irq 硬件/生命周期状态，`include/linux/irq.h` v6.6 全集）**：

| 位 | 含义 |
| :--- | :--- |
| `IRQD_TRIGGER_MASK` (0xf) | 触发类型（与 IRQ_TYPE_* 对齐） |
| `IRQD_SETAFFINITY_PENDING` (bit8) | 迁移待完成（等中断回本 CPU 再真正 move） |
| `IRQD_ACTIVATED` (bit9) | domain activate 已完成（第 4 章） |
| `IRQD_NO_BALANCING` / `IRQD_PER_CPU` | 禁止平衡 / per-CPU |
| `IRQD_AFFINITY_SET` (bit12) | affinity 已被显式设置过 |
| `IRQD_LEVEL` (bit13) | 电平触发 |
| `IRQD_WAKEUP_STATE` (bit14) | 配置为唤醒源（`irq_set_irq_wake`） |
| `IRQD_MOVE_PCNTXT` (bit15) | 允许在进程上下文直接迁移（不挑时机） |
| `IRQD_IRQ_DISABLED` (bit16) | 逻辑禁用（depth>0） |
| `IRQD_IRQ_MASKED` (bit17) | 硬件已 mask |
| `IRQD_IRQ_INPROGRESS` (bit18) | 正在执行 handler（`synchronize_irq` 依赖） |
| `IRQD_WAKEUP_ARMED` (bit19) | suspend 周期内已武装唤醒 |
| `IRQD_FORWARDED_TO_VCPU` (bit20) | KVM 直注入（GICv4） |
| `IRQD_AFFINITY_MANAGED` (bit21) | **managed IRQ**：亲和由内核按队列自动分配（第 6 章 RSS） |
| `IRQD_IRQ_STARTED` (bit22) | startup 完成 |
| `IRQD_MANAGED_SHUTDOWN` (bit23) | managed IRQ 因目标 CPU 全下线被关闭 |
| `IRQD_SINGLE_TARGET` (bit24) | 硬件只支持单目标 |
| `IRQD_DEFAULT_TRIGGER_SET` (bit25) | 固件已指定触发类型 |
| `IRQD_CAN_RESERVE` (bit26) | 支持预约模式（x86 vector 预约，避免启动期耗尽） |
| `IRQD_MSI_NOMASK_QUIRK` (bit27) | MSI 迁移的特殊 quirk |
| `IRQD_HANDLE_ENFORCE_IRQCTX` (bit28) | 强制 flow handler 只能运行于真实中断上下文（防 `handle_fasteoi_irq` 被进程上下文误调） |
| `IRQD_AFFINITY_ON_ACTIVATE` (bit29) | 亲和性在 activate 时才下发 |
| `IRQD_IRQ_ENABLED_ON_SUSPEND` (bit30) | suspend 中保持 enable |
| `IRQD_RESEND_WHEN_IN_PROGRESS` (bit31) | 同一中断可能在 handler 执行期间再次触发（迁移竞态），需补发 |

**IRQS_*（desc 内部 istate，`kernel/irq/internals.h` v6.6）**：

| 位 | 值 | 含义 |
| :--- | :--- | :--- |
| `IRQS_AUTODETECT` | 0x1 | 自动探测进行中 |
| `IRQS_SPURIOUS_DISABLED` | 0x2 | 被 spurious 检测禁用 |
| `IRQS_POLL_INPROGRESS` | 0x8 | irqpoll 轮询中 |
| `IRQS_ONESHOT` | 0x20 | 该 IRQ 处于 oneshot 模式（有线程尚未跑完前不 unmask） |
| `IRQS_REPLAY` | 0x40 | 已软件重发（`check_irq_resend`），防重复 |
| `IRQS_WAITING` | 0x80 | 探测等待（autoprobe 用） |
| `IRQS_PENDING` | 0x200 | 有中断待处理/待重发——边沿 flow handler 的循环出口条件 |
| `IRQS_SUSPENDED` | 0x800 | suspend 流程中挂起 |
| `IRQS_TIMINGS` | 0x1000 | 启用 IRQ timing 采样（`CONFIG_IRQ_TIMINGS`） |
| `IRQS_NMI` | 0x2000 | 以 NMI 交付（request_nmi 路径） |
| `IRQS_SYSFS` | 0x4000 | 已加入 sysfs |

一个交叉验证的例子：`handle_irq_event()` 先 `irqd_set(IRQD_IRQ_INPROGRESS)` 再解锁跑 handler，退出时清除——所以 `synchronize_irq()` 自旋等待的是"IRQD_IRQ_INPROGRESS 清零 + `!desc->action`"，两条合起来保证返回后 CPU 上绝无该中断的执行流。

### 🔭 观测速查

- `/proc/interrupts`：`show_interrupts()` —— desc 遍历 + kstat_irqs RCU 读；
- `/proc/irq/N/spurious`：irqs_unhandled / irq_count 明细；
- `/sys/kernel/irq/N/`（sysfs）与 `/sys/kernel/debug/irq/irqs/N/`（`CONFIG_GENERIC_IRQ_DEBUGFS`，展示 handler/chip/actions/IRQD_/IRQS_ 全部状态位，`kernel/irq/debugfs.c`）；
- `crash`/`drgn` 里 `irq_to_desc(N)` 直接落 maple tree。

### 💭 思考题

1. `irq_data` 为什么内嵌在 `irq_desc` 中，而 `chip` 用指针？如果把 `chip` 也内嵌会怎样？
   <details><summary>提示</summary>一个 chip 对象被成百上千个 desc 共享（如 GIC 的 gic_chip）；内嵌会让每个 desc 复制一份函数表，浪费 icache 且无法 `irq_set_chip` 换芯片。</details>
2. `irq_common_data.affinity` 与 `irq_data.affinity`（不存在）——为什么亲和性放 common 而不是每层 irq_data？
   <details><summary>提示</summary>亲和性是"这条中断投给哪些 CPU"的全局语义，整条层级链必须一致；每层 irq_data 只有 hwirq/chip 语义不同。</details>
3. `depth` 与 `IRQD_IRQ_DISABLED` 有什么区别？`disable_irq()` 嵌套 3 层后 `enable_irq()` 一次，中断会 unmask 吗？
   <details><summary>提示</summary>depth 是计数器，IRQD_IRQ_DISABLED 是布尔状态；enable 一次 depth=2，仍 disabled，不会 unmask（这正是 WARN "enable_irq unbalanced" 的由来——free 前 depth 必须归零）。</details>
4. 共享中断上 A 驱动（无 ONESHOT）与 B 驱动（IRQF_ONESHOT threaded）并存时，`desc->threads_oneshot` 如何防止 B 的 unmask 抢跑？
   <details><summary>提示</summary>每个 oneshot action 有独立 thread_mask 位；`cond_unmask_irq()` 要求位图全清才 unmask；B 的线程 `irq_finalize_oneshot()` 清位。</details>
5. `/proc/interrupts` 的读取为什么必须 `rcu_read_lock()`？写侧（hardirq 的 `kstat_incr_irqs_this_cpu`）不需要任何锁，凭什么安全？
   <details><summary>提示</summary>desc 可能被 irq_dispose_mapping→free_desc 的 call_rcu 回收；per-CPU 变量本 CPU 写 + 读侧拿到 desc 指针期间 RCU 保活。</details>
