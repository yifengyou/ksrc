# crypto

## crypto type

``` shell
# # cat /proc/crypto  |grep type |sort -u
type         : aead
type         : ahash
type         : akcipher
type         : cipher
type         : compression
type         : rng
type         : scomp
type         : shash
type         : skcipher
```

Linux内核的Crypto框架通过高度抽象化的设计支持多种密码学算法类型，各类别在功能、应用场景和实现机制上有明显区别，同时存在组合使用关系。以下是各类型的详细解析，按核心功能和层级关系分类：

---

### **一、对称加密相关类型**

1. **`cipher`（单块密码）**
   - **功能**：提供最基础的块加密/解密能力，每次仅处理一个固定大小的数据块（如AES的16字节）。
   - **典型算法**：`aes`、`des`。
   - **特点**：
     - 无块链接模式（如CBC、CTR），需配合模板使用。
     - 通常被`skcipher`或`aead`调用，不直接由用户使用。
   - **示例**：`aes-generic`仅实现单块加密，需通过`cbc(aes)`组合使用。

2. **`skcipher`（对称密钥密码）**
   - **全拼**：对称密钥密码（Symmetric Key Cipher）
   - **定义**：加密与解密使用**同一密钥**，通信双方需预先共享密钥。
   - **功能**：支持多块数据的对称加密（含块链接模式），可处理流式数据。
   - **典型算法**：`cbc(aes)`、`xts(serpent)`。
   - **特点**：
     - 同步或异步操作（通过`CRYPTO_ALG_ASYNC`标志控制）。
     - 内部可能调用`cipher`实现核心加密。
   - **应用场景**：磁盘加密（如dm-crypt）、网络协议（如IPSec）。

---

### **二、哈希与认证相关类型**

1. **`shash`（同步哈希）**
   - **功能**：同步计算消息摘要，适用于小数据或原子上下文。
   - **典型算法**：`sha256`、`md5`。
   - **特点**：无异步回调，直接返回结果。

2. **`ahash`（异步哈希）**
   - **功能**：异步计算消息摘要，支持大文件分块处理。
   - **典型算法**：`sha1-avx2`。
   - **特点**：
     - 通过回调机制通知完成，避免阻塞。
     - 通常由网络协议栈使用。

3. **键控哈希（HMAC）**
   - **实现方式**：通过模板（如`hmac(sha256)`）组合`shash`或`ahash`，添加密钥认证。

---

### **三、非对称加密类型（`akcipher`）**

- **全称**：非对称密钥密码（Asymmetric Key Cipher）。
- **定义**：加密与解密使用**不同密钥**（公钥加密、私钥解密），无需共享密钥。
- **功能**：支持公钥密码学操作，如加密/解密、签名/验签。
- **典型算法**：
  - `rsa`：支持加密/解密和密钥导入。
  - `sm2`/`ecdsa`：仅支持验签和公钥导入（无加密功能）。
- **特点**：
  - 需显式设置公/私钥（`crypto_akcipher_set_*_key`）。
  - 多用于内核密钥管理（如模块签名验证）。

---

### **四、认证加密（`aead`）**

- **功能**：同时提供加密和认证（如GCM、CCM模式）。
- **典型算法**：`gcm(aes)`、`ccm(arc4)`。
- **实现机制**：
  - 组合`skcipher`（加密）和`ahash`（认证），如GCM = CTR模式 + GHASH。
  - 支持关联数据（AAD）的完整性校验。
- **应用场景**：TLS/IPSec等需机密性与完整性并重的协议。

---

### **五、随机数生成(`rng`)**
1. **`rng`（随机数生成）**
   - 生成加密安全随机数（如`drbg`算法），依赖硬件熵源（`/dev/hw_rng`）。


### **六、压缩类型**
2. **`compression` & `scomp`**
   - **`compression`**：分块压缩（如`deflate`）。
   - **`scomp`**：流式压缩（零拷贝优化），逐步替换`compression`。

---

### **类型关联与层级总结**

| **特性**         | **skcipher**                              | **akcipher**                              |
|------------------|------------------------------------------|------------------------------------------|
| **密钥机制**     | 单密钥（共享密钥）                        | 双密钥（公钥+私钥）                       |
| **数学基础**     | 混淆与扩散（如AES的S盒置换）               | 数学难题（如RSA的大数分解、ECC的离散对数） |
| **加密速度**     | 快（适合大数据流）                        | 慢（适合小数据）                          |
| **密钥管理**     | 需安全信道分发密钥                        | 公钥可公开分发，私钥保密                  |
| **主要功能**     | 数据机密性                                | 加密、数字签名、密钥交换                  |

---

| **类型**       | **依赖关系**                | **操作方向**       | **典型使用模式**         |
|----------------|----------------------------|-------------------|--------------------------|
| `cipher`       | 被`skcipher`/`aead`调用    | 同步              | 单块处理                 |
| `skcipher`     | 可能调用`cipher`           | 同步/异步         | 多块流式加密             |
| `akcipher`     | 独立                       | 同步              | 公钥操作                 |
| `aead`         | 组合`skcipher`+`ahash`     | 异步为主          | 加密+认证                |
| `shash`/`ahash`| 可被模板组合（如HMAC）     | 同步/异步         | 消息摘要                 |

---

内核实现差异：

| **维度**         | **skcipher**                                      | **akcipher**                                      |
|------------------|--------------------------------------------------|--------------------------------------------------|
| **API结构**      | 基于`struct skcipher_request`处理流式数据          | 基于`struct akcipher_request`处理密钥与签名操作    |
| **异步支持**     | 支持异步回调（如DMA加速）                         | 通常同步操作（因计算复杂）                        |
| **密钥设置**     | `crypto_skcipher_setkey()`设置单密钥              | `crypto_akcipher_set_pub_key()`/`set_priv_key()`  |
| **典型函数**     | `crypto_skcipher_encrypt()`/`decrypt()`           | `crypto_akcipher_sign()`/`verify()`               |

### **核心设计思想**
1. **模板化组合**
   - 算法通过“模板+基础算法”动态组合（如`cbc(aes)`），提升复用性。
2. **异步优先**
   多数类型（如`skcipher`、`ahash`）支持异步操作，避免阻塞高并发场景。
3. **硬件加速透明**
   框架自动选择最优实现（如AES-NI），用户通过`/proc/crypto`的`priority`查看优先级。

通过这种分层设计，内核Crypto框架既能适配硬件特性，又能为不同场景（如实时处理、大文件加密）提供统一接口，同时保持算法扩展的灵活性。实际开发中需根据需求选择类型：如高性能网络用`aead`，密钥操作选`akcipher`，而随机数生成必用`rng`。

###  **安全性考量**

- **`skcipher`风险**：
   - 密钥泄露导致全盘数据暴露（如侧信道攻击）。
   - 需防范模式漏洞（如CBC的填充预言攻击）。
- **`akcipher`风险**：
   - 量子计算威胁（如Shor算法破解RSA）。
   - 私钥存储安全（需硬件隔离如TPM）。
