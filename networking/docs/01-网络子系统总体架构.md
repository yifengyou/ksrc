# 网络子系统总体架构

Linux 网络子系统是内核中最庞大的子系统之一：从网卡驱动的收发中断，到 TCP/IP 协议栈，再到 socket 抽象与 VFS 的对接，横跨 `drivers/net`、`net/core`、`net/ipv4`、`net/ipv6`、`net/socket.c` 等数十万行代码。本章以 Linux 6.6 为基准，建立一张"全局地图"：分层模型、初始化流程、核心数据结构之间的引用关系，以及与调度器/中断/软中断子系统的接口。后续各章（sk_buff、net_device、收包路径、发包路径）将逐一放大这张地图的局部。

### 🎯 设计哲学

理解网络子系统的几条主线：

*   **一切皆 `struct sk_buff`**：报文在内核中的一切形态都由 sk_buff 描述，它是一个"元数据"结构，本身不含报文数据；数据的所有权、线性区与非线性区（page frag）分离，这是所有高性能优化（GRO/TSO/zerocopy）的基础。
*   **驱动与协议栈解耦**：`net_device` 抽象屏蔽硬件差异，协议栈只认 `net_device` 和 `packet_type` 分发；`net/core/dev.c`（~12000 行）是整个子系统的"心脏"，收发包的公共路径都在这里。
*   **软中断驱动的一切**：收包（`NET_RX_SOFTIRQ`）与发包完成（`NET_TX_SOFTIRQ`）都运行在 softirq 上下文，per-CPU 的 `softnet_data` 是一切状态的汇聚点。理解 softirq，就理解了内核网络 80% 的运行时行为。
*   **垂直分层的 `net namespace` 泛化**：几乎所有"全局"状态都被收进 `struct net`，使得容器/VM 场景下每个 netns 拥有独立的设备表、协议参数与路由表。

### 🧱 分层总览

自上而下的调用层次（以 IPv4/TCP 为例，标注关键函数与文件）：

```text
┌────────────────────────────────────────────────────────────────────┐
│ 用户空间:  sendto()/recvmsg()/write()/read()                       │
├────────────────────────────────────────────────────────────────────┤
│ VFS:      vfs_write/vfs_read → socket 文件操作                      │
│           net/socket.c: sock_write_iter → sock_sendmsg             │
├────────────────────────────────────────────────────────────────────┤
│ Socket 层: struct socket → struct sock                             │
│           proto_ops(*inet_stream_ops) / proto(tcp_prot)           │
│           tcp_sendmsg / tcp_recvmsg / udp_sendmsg                  │
├────────────────────────────────────────────────────────────────────┤
│ L4:       TCP(net/ipv4/tcp_*.c) / UDP(net/ipv4/udp.c)             │
│           tcp_write_xmit → __tcp_transmit_skb (报文生成)           │
├────────────────────────────────────────────────────────────────────┤
│ L3:       IP(net/ipv4/ip_output.c, ip_input.c) + XFRM(net/xfrm)    │
│           ip_queue_xmit/ip_local_out │ ip_rcv → ip_rcv_finish      │
│           Netfilter: NF_INET_* 五个钩子点                           │
├────────────────────────────────────────────────────────────────────┤
│ L2/核心:  net/core/dev.c                                            │
│           发: __dev_queue_xmit → Qdisc → ndo_start_xmit            │
│           收: net_rx_action → napi->poll → netif_receive_skb       │
│           → __netif_receive_skb_core → ptype_base[ip_rcv/arp_rcv]  │
├────────────────────────────────────────────────────────────────────┤
│ 设备驱动:  drivers/net/*.c                                          │
│           RX: 硬中断 → napi_schedule_irqoff → poll()               │
│           TX: ndo_start_xmit 描述符入环                             │
├────────────────────────────────────────────────────────────────────┤
│ 硬件:     多队列 NIC(RSS) / DMA / 硬件 offload(TSO/csum)           │
└────────────────────────────────────────────────────────────────────┘
```

两个方向的关键分界：

| 方向 | 里程碑函数 | 语义 |
| :--- | :--- | :--- |
| 发送（TX） | `__dev_queue_xmit()`（net/core/dev.c） | 从协议栈进入"设备无关发送层"；此后 skb 属于 qdisc/驱动 |
| 接收（RX） | `__netif_receive_skb_core()`（net/core/dev.c） | L2 处理终点、L3 分发起点；`ptype_base[]` 在此完成协议分发 |

### 🚀 子系统初始化

三个 initcall 按依赖顺序搭建骨架（均在持有 RTNL 之外完成大部分工作）：

**1) `sock_init()`（net/socket.c，`core_initcall`）**
*   `net_sysctl_init()` → **`skb_init()`**：创建 `skbuff_cache`/`skbuff_fclone_cache`/`skb_small_head_cache` 三个 slab（skbuff 外壳的专用分配器）。
*   `init_inodecache()` + `register_filesystem(&sock_fs_type)` + `kern_mount`：创建 `sockfs`（每个 socket 是一个伪 inode），并建立 `net_families[]` 协议族注册表（`sock_register()`）。

**2) `net_dev_init()`（net/core/dev.c，`subsys_initcall`）——网络核心的地基**

```c
static int __init net_dev_init(void)
{
    ...
    INIT_LIST_HEAD(&ptype_all);                    /* 全局 tap 链表 */
    for (i = 0; i < PTYPE_HASH_SIZE; i++)          /* 协议哈希桶(16) */
        INIT_LIST_HEAD(&ptype_base[i]);

    for_each_possible_cpu(i) {
        struct softnet_data *sd = &per_cpu(softnet_data, i);
        skb_queue_head_init(&sd->input_pkt_queue);  /* backlog 输入队列 */
        skb_queue_head_init(&sd->process_queue);
        INIT_LIST_HEAD(&sd->poll_list);             /* 待 poll 的 napi 链表 */
        sd->output_queue_tailp = &sd->output_queue; /* 待运行的 qdisc */
        INIT_CSD(&sd->defer_csd, trigger_rx_softirq, sd);
        init_gro_hash(&sd->backlog);                /* backlog 也可 GRO */
        sd->backlog.poll = process_backlog;         /* 虚拟 NAPI 实例 */
        sd->backlog.weight = weight_p;              /* 默认 64 */
    }
    register_pernet_device(&loopback_net_ops);      /* 回环设备最先注册 */
    open_softirq(NET_TX_SOFTIRQ, net_tx_action);
    open_softirq(NET_RX_SOFTIRQ, net_rx_action);
    ...
}
```

要点：`softnet_data` 是 per-CPU 结构（`DECLARE_PER_CPU_ALIGNED`），它同时是收包（poll_list/input_pkt_queue/backlog）与发包（output_queue/completion_queue）的 per-CPU 汇聚点；`ptype_all`/`ptype_base` 是协议分发链；`open_softirq()` 注册两个软中断处理函数。

**3) `inet_init()`（net/ipv4/af_inet.c，`fs_initcall`）——IPv4 协议栈**

```c
static int __init inet_init(void)
{
    proto_register(&tcp_prot, 1);      /* L4 proto: sock 级注册 */
    proto_register(&udp_prot, 1);
    proto_register(&raw_prot, 1);
    proto_register(&ping_prot, 1);
    sock_register(&inet_family_ops);   /* net_families[AF_INET] */

    inet_add_protocol(&icmp_protocol, IPPROTO_ICMP); /* inet_protos[] */
    inet_add_protocol(&udp_protocol, IPPROTO_UDP);
    inet_add_protocol(&tcp_protocol, IPPROTO_TCP);   /* L4 处理函数注册 */

    inet_register_protosw(q);          /* inetsw[]: SOCK_STREAM→tcp 等 */
    arp_init();  ip_init();  tcp_init();  udp_init(); ...
}
```

三个 initcall 的时序关系（`core → subsys → fs` 严格有序）：

```text
start_kernel
 └→ do_basic_setup / do_initcalls
     ├─ [core_initcall]  sock_init()          net/socket.c
     │    └─ 创建 sockfs; net_families[] 就绪(但 AF_INET 尚未注册)
     ├─ [subsys_initcall] net_dev_init()      net/core/dev.c
     │    ├─ ptype_all/ptype_base 就绪(尚无人注册)
     │    ├─ per-CPU softnet_data 就绪(poll_list/backlog/qdisc 队列)
     │    ├─ loopback 设备注册(register_pernet_device)
     │    └─ NET_TX/NET_RX softirq 注册: open_softirq()
     └─ [fs_initcall]    inet_init()          net/ipv4/af_inet.c
          ├─ proto_register(tcp_prot/udp_prot/...)   ← 需要 slab 就绪
          ├─ sock_register(inet_family_ops)           ← 填 net_families[AF_INET]
          ├─ inet_add_protocol(tcp_protocol...)       ← 填 inet_protos[]
          └─ ip_init/arp_init/tcp_init ...
               └─ dev_add_pack(ip_packet_type)        ← 填 ptype_base[ETH_P_IP]
```

若顺序颠倒：`inet_init` 会在 `ptype_base` 未初始化时 `dev_add_pack`（链表写崩），或 `alloc_skb` 在 slab 未建时崩溃——所以 initcall level 本身就是隐式依赖声明。

注册分两级，注意区分：

| 注册表 | 结构 | 挂载者 | 分发点 |
| :--- | :--- | :--- | :--- |
| `net_families[]` | `struct net_proto_family` | `inet_family_ops`(AF_INET) | `socket()` 系统调用 |
| `inetsw[SOCK_MAX]` | `struct inet_protosw` | tcp/udp/raw 的 `proto_ops` | `inet_create()` |
| `inet_protos[MAX_INET_PROTOS]` | `struct net_protocol` | `tcp_protocol`/`udp_protocol`（`.handler = tcp_v4_rcv`） | `ip_local_deliver_finish()` 按 `iph->protocol` 分发 |
| `ptype_base[PTYPE_HASH_SIZE]` | `struct packet_type` | `ip_packet_type`(`.func = ip_rcv`)、`arp_packet_type`、`ipv6_packet_type` | `__netif_receive_skb_core()` 按 `skb->protocol`(Ethertype) 分发 |
| `inet_protos`/`ptype_all` | tap 型 `packet_type` | AF_PACKET(tcpdump) | 分发前的旁路复制 |

### 🗂️ 核心数据结构鸟瞰

```text
                    struct net (per-netns)
                    ┌─────────────────────────────┐
                    │ dev_base_head(设备链表)      │
                    │ loopback_dev  netns_ipv4    │
                    └───────┬─────────────────────┘
                            │ list_add_tail_rcu
      ┌─────────────────────┴──────────────────────────────┐
      │                struct net_device                   │
      │  name/ifindex  netdev_ops  ethtool_ops  features   │
      │  _tx[]→netdev_queue──→Qdisc(qdisc_sleeping)        │
      │  _rx[]→netdev_rx_queue   napi_list                 │
      │  ptype_all/ptype_specific   rx_handler             │
      └───────┬──────────────┬───────────────┬─────────────┘
              │              │               │
     struct napi_struct   struct Qdisc   协议注册表
     poll_list/weight      enqueue/dequeue  ptype_base[] ──→ ip_rcv
     gro_hash[8]           (pfifo_fast 等)                  │
              │                                               │
              │ poll() 产出                                   ▼
              │                                        tcp_v4_rcv()
      ┌───────┴───────────────────────────────┐            │
      │          struct sk_buff               │◄───────────┘
      │  next/prev/sk/dev/cb[48]/_skb_refdst  │   (skb 遍历协议栈)
      │  head→[headroom|data..tail|tailroom|  │
      │         skb_shared_info{frags[]}]     │
      │  truesize/users  len/data_len          │
      └───────┬───────────────────────────────┘
              │ skb->sk (所有权)
      ┌───────┴────────────┐        socket 层
      │ struct sock        │ sk_receive_queue/sk_write_queue
      │ sk_rmem_alloc      │ sk_data_ready()/sk_write_space()
      │ sk_wmem_alloc      │ 等待队列(与调度器接口)
      └────────────────────┘
```

结构间核心引用关系（"谁拥有谁"）：

*   `net_device._tx[i]`：内嵌 `struct netdev_queue`，每个 TX 队列持有自己的 `_xmit_lock` 与 `qdisc`/`qdisc_sleeping` 两个 Qdisc 指针（运行态与休眠态）。
*   `net_device.napi_list`：驱动通过 `netif_napi_add_weight()` 把 `napi_struct` 挂进设备；调度时又被链入 per-CPU 的 `softnet_data.poll_list`。
*   `sk_buff.dev / sk_buff.sk`：分别记录"从哪个设备来 / 属于哪个 socket"；发送路径上 skb 脱离 socket（`skb_orphan`）后 `sk` 置空。
*   `sock.sk_receive_queue`：`sk_buff_head` 双向链表，用户态 `recvmsg` 从此摘取 skb。
*   `packet_type`（`ptype_all`/`ptype_base`）：L2→L3 的分发纽带；`dev_add_pack()` 注册、`dev_remove_pack()` 注销。

### 🔌 系统调用入口

**发送路径（简）**：

```text
sendto(sd, buf, len, flags, dst, addrlen)
 └→ __sys_sendto (net/socket.c)
     └→ sock_sendmsg → sock->ops->sendmsg (如 tcp_sendmsg)
         └→ tcp_sendmsg_locked: 从用户空间拷贝到 skb(sk_write_queue)
             └→ tcp_write_xmit → __tcp_transmit_skb
                 └→ ip_queue_xmit → __ip_local_out
                     └→ NF_INET_LOCAL_OUT → dst_output → ip_output
                         └→ NF_INET_POST_ROUTING → neigh_output
                             └→ dev_queue_xmit → __dev_queue_xmit (见第 5 章)
```

**接收路径（简）**：

```text
网卡硬中断 → napi_schedule_irqoff → NET_RX_SOFTIRQ (net_rx_action)
 └→ 驱动 poll() → napi_gro_receive → __netif_receive_skb_core
     └→ ptype_base → ip_rcv → NF_INET_PRE_ROUTING → ip_rcv_finish
         (fib 路由查找, skb_dst_set_noref) → dst_input
         └→ ip_local_deliver → NF_INET_LOCAL_IN
             └→ tcp_v4_rcv → __inet_lookup_skb (找到 struct sock)
                 ├─ socket 空闲: tcp_v4_do_rcv 直接入队
                 └─ socket 被用户占用: tcp_add_backlog 暂存
                     └→ sk_data_ready() = sock_def_readable
                         └→ wake_up_interruptible_sync_poll
                             └→ 用户进程从 recvmsg 返回 (第 4 章详述)
```

### ⚙️ 与调度器 / 中断 / 软中断的接口

网络栈不是一个"自驱"系统，它被三类事件驱动，全部依赖其它子系统：

1.  **硬中断（中断子系统）**：驱动 RX/TX 完成 ISR。现代驱动收包 ISR 只做一件事——`napi_schedule_irqoff()`（关中断版调度，省一次 `local_irq_save`），随即返回。发图中断同理，多数被 NAPI 合并轮询化。
2.  **软中断（softirq 子系统）**：`raise_softirq_irqoff(NET_RX_SOFTIRQ)` 在 `irq_exit()` 时被检查，未超过 2ms/`ksoftirqd` 唤醒阈值则就地执行 `net_rx_action`；超限或 `__raise_softirq_irqoff` 置位时唤醒 **ksoftirqd/n**（per-CPU 内核线程，SCHED_OTHER，可被 CFS 调度管控）。`local_bh_disable()`（即 `preempt_count` 的 SOFTIRQ 位）是网络栈里最常见的"锁"，`rcu_read_lock_bh()` 把 RCU 与 BH 关中断合二为一。
3.  **进程唤醒（调度器）**：`sk_data_ready()`（默认实现 `sock_def_readable`，wake_up 等 SkSocketWakeUp 偏好）把"有数据到达"翻译为等待队列唤醒；epoll 的回调也挂在这里（`sk->sk_wq`/`wq_head`）。反向地，`sk_flush_backlog`（用户进程 release socket 时）会处理 backlog 中积压的 skb。

**为什么收包要绕这么大一圈（中断→softirq→poll→softirq→进程）？** 因为硬中断上下文不能睡眠、不能处理复杂逻辑，而 softirq 上下文允许关闭 BH 的"伪进程"语义，且有 per-CPU 状态与预算（budget）机制防止饿死其它中断——这是吞吐与时延的折中设计。

三种执行上下文的对比（网络栈代码必须知道自己跑在哪一层）：

| 上下文 | 进入方式 | 可睡眠 | 典型网络代码 | 禁忌 |
| :--- | :--- | :--- | :--- | :--- |
| 硬中断（IRQ） | 驱动 ISR | ❌ | `napi_schedule_irqoff`、`dev_kfree_skb_irq` | 任何分配 GFP_KERNEL、拿 spinlock_irqsave 之外的锁 |
| 软中断（softirq/BH off） | `irq_exit`/ksoftirqd | ❌ | `net_rx_action`/`net_tx_action`/`process_backlog` | `might_sleep`、`lock_sock` |
| 进程上下文 | 系统调用/内核线程 | ✅（可抢占点） | `tcp_sendmsg`/`recvmsg`/RTNL 配置路径 | 无锁读共享结构（需 RCU/BH 保护） |

`local_bh_disable()` 是 IRQ-safe 的"半锁"：它不关硬中断，只把 `preempt_count` 的 SOFTIRQ 位抬高，使本 CPU 的 softirq 延迟到 `local_bh_enable` 再执行——`rcu_read_lock_bh()`（= `local_bh_disable` + RCU 读锁）因此成为 `__dev_queue_xmit` 等热路径的标准护卫。

### 🌐 Network Namespace 泛化

`struct net`（include/net/net_namespace.h）把"全局"状态泛化为 per-netns：

```c
struct net {
    refcount_t       passive;            /* netns 生命周期引用 */
    struct list_head dev_base_head;      /* 本 netns 设备链表头 */
    struct hlist_head *dev_name_head;    /* 按名索引 */
    struct hlist_head *dev_index_head;   /* 按 ifindex 索引 */
    struct raw_notifier_head netdev_chain; /* per-netns notifier 链 */
    struct net_device *loopback_dev;     /* 回环设备(每 netns 一个) */
    struct netns_core core;
    struct netns_mib   mib;              /* SNMP 计数器 */
    struct netns_packet packet;
    struct netns_ipv4  ipv4;             /* devconf/tcp_mem/路由表... */
    struct netns_ipv6  ipv6;
    struct netns_xfrm  xfrm;             /* XFRM 状态/策略 */
    ...
    u32   hash_mix;                      /* socket 哈希扰动(防碰撞 DoS) */
    struct net_generic __rcu *gen;       /* 动态 per-netns 私有数据 */
};
```

*   **每个 netns 一个 `struct net`**（`init_net` 是初始 netns），所有 net_device 经 `dev_net_set()` 归属一个 netns；`dev_base_head` 使 `for_each_netdev(net, dev)` 只遍历本空间设备。
*   **协议参数同样泛化**：`net->ipv4`（struct netns_ipv4）内含 `ipv4_devconf`（`net->ipv4.devconf_all`/`devconf_dflt`，即 `net.ipv4.conf.all/default.*` sysctl 的后端）、`tcp_mem[]`、`sysctl_*` 镜像等；procfs 下 `/proc/net/*` 被映射到 `/proc/<pid>/net/` 或 netns 挂载点。
*   **pernet 机制**：子系统通过 `register_pernet_ops()`（`struct pernet_operations` 的 `init/exit`）声明 per-netns 状态，netns 创建/销毁时回调；`net_dev_init()` 里的 `register_pernet_subsys(&netdev_net_ops)` 就是典型用法。这就是"数据结构的泛化"：老内核里的全局变量 `ipv4_devconf`、`ipv4_routing_table` 等如今全部长在 `struct net` 里。

### ⚡ 高性能主题概览

后续章节会反复遇到这些优化，此处建立索引：

| 技术 | 层次 | 核心思想 | 关键数据结构/函数 |
| :--- | :--- | :--- | :--- |
| RSS | 硬件 | 网卡多队列按哈希分流到不同 IRQ/CPU | `ethtool -x/-l`；`num_rx_queues` |
| RPS/RFS/aRFS | 软件 | 把收包转发到"socket 所在 CPU"处理，提升缓存命中 | `rps_sock_flow_table`、`get_rps_cpu()`、`enqueue_to_backlog()`（第 4 章） |
| XPS | 软件 | 发包时 CPU→TX 队列映射，与 RSS 对称 | `xps_maps[XPS_CPUS]`、`netif_set_xps_queue()`（第 3/5 章） |
| GRO | 收包 | 软件聚合同流小包成大 skb 再上送，减少 per-packet 开销 | `napi_gro_receive()`、`gro_hash[8]`（第 4 章） |
| GSO/TSO | 发包 | 协议栈构造 64KB 大 skb，由硬件（或软件 fallback）在最后拆段 | `skb_shared_info.gso_size/gso_type`、`skb_gso_segment()` |
| XDP | 驱动收包最早点 | 在 skb 创建之前运行 eBPF，做 DPDK 式快速转发/丢弃 | `xdp_buff`、`ndo_bpf`、`page_pool` |
| page_pool | 驱动 RX | 页面级回收池，避免 alloc/free page 抖动 | `struct page_pool`、`skb_mark_for_recycle()`（第 4 章） |
| zerocopy | socket | `MSG_ZEROCOPY`/AF_XDP/io_uring zc 收发，消除用户态拷贝 | `ubuf_info`、`skb_shared_info.destructor_arg` |
| busy polling | socket | 应用主动轮询 NAPI，降低唤醒时延（`SO_BUSY_POLL`） | `napi_busy_loop()`、`napi_id` |
| BQL | 驱动 TX | 动态限制驱动环内 in-flight 字节，对抗 bufferbloat | `struct dql`（第 5 章） |

### 🔭 观测入口

*   **`/proc/net/dev`**：per-device 收发计数（`dev_seq_printf_stats()` 输出 rx_bytes/packets/errs/dropped... tx_bytes/...，字段合并规则见第 3 章）。
*   **`/proc/net/softnet_stat`**：per-CPU 收包健康度（15 列十六进制）：第 1 列 `processed`、第 2 列 `dropped`（backlog 溢出）、第 3 列 `time_squeeze`（预算耗尽被迫重新调度）、第 10 列 `received_rps`（RPS IPI 到达）、第 12 列 backlog 长度（第 4 章逐列解读）。
*   **`ethtool -S <dev>`**：驱动/硬件私有计数（RX 各队列 drops、no buffer 等）；`ethtool -k` 查看 offload 开关（TSO/GSO/GRO/checksum）。
*   **`ss -tinp`**：socket 级 rtt/cwnd/backlog/mem（读取 `sk->sk_backlog`、`sk_rmem_alloc`）。
*   **`nstat -az` / `/proc/net/snmp`**：TCP/IP MIB 计数（`netns_mib` per-cpu 汇总）。
*   **dropwatch / `perf trace`**：消费 `kfree_skb` tracepoint（携带 drop reason，见第 2 章）。

### 🧠 深挖难点

*   **为什么 `ptype_all` 在 `ptype_base` 之前分发？** tcpdump（AF_PACKET 的 `packet_type`）必须看到"未经 L3 处理的原始帧"，包括即将被丢弃的帧；`__netif_receive_skb_core()` 用 `pt_prev` 指针做"延迟一跳"优化——只有当存在多个消费者时才对前一消费者 `skb_clone`，单消费者路径零拷贝。
*   **socket 层的双重注册（`proto` 与 `proto_ops`）**：`proto_ops`（`inet_stream_ops`）面向系统调用做通用粘合；`proto`（`tcp_prot`）面向具体传输协议提供 `obj_size`、`init()`、`memory_allocated` 等钩子，使内存记账（`sk->sk_prot->memory_allocated`）可按协议聚合（TCP 全局压力 `tcp_memory_pressure`）。
*   **RTNL（`rtnl_mutex`）与数据面锁的分层**：配置路径（register/ unregister、地址、路由、tc）全部串行于 RTNL；数据面（softirq）只依赖 per-CPU/RCU/每队列 spinlock，两者通过 `rtnl_dereference`/`rcu_dereference` 的约定衔接。这是网络栈能水平扩展的前提。

### ❓ 思考题

1.  `net_dev_init()` 为什么必须在 `sock_init()` 之后、`inet_init()` 之前运行？如果三者顺序颠倒，最早崩溃的会是哪一步？
    *提示：`ptype_base` 的初始化者是 `dev_add_pack()` 的调用方（`ip_init`/`arp_init`）；`skb_init` 由谁调用。*
2.  `ptype_all` 与 `ptype_base` 同为 `packet_type` 链表，内核为何要分两张表而不是一张表加过滤标志？
    *提示：数量级差异——tap 通常 0~2 个 vs 协议十几个；热路径上遍历 tap 是全量、分发是哈希查找 O(1)。*
3.  `sk_data_ready` 为什么默认实现是 `wake_up_interruptible_sync_poll` 而非普通 `wake_up`？"sync" 优化了什么？
    *提示：sync 版本避免在唤醒路径上立即调度别的 CPU 上的等待者，减少上下文切换与锁竞争；语义与 `rcu_read_lock_bh` 持有期间的约束。*
4.  一个容器（netns）内 `ifconfig` 看不到宿主机的 eth0，但宿主机内核代码里并没有按 netns if 的 if 分支——泛化是如何做到"零分支"的？
    *提示：`dev_net(dev)` 指针间接引用；`for_each_netdev` 的迭代起点；`net_generic` 机制。*
5.  若把 GRO 关闭（`ethtool -K eth0 gro off`），`/proc/net/softnet_stat` 的哪些列会变化？为什么 pps 高的小包场景 time_squeeze 反而可能下降？
    *提示：GRO 聚合后每"批"只占 1 个 budget；GRO 本身也消耗 poll 时间（gro_list 遍历）。*
