# 信号子系统（Linux 6.6）

> 阅读目标：信号是内核里唯一的**异步控制流**——它把"处理一个事件"拆成几乎不相见的两个半场：发送侧只做**记账**（位图置位、入队、唤醒），递送侧在**返回用户态的最后一刻**收口。本章以 `kernel/signal.c`（4859 行）为主战场讲清三件事：**数据结构三件套**（signal_struct / sighand_struct / sigpending——哪些状态线程组共享、哪些线程私有，多线程信号的一切怪癖源于此）；**发送链**（`kill → check_kill_permission → __send_signal_locked 的位图与双队列 → complete_signal 的目标选择算法 → signal_wake_up 的 TIF_SIGPENDING + IPI`）；**递送链**（`exit_to_user_mode_loop` 检查点 → `get_signal` 处理矩阵 → x86 的 `setup_rt_frame` / `rt_sigreturn`）。最后补齐 job control（SIGSTOP/SIGCONT 组协议与双父通知）、SIGKILL 的快速路径（**它通常根本不排队**——多数资料在此讲错）、handler 内再 fault 的递归兜底，以及 `/proc/PID/status` 十六进制掩码的读法。第 3 章结尾欠的账——`do_notify_parent` 的另一半（SIGCHLD 接收侧）——在本章 §4.5、§7.1 结清。

## 一、概述：generation → pending → delivery

```
① 生成(generation)   check_kill_permission / prepare_signal / __send_signal_locked
                      ——只记账：位图 + 可选 sigqueue + 唤醒，不触碰用户内存
② 等待(pending)      task->pending（私有）/ signal->shared_pending（共享）
                      ——可被阻塞推迟；SIGKILL/SIGSTOP 永不缺席
③ 递送(delivery)     exit_to_user_mode_loop → get_signal → 处理矩阵
                      ——忽略 / 默认动作(term/core/stop/cont) / 捕获(setup_rt_frame)
```

信号编号：1~31 是 legacy 信号，32~63 是实时信号；内核 `_NSIG=64`，`SIGRTMIN` 内核侧为 32，**glibc 的 SIGRTMIN=34**（NPTL 征用了 32/33）。两者最关键的差异是排队规则（§3.4）。与生命周期各章的衔接：**fork**（01 章 §2.6）不带 `CLONE_SIGHAND` 时 `copy_sighand` **整表 memcpy** sigaction、`copy_signal` 新建 signal_struct（rlim 整表继承），带 `CLONE_THREAD` 时三件套全部共享——"共享 vs 私有"格局的来源；**exec**（02 章 §5）里 `de_thread` 先单一化线程组，再 `flush_signal_handlers(me, 0)` 把**自定义 handler 全部重置为 SIG_DFL（SIG_IGN 保留）**；**exit**（03 章）的入口 `do_group_exit` 正是本章 §4.3 的致命信号路径，`exit_signals` 置 `PF_EXITING` 后任务对组播信号"隐身"（§7.2）。

## 二、数据结构三件套：共享与私有的分界线

### 2.1 sighand_struct：动作表（可共享）

```c
struct sighand_struct {              /* include/linux/sched/signal.h:20 */
	spinlock_t		siglock;     /* ★ 信号子系统总锁：所有记账都在其临界区内 */
	refcount_t		count;       /* CLONE_SIGHAND 共享计数；归零才真释放 */
	wait_queue_head_t	signalfd_wqh;
	struct k_sigaction	action[_NSIG];   /* ★ 64 项 sigaction 表 */
};
```

fork 的分流（kernel/fork.c:1799 `copy_sighand`）：`CLONE_SIGHAND` → 只 `refcount_inc`（pthread 场景整表共享）；否则新分配并**持父进程 siglock memcpy 整表**——子进程出生时 handler 与父完全一致。释放走 03 章 §5.3 的 `__exit_signal → __cleanup_sighand`。sighand 的 slab 是 `SLAB_TYPESAFE_BY_RCU`，`__lock_task_sighand`（kernel/signal.c:1401）靠"锁完再比对 `tsk->sighand` 指针"的循环对付 exec 期间 `unshare_sighand` 的换表。

### 2.2 signal_struct：线程组的"进程级"状态

定义在 include/linux/sched/signal.h:93（约 150 行，`__randomize_layout`），按职责分组（节选）：

```c
struct signal_struct {
	atomic_t		live;            /* 活线程数：do_exit ⑤ 的 group_dead 判据 */
	int			nr_threads, quick_threads;  /* 后者 6.4 引入：并发组退出配合 */
	struct list_head	thread_head;   /* for_each_thread 遍历的组内线程链 */
	wait_queue_head_t	wait_chldexit; /* ★ wait4 的组级等待队列（03 章 §5.1）*/
	struct task_struct	*curr_target; /* 组播信号的"轮转指针"（§3.5）*/
	struct sigpending	shared_pending; /* ★ 共享待决队列（§2.3）*/
	struct hlist_head	multiprocess;  /* fork 窗口内到达的广播信号暂存：
	                                           copy_process 在 siglock 下收割
	                                           （fork.c:2319/2686）*/
	int			group_exit_code;  /* 组退出码（SIGNAL_GROUP_EXIT 时）*/
	int			group_stop_count; /* 组停止的"到齐计数"（§7.1）*/
	unsigned int		flags;             /* SIGNAL_* 组标志，见下表 */
	struct core_state	*core_state;   /* coredump 进行中（第 5 章 §六）*/
	struct pid		*pids[PIDTYPE_MAX]; /* TGID/PGID/SID 的 struct pid */
	struct tty_struct	*tty;             /* ★ 控制终端：job control 的锚点 */
	/* —— 进程级记账（stats_lock + siglock 双锁保护）—— */
	u64			utime, stime, cutime, cstime;  /* 本组累计+已收割子孙累计 */
	unsigned long		nvcsw, cnvcsw, min_flt, cmin_flt;  /* 切换/缺页同理成对 */
	struct rlimit		rlim[RLIM_NLIMITS]; /* ★ 资源上限表（getrlimit 数据源）*/
};
```

SIGNAL_* 组标志（进程级状态机的核心）：

| 标志 | 语义 | 置位者 |
| :--- | :--- | :--- |
| `SIGNAL_GROUP_EXIT` | 组退出进行中：新信号一律丢弃（coredump 中除外） | `do_group_exit` / `zap_process` / `complete_signal` 快路径 |
| `SIGNAL_STOP_STOPPED` | 组停止生效中（SIGCONT 清除） | `task_participate_group_stop` |
| `SIGNAL_STOP_CONTINUED` / `SIGNAL_CLD_STOPPED/CONTINUED` | "继续"未被收割 / 待补发的 SIGCHLD(CLD_*) | `prepare_signal(SIGCONT)`；后者由 `get_signal` 收割（§4.5） |
| `SIGNAL_UNKILLABLE` | init 特权：默认致命信号免疫 | `copy_process`（is_child_reaper） |

### 2.3 sigpending 与 sigqueue：位图 + 双队列

```c
struct sigqueue {                    /* include/linux/signal_types.h:22 */
	struct list_head	list;       /* 挂进 sigpending.list（FIFO）*/
	int			flags;          /* SIGQUEUE_PREALLOC：POSIX 定时器预分配项 */
	kernel_siginfo_t	info;      /* 128 字节 siginfo（ABI 冻结）*/
	struct ucounts		*ucounts; /* ★ RLIMIT_SIGPENDING 的记账主体 */
};
struct sigpending {                  /* include/linux/signal_types.h:32 */
	struct list_head	list;
	sigset_t		signal;        /* ★ 位图先行：有 1 就有信号 */
};
```

**位图与队列的关系**是理解发送/递送的钥匙：`sigaddset` 永远先发生；`collect_signal`（kernel/signal.c:574）出队时若链表里找不到同号 sigqueue（典型：SIGKILL 根本没分配过队列项，或配额耗尽被静默丢弃），就补一个 `si_code=SI_USER` 的空壳——**信号的存在性由位图决定，siginfo 只是富文本**。

### 2.4 task_struct 侧的私有字段与职责分界

```c
	/* Signal handlers: */           /* include/linux/sched.h:1100 */
	struct signal_struct	*signal;       /* CLONE_THREAD 共享 */
	struct sighand_struct __rcu *sighand; /* CLONE_SIGHAND 共享 */
	sigset_t		blocked;           /* ★ 私有：本线程阻塞掩码 */
	sigset_t		real_blocked;      /* 私有：sigtimedwait 的暂存（§六）*/
	sigset_t		saved_sigmask;     /* 私有：sigsuspend/ppoll 的暂存 */
	struct sigpending	pending;       /* ★ 私有：本线程待决队列 */
	/* 另有 last_siginfo / exit_code / jobctl——第 5 章的 stop/traced 状态机 */
```

| 状态 | 归属 | 谁改它 |
| :--- | :--- | :--- |
| handler 表、组标志、rlim、tty、统计 | **进程（线程组）** | siglock（+tasklist_lock） |
| blocked / saved_sigmask / real_blocked | **线程** | 仅本线程（sigprocmask 等） |
| pending（私有待决） | **线程** | siglock |
| shared_pending | **进程** | siglock |
| jobctl（停止/陷阱状态机） | **线程** | siglock |

> 📌 这张分界表解释两大怪癖：**sigaction 是进程级的**（任何线程改 handler 全组生效——sighand 表共享），而 **sigprocmask 是线程级的**（blocked 私有）。于是"发给进程的信号可能被藏在一个屏蔽它的线程里"（思考题 6）。

## 三、发送链全解：从 kill() 到 TIF_SIGPENDING

### 3.1 API 层矩阵：pid_type 决定落在哪个队列

| 接口 | 内核路径 | pid_type | 落点 | 语义 |
| :--- | :--- | :--- | :--- | :--- |
| `kill(pid>0, sig)` / `pidfd_send_signal` | `kill_proc_info → kill_pid_info` | **TGID** | shared_pending | 发给**线程组**，任一线程可领；pidfd 是稳定引用版 |
| `kill(0/负数, sig)` | `__kill_pgrp_info` | PGID | shared | 进程组广播（^C/^Z 走这里，§7.1） |
| `kill(-1, sig)` | `for_each_process`（跳过 pid≤1 与自身） | PIDTYPE_MAX | shared | 全系统广播 |
| `tkill/tgkill/raise` | `do_tkill → do_send_specific`；raise 是 glibc 的 `tgkill(pid,tid)` | **PID** | 私有 pending | 定向**单线程**；tgkill 校验 tgid 防 PID 复用 |
| `sigqueue/rt_sigqueueinfo` | `do_rt_sigqueueinfo → kill_proc_info` | TGID | shared | 带 payload；`si_code>=0` 冒充内核源要被拒（EPERM） |
| `pidfd_send_signal` | `kill_pid_info` | TGID | shared | pidfd 稳定引用版 kill |
| 内核 `send_sig_info` / `force_sig_fault` 等 | `do_send_sig_info` / `force_sig_info_to_task` | PID | 私有 | 内核事件定向目标线程；后者**强制**递送（§7.3） |

### 3.2 check_kill_permission：跨 uid 的规则与 LSM

`group_send_sig_info`（kernel/signal.c:1451）先在 RCU 下验权再拿 siglock 发送。权限核心（kernel/signal.c:824 `kill_ok_by_cred`）：

```c
	return uid_eq(cred->euid, tcred->suid) || uid_eq(cred->euid, tcred->uid) ||
	       uid_eq(cred->uid,  tcred->suid) || uid_eq(cred->uid,  tcred->uid) ||
	       ns_capable(tcred->user_ns, CAP_KILL);
```

`check_kill_permission`（kernel/signal.c:840）的顺序：`si_fromuser` 为假（内核源信号，负 si_code）**免检**；`audit_signal_info` 审计钩子；同线程组免检；否则 `kill_ok_by_cred` 四选一——**发送者的 euid 或 uid == 目标的 uid 或 suid**（覆盖"同 uid 互发"与"setuid 程序的老特权 suid 反向通道"）；失败时唯一豁免是 **SIGCONT 且同会话**（job control 特例）；最后 `security_task_kill` 让 LSM（SELinux 等）投最后一票。随后 `send_signal_locked`（kernel/signal.c:1225）补 **force 判定**：`SEND_SIG_PRIV` 恒 force；来自**祖先 pid namespace** 的信号 force；`si_code == SI_KERNEL` force——force 的用途只有一个，击穿 `SIGNAL_UNKILLABLE`（§4.3 矩阵）。

### 3.3 prepare_signal：发生在生成时刻的"组魔法"

```c
static bool prepare_signal(int sig, struct task_struct *p, bool force)
{                                              /* kernel/signal.c:912 */
	if (signal->flags & SIGNAL_GROUP_EXIT) {
		if (signal->core_state)
			return sig == SIGKILL;  /* coredump 中：只放行 SIGKILL 打断 */
		return false;               /* 组退出中：新信号一律丢弃 */
	} else if (sig_kernel_stop(sig)) {
		/* 停止信号：把所有队列里的 SIGCONT 冲掉（stop 与 cont 互斥）*/
	} else if (sig == SIGCONT) {
		/* 即时效果不等递送：当场冲掉全部 stop 信号、清 JOBCTL_STOP_PENDING、
		   唤醒所有 STOPPED 线程；置 CLD_CONTINUED 延迟通知位 */
	}
	return !sig_ignored(p, sig, force);   /* SIG_IGN 且未被屏蔽 → 丢弃 */
}
```

要点：**SIGCONT 的"继续"在生成时刻当场生效**（唤醒所有停止线程），递送与否反而是次要的——这解释了 `kill -CONT` 后 `WCONTINUED` 事件的时序。`sig_ignored`（kernel/signal.c:103）有两个防御：**被阻塞的信号永不算 ignored**（handler 可能在解除阻塞前被换掉）；被 ptrace 的任务不忽略任何信号（tracer 有知情权）。

### 3.4 __send_signal_locked：记账的六个步骤

6.6 的函数名是 `__send_signal_locked`（5.13 前叫 `__send_signal`，老资料注意），外层公共入口 `send_signal_locked`。主体（kernel/signal.c:1084）：

```c
static int __send_signal_locked(int sig, struct kernel_siginfo *info,
				struct task_struct *t, enum pid_type type, bool force)
{
	if (!prepare_signal(sig, t, force))   /* ① 组魔法 + ignored 丢弃 */
		goto ret;
	pending = (type != PIDTYPE_PID) ? &t->signal->shared_pending
					: &t->pending;  /* ② 私有 or 共享 */
	if (legacy_queue(pending, sig))       /* ③ legacy 合并：已 pending 的
	                                          非 rt 信号整份丢弃 */
		goto ret;
	if ((sig == SIGKILL) || (t->flags & PF_KTHREAD))
		goto out_set;                 /* ④ SIGKILL/kthread 不分配 sigqueue */
	if (sig < SIGRTMIN)
		override_rlimit = (is_si_special(info) || info->si_code >= 0);
	else
		override_rlimit = 0;          /* rt 信号受配额管 */
	q = __sigqueue_alloc(sig, t, GFP_ATOMIC, override_rlimit, 0);
	if (q)
		list_add_tail(&q->list, &pending->list); /* FIFO 尾插；NOINFO→填
		     si_pid/si_uid（目标 ns 视角），PRIV→SI_KERNEL */
	else if (!is_si_special(info) && sig >= SIGRTMIN && info->si_code != SI_USER)
		return -EAGAIN;               /* rt 队列满：sigqueue 才能见到 EAGAIN；
		                                 kill() 静默丢（LOSE_INFO）*/
out_set:
	signalfd_notify(t, sig);
	sigaddset(&pending->signal, sig);     /* ⑤ 位图置位（存在性）；广播信号
	                                       （type>TGID）另暂存进 multiprocess */
	complete_signal(sig, t, type);        /* ⑥ 选目标并唤醒 */
ret:
	trace_signal_generate(sig, info, t, type != PIDTYPE_PID, result);
	return ret;                            /* perf trace 埋点在此 */
}
```

三条配额/合并规则务必记住：**legacy 合并**（`legacy_queue`：`sig < SIGRTMIN && sigismember(...)`）——同一 legacy 信号只留 1 位 + **最早**的一份 siginfo（`collect_signal` 取 first），后到的整份丢弃，`kill -USR1 十次` 只递送一次；**rt 不合并**——34~64 号（glibc 视角）每发一次入队一次，FIFO 逐份递送；**RLIMIT_SIGPENDING 是 ucounts 记账**（`__sigqueue_alloc → inc_rlimit_get_ucounts`，按 user namespace × user 计数；`/proc/PID/status` 的 `SigQ: used/limit` 直接读它）——内核源 legacy 信号（`si_code>=0`）可超配额分配，用户 rt 信号超额则 `sigqueue()` 拿 `-EAGAIN`。

### 3.5 complete_signal：目标选择算法与组退出快速路径

```c
static inline bool wants_signal(int sig, struct task_struct *p)
{                                             /* kernel/signal.c:987 */
	if (sigismember(&p->blocked, sig)) return false;
	if (p->flags & PF_EXITING)       return false; /* 对组播隐身 */
	if (sig == SIGKILL)              return true;  /* 不看下面两条 */
	if (task_is_stopped_or_traced(p)) return false;
	return task_curr(p) || !task_sigpending(p); /* "正在跑"或"闲着没活"优先 */
}
```

```c
static void complete_signal(int sig, struct task_struct *p, enum pid_type type)
{                                             /* kernel/signal.c:1004 */
	if (wants_signal(sig, p))
		t = p;                    /* 首选：发送指定的任务 */
	else if ((type == PIDTYPE_PID) || thread_group_empty(p))
		return;   /* 定向发送/单线程：无需唤醒，下次运行时自己出队 */
	else {        /* 组播：从 curr_target 轮转起点找愿意接的线程 */
		t = signal->curr_target;
		while (!wants_signal(sig, t)) {
			t = next_thread(t);
			if (t == signal->curr_target)
				return;   /* 没人要（全屏蔽/全忙）：留在共享队列 */
		}
		signal->curr_target = t;     /* ★ 轮转负载均衡 */
	}
	if (sig_fatal(p, sig) &&        /* 默认动作致命（handler==SIG_DFL）*/
	    (signal->core_state || !(signal->flags & SIGNAL_GROUP_EXIT)) &&
	    !sigismember(&t->real_blocked, sig) &&
	    (sig == SIGKILL || !p->ptrace)) {
		if (!sig_kernel_coredump(sig)) {  /* 非 coredump 类致命信号 */
			signal->flags = SIGNAL_GROUP_EXIT;   /* ★ 组退出快速路径 */
			signal->group_exit_code = sig;
			signal->group_stop_count = 0;
			t = p;
			do {                    /* 组播到每个线程的私有位图 */
				task_clear_jobctl_pending(t, JOBCTL_PENDING_MASK);
				sigaddset(&t->pending.signal, SIGKILL);
				signal_wake_up(t, 1);
			} while_each_thread(p, t);
			return;
		}
	}
	signal_wake_up(t, sig == SIGKILL);  /* 常规：只唤醒选中的线程 */
}
```

**这就是 SIGKILL 的快速路径**，也是本章第一处"认知 vs 真相"：`kill -9` 一个普通进程时，**没有任何 sigqueue 被分配、信号只存在于位图**——`prepare_signal` 通过后直接跳到 `complete_signal`，后者当场置 `SIGNAL_GROUP_EXIT`、把 SIGKILL 位图**塞进每个线程的私有 pending**、逐个致命唤醒；各线程走到 `get_signal` 时看到组标志直接 `do_group_exit`（§4.3），根本不做出队动作。只有"已安装 handler 的致命信号"或"coredump 类信号"才走常规队列路径。**不存在所谓 `do_add_pid` 之类的"退出任务直投"路径**——对正在退出的任务，SIGKILL 的作用是推进其退出路径上的睡眠点（§7.2）。`wants_signal` 的选人偏好值得咀嚼：`task_curr`（正在跑——反正马上回用户态）或 `!task_sigpending`（手头没别的信号活儿）；屏蔽者、`PF_EXITING`、stopped/traced 一律跳过。全组无人可唤醒时信号**留在共享队列**（位图已置），任一线程解除阻塞或下次 `recalc_sigpending` 时自然浮现。

### 3.6 signal_wake_up：TIF_SIGPENDING 与 kick_process 的 IPI

```c
void signal_wake_up_state(struct task_struct *t, unsigned int state)
{                                             /* kernel/signal.c:769 */
	set_tsk_thread_flag(t, TIF_SIGPENDING);  /* ★ 唯一的"通知"动作 */
	if (!wake_up_state(t, state | TASK_INTERRUPTIBLE))
		kick_process(t);   /* 唤醒失败：若它正在别的 CPU 上运行，发 reschedule
		                      IPI（sched/core.c: task_curr(p) 才发，不盲发）*/
}
```

`signal_wake_up(t, fatal=true)`（SIGKILL 场景）额外做：清 `JOBCTL_STOPPED|JOBCTL_TRACED`、唤醒态加 `TASK_WAKEKILL|__TASK_TRACED`——**SIGKILL 能把 stopped 甚至 traced 的任务拽起来**，这是"kill -9 能杀死被 gdb 停住的进程"的机制保证。TIF_SIGPENDING 置位后：睡眠中的任务被 wake、运行中的任务被 IPI 打断，而无论哪种，真正处理信号的时机都是**返回用户态前**（§4.1）。

### 3.7 发送—递送全时序（ASCII 总图）

```
发送者 CPU ——► 接收任务的宿主 CPU
──────────
sys_kill/tgkill/sigqueue → group_send_sig_info
     ├─ check_kill_permission（RCU：uid 规则+CAP_KILL+LSM）
     └─ do_send_sig_info
       lock_task_sighand() ┌──────── siglock 临界区 ───────────────┐
```

## 四、递送链全解：get_signal 主循环

### 4.1 检查点：返回用户态的必经之路

信号的递送被刻意推迟到**用户态边界**——`kernel/entry/common.c:147` 的 `exit_to_user_mode_loop`：

```c
	while (ti_work & EXIT_TO_USER_MODE_WORK) {
		local_irq_enable_exit_to_user(ti_work);
		if (ti_work & _TIF_NEED_RESCHED)
			schedule();                      /* 抢占检查点 */
		if (ti_work & (_TIF_SIGPENDING | _TIF_NOTIFY_SIGNAL))
			arch_do_signal_or_restart(regs); /* ★ 信号收口（其余 work 项：
			                                     uprobe/livepatch/task_work）*/
		ti_work = read_thread_flags();        /* 循环直到无工作 */
	}
```

x86 的 `arch_do_signal_or_restart`（arch/x86/kernel/signal.c:305）：`get_signal(&ksig)` 成功则 `handle_signal`（装帧，§五）；失败（无可递送）则做 **syscall 重启判定**（§5.4 的兜底列）+ `restore_saved_sigmask`。syscall 返回、中断返回、异常返回**三条路径共用这个循环**——"无论怎么陷入内核，回去时一定查信号"的结构性保证。内核态深处则靠另一套检查点（§八）：可中断睡眠在 `__schedule` 里被 `signal_pending_state` "抢救"（调度器分册 04 §4.2）、缺页重试 `fault_signal_pending`（mm 分册 [pagefault](../../mm/pagefualt/pagefault.md)）。

### 4.2 dequeue_signal：优先级规则

`get_signal` 出队前先问两个问题。其一，**同步信号插队**（kernel/signal.c:716 `dequeue_synchronous_signal`）：`si_code > SI_USER` 且属于 `SYNCHRONOUS_MASK`（SIGSEGV/SIGBUS/SIGILL/SIGTRAP/SIGFPE/SIGSYS）的信号**最先出队**——指令引发的信号必须先处理，帧里的 RIP 才指向出错指令；`next_signal`（kernel/signal.c:209）在位图层面同款偏袒（第一个字先 `x &= SYNCHRONOUS_MASK`）。其二，**私有队列优先于共享队列**（`dequeue_signal`，kernel/signal.c:635）：先 `t->pending`，空了再 `signal->shared_pending`；出队同时 `recalc_sigpending` 维护 TIF；出队 stop 信号时置 `JOBCTL_STOP_DEQUEUED`（SIGCONT 能反杀的标记）。其余按编号序：字内低位优先（1~31），跨字则 32~64 顺次——**没有"信号号优先级"概念，只有"同步 vs 异步""私有 vs 共享"两级插队**。

### 4.3 处理矩阵：get_signal 的 switch 与默认动作

`get_signal`（kernel/signal.c:2660）是个大 `for(;;)`，每个信号面对四层判定：

```
dequeue_signal(信号 X)
  ├─ ptrace 且 X≠SIGKILL 且非 SA_IMMUTABLE
  │    → ptrace_signal：先给 tracer 审（第 5 章 §二的 signal-delivery-stop），
  │      tracer 可改号/吞掉（返回 0 → continue 重出队）
  ├─ action[X].handler == SIG_IGN   → continue（出队即丢弃）
  ├─ handler != SIG_DFL（自定义）   → break 返回，装帧执行（§五）；
  │      SA_ONESHOT(SysV 的 SA_RESETHAND) 顺手重置为 SIG_DFL
  └─ SIG_DFL：默认动作矩阵
       ├─ sig_kernel_ignore(X)      → continue（默认即忽略）
       ├─ SIGNAL_UNKILLABLE && !sig_kernel_only(X)
       │    → continue（容器 init 免疫；force 的 SIGKILL/SIGSTOP 例外）
       ├─ sig_kernel_stop(X)        → do_signal_stop（§7.1 组停止）
       └─ 其余                       → fatal：PF_SIGNALED 置位 →
             sig_kernel_coredump(X) → do_coredump（第 5 章 §六）→
             do_group_exit(X)        /* 03 章 §一：NOTREACHED */
```

循环顶部还有**抢占式短路**：`signal->flags & SIGNAL_GROUP_EXIT || group_exec_task` 时直接 `sigdelset(&current->pending.signal, SIGKILL)`、`goto fatal`——组已判死刑的线程不再逐个出队（§3.5 快速路径的接收端；`do_coredump` 成功后 `coredump_finish` 里 `group_exit_code |= 0x80`，`WCOREDUMP` 的来源）。

`SIG_KERNEL_*` 掩码（include/linux/signal.h:418，默认动作分类的唯一事实源）：

| 掩码 | 成员 | get_signal 中的动作 |
| :--- | :--- | :--- |
| `SIG_KERNEL_ONLY` | SIGKILL, SIGSTOP | 不可捕获/阻塞/忽略（do_sigaction 拒绝安装） |
| `SIG_KERNEL_IGNORE` | SIGCONT, SIGCHLD, SIGWINCH, SIGURG | 默认动作 = 忽略 |
| `SIG_KERNEL_STOP` | SIGSTOP, SIGTSTP, SIGTTIN, SIGTTOU | 默认动作 = 组停止（§7.1） |
| `SIG_KERNEL_COREDUMP` | SIGQUIT, SIGILL, SIGTRAP, SIGABRT, SIGFPE, SIGSEGV, SIGBUS, SIGSYS, SIGXCPU, SIGXFSZ | term **+ core**（第 5 章） |
| （其余 SIGHUP/INT/PIPE/ALRM/TERM/USR1/USR2/PROF/VTALRM…） | | term（do_group_exit） |

### 4.4 SIGCHLD 接收侧：还第 3 章的账

03 章 §三 讲了死亡通知**发送侧**的 `do_notify_parent`；接收侧续篇在此（kernel/signal.c:2058）：

```c
	info.si_code = tsk->exit_code & 0x80 ? CLD_DUMPED :
		       (tsk->exit_code & 0x7f ? CLD_KILLED : CLD_EXITED);
	psig = tsk->parent->sighand;
	spin_lock_irqsave(&psig->siglock, flags);
	if (!tsk->ptrace && sig == SIGCHLD &&
	    (psig->action[SIGCHLD-1].sa.sa_handler == SIG_IGN ||
	     (psig->action[SIGCHLD-1].sa.sa_flags & SA_NOCLDWAIT)))
		autoreap = true;            /* 自动收尸判定（03 章 §6.1）*/
	if (valid_signal(sig) && sig)
		__send_signal_locked(sig, &info, tsk->parent, PIDTYPE_TGID, false);
	__wake_up_parent(tsk, tsk->parent); /* ★ 唤醒 wait_chldexit 上所有睡着的
	                                       wait(2)——SIG_IGN 时也靠它查 ECHILD */
	spin_unlock_irqrestore(&psig->siglock, flags);
	return autoreap;
```

stop/continue 的状态通知走 `do_notify_parent_cldstop`（kernel/signal.c:2169）：`CLD_STOPPED/CONTINUED/TRAPPED` 三种 si_code，受 `SA_NOCLDSTOP` 抑制；**通知谁**有讲究——`for_ptracer=false` 时以 group_leader 身份通知 real_parent（job control 视角），`true` 时通知 tracer（调试视角），ptrace_reparented 的 leader 两份都发。触发点有三：`do_signal_stop` 组停止到齐、`get_signal` 顶部的 `SIGNAL_CLD_MASK` 收割分支（§3.3 置的延迟通知位）、`ptrace_stop`（第 5 章）。

## 五、handler 的安装与执行：x86 信号帧

### 5.1 安装：do_sigaction 的两条即时语义

`do_sigaction`（kernel/signal.c:4123）：`sig_kernel_only(sig)` 拒绝安装；装 SIG_IGN（或"默认即忽略"的 SIG_DFL）时**当场冲掉该信号全部待决实例**（POSIX 3.3.1.3：`flush_sigqueue_mask` 遍历共享+全部私有队列）——`signal(SIGCHLD, SIG_IGN)` 后堆积的待决也被清（Go runtime 自动收尸的底层依据，呼应 03 章 §6.1）。`SA_IMMUTABLE` 的表项拒绝再改（force_sig 的防逃逸栏）。

### 5.2 装帧：x64_setup_rt_frame 与 get_sigframe

x86_64 的帧结构（arch/x86/include/asm/sigframe.h:59）：`struct rt_sigframe { char __user *pretcode; struct ucontext uc; struct siginfo info; /* fp state follows here */ }`——pretcode 是**返回地址**（指向 sa_restorer），uc 含 uc_mcontext（寄存器）/uc_sigmask/uc_stack，尾部是 64 字节对齐的 XSAVE 区。布局与落点：

```
低地址 ◄──
        ┌───────────────────────────────┐
        │ siginfo（SA_SIGINFO）           │
        │ ucontext                        │
        │  ├ uc_mcontext (sigcontext)     │ ← GPR/rip/rsp/flags
        │  ├ uc_sigmask（阻塞副本）       │ ← rt_sigreturn 的恢复源
        │  └ uc_stack（备用栈信息）        │
        │ pretcode = sa_restorer          │ ← RSP 落点；handler ret 跳这里
        │ （16B 对齐 padding）             │
        │ XSAVE 区（64B 对齐，fpstate）    │
        └───────────────────────────────┘ ──► 高地址
```

`get_sigframe`（arch/x86/kernel/signal.c:74）决定落点：`SA_ONSTACK` 且不在备用栈上 → 切到 sigaltstack 顶端；先 `sp -= 128`（x86_64 red zone）；`fpu__alloc_mathframe` 为 **XSAVE 区预留并对齐 64 字节**；帧本体 16 字节对齐后再 `-8`（ABI：函数入口 RSP%16==8）；**备用栈溢出判定**：新 sp 落在 sigaltstack 外 → 打印 `overflowed sigaltstack`、返回 -1L——装帧失败最终演变为 SIGSEGV（§7.3）。随后 `x64_setup_rt_frame`（arch/x86/kernel/signal_64.c:164）：`user_access_begin` 后 `unsafe_put_user` 依次写 uc_flags/uc_link/uc_stack、`pretcode = sa_restorer`、sigcontext（15 个 GPR + IP/SP/FLAGS/CS/SS + fpstate 指针 + trapno/err/cr2）、uc_sigmask；SA_SIGINFO 再 `copy_siginfo_to_user`；最后**直接改 pt_regs 换魂**：`regs->ip = sa_handler`、`regs->sp = frame`、`di=sig, si=&info, dx=&uc`（后两个参数恰好复用给非 SA_SIGINFO 的老 ABI）、CS/SS 修成 `__USER_CS/__USER_DS`（`force_valid_ss`：#GP/#SS 场景的坏段寄存器兜底）；FPU 状态由 `copy_fpstate_to_sigframe` 提前存入帧内。

### 5.3 rt_sigreturn 与 SA_RESTORER

handler 执行完 `ret`，跳到帧顶 `pretcode`——**内核从不把"返回内核"的代码放栈上执行**（NX 时代栈不可执行；i386 的 `retcode[8]` 自修改代码已成历史）。x86_64 更进一步**强制 SA_RESTORER**：`x64_setup_rt_frame` 开头 `if (!(sa_flags & SA_RESTORER)) return -EFAULT`——glibc 在每个 sigaction 里自动填 `sa_restorer = vDSO 的 __restore_rt`。arm64 无 SA_RESTORER 概念，改用 `regs->regs[30] (LR) = VDSO_SYMBOL(vdso, sigtramp)`（arch/arm64/kernel/signal.c:1123）——返回地址走寄存器而非栈，同一逻辑的两种 ABI 表达。`__restore_rt` 只含 `mov $__NR_rt_sigreturn, %eax; syscall`：

```c
SYSCALL_DEFINE0(rt_sigreturn)               /* arch/x86/kernel/signal_64.c:246 */
{
	frame = (struct rt_sigframe __user *)(regs->sp - sizeof(long));
	...
	if (__get_user(*(__u64 *)&set, &frame->uc.uc_sigmask))
		goto badframe;
	set_current_blocked(&set);              /* ★ 恢复 handler 前的掩码
	                                             （signal_delivered 曾把
	                                             sa_mask+sig 并入 blocked）*/
	if (!restore_sigcontext(regs, &frame->uc.uc_mcontext, uc_flags))
		goto badframe;                   /* GPR/IP/SP/FLAGS +
	                                         fpu__restore_sig（XSAVE 恢复）*/
	if (restore_altstack(&frame->uc.uc_stack))
		goto badframe;
	return regs->ax;              /* ★ 妙笔：把被打断处的返回值原样放回 rax
	                                  ——rt_sigreturn 的"返回值"即恢复现场 */
badframe:
	signal_fault(regs, frame, "rt_sigreturn"); /* 打日志 → force_sig(SIGSEGV) */
	return 0;
}
```

### 5.4 handler 前后：掩码与 syscall 重启

装帧成功后 `signal_setup_done → signal_delivered`（kernel/signal.c:2915）：`blocked |= sa_mask`、无 `SA_NODEFER` 时**再并入信号自身**（handler 期间同号信号阻塞，防递归）；`SS_AUTODISARM` 的备用栈自动解除武装；`stepping` 时补一发 `ptrace_notify(SIGTRAP)`（单步调试，第 5 章）。中断了系统调用则有重启矩阵（`handle_signal`，x86 signal.c:227）：

| 系统调用返回 | handler 存在时 | 无 handler 时（`arch_do_signal_or_restart` 尾部） |
| :--- | :--- | :--- |
| `-ERESTARTSYS` | 无 `SA_RESTART` → `-EINTR`；有则重放 | 重放：`ax=orig_ax; ip-=2` |
| `-ERESTARTNOINTR` / `-ERESTARTNOHAND` | 前者重放；后者 `-EINTR` | 重放 |
| `-ERESTART_RESTARTBLOCK` | `-EINTR` | 换号 `restart_syscall`（poll 等带状态的续算） |

## 六、阻塞与排队语义

### 6.1 sigprocmask：改掩码的正确姿势

用户路径 `rt_sigprocmask` 先 `sigdelsetmask(SIGKILL|SIGSTOP)`——**不可屏蔽集**，用户态永远封不掉；内核内部 `sigprocmask()` 无此豁免（kthread 可以挡 SIGKILL，代价是 `flush_signals` 一类显式管理）。改掩码必须走 `set_current_blocked → __set_task_blocked`（kernel/signal.c:3045）：

```c
static void __set_task_blocked(struct task_struct *tsk, const sigset_t *newset)
{
	if (task_sigpending(tsk) && !thread_group_empty(tsk)) {
		sigset_t newblocked;
		sigandnsets(&newblocked, newset, &current->blocked);
		retarget_shared_pending(tsk, &newblocked); /* ★ 新屏蔽的共享信号转投
		                             他人——防"只有我能处理却被我封死"死锁 */
	}
	tsk->blocked = *newset;
	recalc_sigpending();                 /* 位图 vs blocked 重算 TIF */
}
```

**屏蔽期间到达的信号照常入队**，只是 `next_signal` 的 `x &~ *m` 把它滤掉；解除阻塞后自然出队。legacy 合并同样发生在屏蔽期——屏上十次只欠一份。`recalc_sigpending` 的三个输入（jobctl、私有、共享）解释了 TIF_SIGPENDING 为什么可能"长期为真"：全组信号都被本线程屏蔽时，它每次回用户态都会进 `get_signal` 空转一圈再出来。

### 6.2 sigsuspend / sigwait：两种"反向"等待

```c
static int sigsuspend(sigset_t *set)          /* kernel/signal.c:4650 */
{
	current->saved_sigmask = current->blocked;  /* 原掩码存档 */
	set_current_blocked(set);                   /* 换成调用者给的（通常更窄）*/
	while (!signal_pending(current)) {
		__set_current_state(TASK_INTERRUPTIBLE);
		schedule();                         /* 睡到任何未屏蔽信号到达 */
	}
	set_restore_sigmask();                      /* 标记：返回用户态前恢复 */
	return -ERESTARTNOHAND;   /* 重启规则：有 handler 才重算，否则 -EINTR 立即上报 */
}
```

`-ERESTARTNOHAND` 是 sigsuspend 的灵魂：**它调用的目的就是等信号，若信号没被 handler 处理，重启它没有意义**。`sigtimedwait/sigwaitinfo`（kernel/signal.c:3604）则是**同步消费**：把感兴趣的集合取反暂存进 `real_blocked`（该字段只有 sigtimedwait 用），`schedule_hrtimeout_range` 睡眠（带 timer_slack），醒来先 `__set_task_blocked(real_blocked)` 复原再出队——sigwait 成功时信号被**吃掉**（不执行任何动作、不调 handler），这是 POSIX "sigwait 消灭信号"语义的实现点；`restore_saved_sigmask`（`saved_sigmask` + `TIF_RESTORE_SIGMASK`）则支撑了 ppoll/pselect/epoll_pwait 的临时掩码（进系统调用换窄掩码、`-ERESTARTNOHAND` 退出时由 arch 层恢复）。

## 七、特殊信号行为

### 7.1 SIGSTOP/SIGCONT：job control 的组协议

终端按 ^Z → tty 驱动 `__kill_pgrp_info(SIGTSTP)` 组播（kernel/signal.c:1471 注释原话："this is what the tty control characters do (^C, ^Z etc)"）。递送侧 `do_signal_stop`（kernel/signal.c:2417）：

```
do_signal_stop(signr)（get_signal 的 sig_kernel_stop 分支进入）
 ├─ JOBCTL_STOP_PENDING 未置？我是发起者：
 │    signal->group_exit_code = signr（SIGNAL_STOP_STOPPED 时保留旧值）
 │    for_each_thread：task_set_jobctl_pending(每线程, signr|gstop)
 │       → group_stop_count++（"该到齐多少人"）；seized 线程改走
 │         ptrace_trap_notify（第 5 章：PTRACE_EVENT_STOP）
 ├─ 非 ptrace：
 │    task_participate_group_stop：--group_stop_count 减到 0
 │      → 我是最后一个 → notify = CLD_STOPPED
 │    jobctl |= JOBCTL_STOPPED; set_special_state(TASK_STOPPED)  ★ 组停止
 │    schedule()                          睡到 SIGCONT/SIGKILL
 │    （notify → do_notify_parent_cldstop(real_parent)）
 └─ ptrace 中：不亲自停，置 JOBCTL_TRAP_STOP 交给 tracer 裁决
```

SIGCONT 的反向动作全在 §3.3 的 `prepare_signal`：冲队列 stop 信号、清 `JOBCTL_STOP_PENDING/STOPPED`、唤醒全部 STOPPED 线程、置 `SIGNAL_STOP_CONTINUED`（供 WCONTINUED 收割）与延迟 CLD_CONTINUED 通知位。两个易错点：**孤儿进程组里 SIGTSTP/TTIN/TTOU 无效**（`is_current_pgrp_orphaned`——get_signal 中为此专门解锁再检查，容忍窗口内插入的 SIGCONT；但 SIGSTOP 永远有效）；**SIGNAL_STOP_CONTINUED 只在有人 WCONTINUED 时消费**（`wait_task_continued`），无人认领则一直挂着（POSIX 的延续性语义）。

### 7.2 SIGKILL 的快速路径与 PF_EXITING

汇总 §3.5 + 第 3 章 §2.2 的完整图景：**活进程**的 `kill -9` 走组退出快速路径（SIGNAL_GROUP_EXIT + 每线程位图 SIGKILL + 致命唤醒），各线程在 `get_signal` 顶部短路进 `do_group_exit`；coredump 类信号不走快速路径（要先写盘，第 5 章 §六）。**`PF_EXITING` 已置位的线程**：`wants_signal` 直接跳过——它永远不会再回用户态，递送无意义；`exit_signals` 里 `retarget_shared_pending` 把它名下的共享信号转投活线程；`do_group_exit` ① `synchronize_group_exit` 置 `SIGNAL_GROUP_EXIT` 后，`prepare_signal` 对全组新信号一概丢弃（唯一例外：coredump 中放行 SIGKILL 打断写盘）。**SIGKILL 对退出中任务的真实作用是"推进"而非"递送"**：清理路径上的睡眠点要么在 `signal_pending_state` 抢救下拒绝入睡（TASK_INTERRUPTIBLE/TASK_WAKEKILL 类睡眠，调度器分册 04 §4.2），要么显式检查 `fatal_signal_pending`（`do_coredump` 的 `dump_interrupted`、`copy_process` 的"Let kill terminate clone/fork in the middle"检查点——kernel/fork.c:2658）。（有人声称"`PF_EXITING` 置位后 SIGKILL 走 `do_add_pid` 直投"——**内核没有这个函数/路径**，属对新版信号语义的误传。）

### 7.3 递归 fault：force_sig 家族的兜底

handler 里再出错（SIGSEGV handler 自己又 SIGSEGV、备用栈被写穿）时内核的两道保险：

```c
static int force_sig_info_to_task(struct kernel_siginfo *info,
		struct task_struct *t, enum sig_handler handler)
{                                              /* kernel/signal.c:1335 */
	action = &t->sighand->action[sig-1];
	ignored = action->sa.sa_handler == SIG_IGN;
	blocked = sigismember(&t->blocked, sig);
	if (blocked || ignored || (handler != HANDLER_CURRENT)) {
		action->sa.sa_handler = SIG_DFL;    /* ★ SIG_IGN 改默认 */
		if (handler == HANDLER_EXIT)
			action->sa.sa_flags |= SA_IMMUTABLE;   /* 一次性封死 */
		if (blocked) {
			sigdelset(&t->blocked, sig);  /* ★ 强制解封（sa_mask/用户封的）*/
			recalc_sigpending_and_wake(t);
		}
	}
	if (action->sa.sa_handler == SIG_DFL &&
	    (!t->ptrace || (handler == HANDLER_EXIT)))
		t->signal->flags &= ~SIGNAL_UNKILLABLE; /* 连 init 特权也击穿
		                                 （HANDLER_EXIT 恒真）*/
	ret = send_signal_locked(sig, info, t, PIDTYPE_PID); /* 恒 force */
	...
}
```

三档力度：`force_sig`（HANDLER_CURRENT——尊重现有 handler，只破屏蔽/忽略）、`force_fatal_sig`（HANDLER_SIG_DFL——强制默认动作）、`force_exit_sig`（HANDLER_EXIT——加 SA_IMMUTABLE 的死刑；02 章半 exec 失败的 `force_fatal_sig(SIGSEGV)` 同族）。递归 SEGV 的最终兜底是 `force_sigsegv`（kernel/signal.c:1713）：`sig == SIGSEGV ? force_fatal_sig(SIGSEGV) : force_sig(SIGSEGV)`——出问题的就是 SEGV 本身时**升级**，无视一切 handler 安装。完整链条（x86）：handler 执行中 fault → 缺页/trap 路径 `force_sig_fault(SIGSEGV,...)` → 该信号因 `sa_mask` 屏蔽中 → `force_sig_info_to_task` **解封**并递送 → handler 再次执行 → 栈耗尽后 `get_sigframe` 返回 -1L、`setup_rt_frame` 失败 → `handle_signal` 的 `signal_setup_done(failed=1) → force_sigsegv(sig)`：SA_IMMUTABLE + SIG_DFL + 清 UNKILLABLE → 默认动作（core+term）终结；配合 §4.2 的 SYNCHRONOUS_MASK 插队（fault 信号永远先于异步信号出队），保证 RIP 指向出错指令、退化的 handler 不会再被卷入。

## 八、与调度器/中断的联动点总结

| TIF_SIGPENDING 的检查点 | 位置 | 动作 |
| :--- | :--- | :--- |
| syscall / 中断 / 异常返回用户态 | `syscall_exit_to_user_mode` / `irqentry_exit_to_user_mode` → `exit_to_user_mode_loop` | `arch_do_signal_or_restart`（§4.1） |
| `__schedule` 出队判定 | `signal_pending_state(...) → WRITE_ONCE(__state, TASK_RUNNING)` | "信号抢救"：可中断睡眠被打回运行态（调度器 04 §4.2） |
| 任意可中断睡眠 | `wait_event_interruptible` / `mutex_lock_interruptible` 等 | `-EINTR/-ERESTARTSYS` 撤退 |
| 缺页重试 | `fault_signal_pending(VM_FAULT_RETRY)` | 中断缺页循环、先处理信号（mm 分册） |
| 唤醒侧 | `signal_wake_up_state`：置 TIF + `wake_up_state` | 置位者；唤醒失败 → `kick_process` IPI |
| fork 慢路径 | `copy_process` 中 `fatal_signal_pending(current)` → `-EINTR` | 克隆中途可被杀（fork.c:2658） |
| `finish_task_switch` | `calculate_sigpending()`（调度器 04 §5.3） | 新任务上线时重算（fork 期间的信号不丢） |

> 💡 `TIF_NOTIFY_SIGNAL` 与 `TIF_SIGPENDING` 并列检查（§4.1）：前者是 task_work 的"借用信道"（`set_notify_signal`），行为上要求与信号一致——打破可中断等待、回用户态前收口，但它不是信号（`signal_pending()` 把两者都算 1，见 include/linux/sched/signal.h:392 的注释）。

## 九、观测与调试

### 9.1 /proc/PID/status 的信号五行

```
SigQ:   2/127591                  # sigqueue 占用/RLIMIT_SIGPENDING（ucounts 记账）
SigPnd: 0000000000000000          # 本线程私有 pending（读的是该 TID 的字段）
ShdPnd: 0000000200000000          # 线程组共享 pending
SigBlk: 0000000028010000          # 本线程 blocked
SigIgn: 0000000000001000          # sighand 表中 SIG_IGN 的位（进程级）
SigCgt: 00000001c987cfc1          # sighand 表中自定义 handler 的位（进程级）
```

十六进制读法（`render_sigset_t`，fs/proc/array.c:227）：16 个 nibble 从**高位（信号 64）到低位（信号 1）**排布——最右字符是 1~4 号。例：`ShdPnd: ...2000000000` 的 `2` 在右数第 10 位 → 信号 34（glibc SIGRTMIN）。**注意 SigPnd≠"进程的全部待决"**：它是**单个线程**的私有队列（读 /proc/PID/task/TID/status 才是那个线程的），共享队列在 ShdPnd；SigIgn/SigCgt 是进程级（sighand 表共享）。

### 9.2 动态观测

```
strace -p PID            # --- SIGSEGV {si_signo=SIGSEGV, si_code=SEGV_MAPERR,
```

## 十、思考题

1. **为什么 legacy 队列合并而 rt 信号不合并？合并的"信息损失"发生在哪一步？** 提示：legacy 信号诞生时多数不带 payload（kill 的 si_pid/si_uid 即可重建大部分语义）；位图只能表达"有/无"；`collect_signal` 取 first——后到的 siginfo 整份丢弃；rt 的契约是"sigqueue 返回 0 = 已排队一份"。追问：`kill()` 发 rt 信号为什么永不返回 EAGAIN？（§3.4 的静默分支）
2. **`complete_signal` 里 `curr_target` 轮转解决什么问题？若没有它会怎样？** 提示：多线程服务器"总是主线程收信号"的惊群/饥饿；`task_curr` 与 `!task_sigpending` 两个偏好各自的理由（§3.5）；轮转指针在 signal_struct 而非 task_struct——它是组播的负载均衡器。
3. **发给线程组的信号如何被"藏"在一个屏蔽它的线程里？说出两种"藏法"和对应的解锁机制。** 提示：私有屏蔽（blocked）与 `do_send_specific` 定向投递（PIDTYPE_PID 只进那个线程的私有队列，连 retarget 都救不了）；`sigwait` 的 real_blocked；`retarget_shared_pending` 只在"屏蔽变化/线程退出"时触发。
4. **SIGKILL 从不分配 sigqueue；递送时它从共享队列出队吗？** 提示：组退出快速路径（§3.5）后每个线程的 `get_signal` 顶部短路——`sigdelset(&current->pending.signal, SIGKILL)` 删的是**私有**位图（谁塞进去的？）；`do_group_exit` 与 03 章 §一的 ① `synchronize_group_exit` 的码值竞争。
5. **同一个 SIGCHLD：为什么 shell 里 `$?` 能拿到退出码，`SIG_IGN` 之后就永远拿不到了？** 提示：`autoreap` 路径连僵尸都不留（03 章 §6.1）；`__wake_up_parent` 在 SIG_IGN 时仍然执行（醒来为什么只会得到 ECHILD？）；`SA_NOCLDWAIT` 与 SIG_IGN 的细微差别（信号照发 vs 完全不发）。
6. **实验**：多线程程序里 (a) 主线程 `pthread_sigmask` 屏蔽 SIGUSR1 后由别的线程 `kill(getpid(), SIGUSR1)`；(b) 改用 `tgkill` 定向发主线程。分别用 `/proc/PID/task/*/status` 的 SigPnd/ShdPnd/SigBlk 验证信号藏在哪；(c) `sigwait` 版本验证信号被"吃掉"后 SigPnd 归零。提示：对照 §2.4 职责分界表预测再实测。
