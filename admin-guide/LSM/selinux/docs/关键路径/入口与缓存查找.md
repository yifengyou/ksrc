# 入口与缓存查找

以openEuler OLK-6.6内核源代码为例

## 入口函数 - avc_has_perm

```c
/**
 * avc_has_perm - Check permissions and perform any appropriate auditing.
 * @ssid: source security identifier
 * @tsid: target security identifier
 * @tclass: target security class
 * @requested: requested permissions, interpreted based on @tclass
 * @auditdata: auxiliary audit data
 *
 * Check the AVC to determine whether the @requested permissions are granted
 * for the SID pair (@ssid, @tsid), interpreting the permissions
 * based on @tclass, and call the security server on a cache miss to obtain
 * a new decision and add it to the cache.  Audit the granting or denial of
 * permissions in accordance with the policy.  Return %0 if all @requested
 * permissions are granted, -%EACCES if any permissions are denied, or
 * another -errno upon other errors.
 */
int avc_has_perm(u32 ssid, u32 tsid, u16 tclass,
		 u32 requested, struct common_audit_data *auditdata)
{
	struct av_decision avd;
	int rc, rc2;

	rc = avc_has_perm_noaudit(ssid, tsid, tclass, requested, 0,
				  &avd); // 策略是否命中缓存，没有命中则计算

	rc2 = avc_audit(ssid, tsid, tclass, requested, &avd, rc,
			auditdata); // 处理审计
	if (rc2)
		return rc2;
	return rc;
}
```

* avc_has_perm 是 SELinux 内核模块中最核心、最关键的权限检查入口函数。几乎每一个 SELinux LSM Hook（安全钩子）在需要判断“是否允许执行某操作”时，最终都会调用这个函数（或其变体）

可以将 SELinux 的工作流简化为以下三层：
1. 内核操作层 (VFS/Network/etc.): 例如 open(), bind(), connect()。
2. LSM Hook 层: 内核在这些操作的关键点插入钩子，例如 security_file_open, security_socket_bind。
3. SELinux 策略层: 具体的检查逻辑，avc_has_perm 就在这里。

```text
用户调用 open("/etc/shadow")
      ↓
内核 VFS 层
      ↓
LSM Hook: security_file_open()
      ↓
SELinux 实现: selinux_file_open()
      ↓
[关键步骤] 调用 avc_has_perm(ssid, tsid, FILE__OPEN, ...)  <-- 这里！
      ↓
   ├─> 检查 AVC 缓存 (Hit?) → 直接返回允许/拒绝
   └─> 缓存未命中 (Miss) → 调用 security_compute_av() → 执行 TE + MLS 检查 → 更新缓存
      ↓
返回结果 (0 或 -EACCES)
      ↓
LSM Hook 根据结果决定：继续执行操作 OR 阻断并报错

```

* 如果没有 avc_has_perm，LSM Hooks 就只是一堆空壳，无法真正依据策略文件（policy）来执行访问控制。


```c
// hooks.c 中的大量实例
static int selinux_inode_check_access(...) {
    ...
    rc = avc_has_perm(sid, isid, SECCLASS_FILE, perms, ad);
    ...
}

static int selinux_socket_bind(...) {
    ...
    err = avc_has_perm(sid, saddr_sid, SECCLASS_NODE, NODE__BIND, &ad);
    ...
}

static int selinux_task_kill(...) {
    ...
    rc = avc_has_perm(current_sid(), p_sid, SECCLASS_PROCESS, PROCESS__SIGKILL, &ad);
    ...
}
```

* avc_has_perm 是 SELinux 实施强制访问控制（MAC）的执行器
* 几乎所有涉及权限判定的 LSM Hook 都必须经过它。没有它，SELinux 就无法根据策略允许或拒绝操作
* 无论上层是文件、网络还是进程，只要到了这一层，都统一转化为 (源SID, 目标SID, 类别, 权限) 的四元组检查，保证了策略执行的一致性。


### 策略与审计分离 - avc_has_perm_noaudit

```c
/**
 * avc_has_perm_noaudit - Check permissions but perform no auditing.
 * @ssid: source security identifier
 * @tsid: target security identifier
 * @tclass: target security class
 * @requested: requested permissions, interpreted based on @tclass
 * @flags:  AVC_STRICT or 0
 * @avd: access vector decisions
 *
 * Check the AVC to determine whether the @requested permissions are granted
 * for the SID pair (@ssid, @tsid), interpreting the permissions
 * based on @tclass, and call the security server on a cache miss to obtain
 * a new decision and add it to the cache.  Return a copy of the decisions
 * in @avd.  Return %0 if all @requested permissions are granted,
 * -%EACCES if any permissions are denied, or another -errno upon
 * other errors.  This function is typically called by avc_has_perm(),
 * but may also be called directly to separate permission checking from
 * auditing, e.g. in cases where a lock must be held for the check but
 * should be released for the auditing.
 */
inline int avc_has_perm_noaudit(u32 ssid, u32 tsid,
				u16 tclass, u32 requested,
				unsigned int flags,
				struct av_decision *avd)
{
	u32 denied;
	struct avc_node *node;

	if (WARN_ON(!requested))
		return -EACCES;

	rcu_read_lock();
	node = avc_lookup(ssid, tsid, tclass);
	if (unlikely(!node)) {
		rcu_read_unlock(); // 缓存未命中
		return avc_perm_nonode(ssid, tsid, tclass, requested,
				       flags, avd);
	} // 否则缓存命中，返回结果
	denied = requested & ~node->ae.avd.allowed;
	memcpy(avd, &node->ae.avd, sizeof(*avd));
	rcu_read_unlock();

	if (unlikely(denied))
		return avc_denied(ssid, tsid, tclass, requested, 0, 0,
				  flags, avd);
	return 0;
}

```

### 为什么要分离 "NoAudit"

* 场景: 假设某个内核子系统（如文件系统）持有一个自旋锁（Spinlock）或者处于中断上下文中。
* 限制: 在持有自旋锁时，绝对不能执行可能睡眠的操作，也绝对不能执行复杂的日志记录（审计子系统可能获取自己的锁，甚至触发磁盘 I/O 或内存分配）。

解决方案:
1. 先调用 avc_has_perm_noaudit：它只进行快速的内存查找和位运算。即使在缓存未命中时，avc_perm_nonode 也会小心处理（通常缓存未命中路径本身就不允许在自旋锁下调用，或者有更复杂的机制，但在命中路径下它是完全安全的）。最重要的是，它不触碰审计子系统。
2. 释放子系统的锁。
3. 再调用 avc_audit：此时环境安全了，可以安心地记录日志。

性能优化亮点:
1. RCU (Read-Copy-Update): 实现了读侧的极致并发性能，多核 CPU 下不会因为争抢读写锁而退化。
2. 位运算 (Bitwise Operations): 权限检查被简化为几条 CPU 指令 (AND, NOT, TEST)，速度极快。
3. 分支预测 (unlikely): 引导 CPU 流水线优先执行“缓存命中且允许”的最常见路径。
4. 内联 (inline): 消除函数调用压栈开销。
5. 数据局部性: avc_node 结构设计紧凑，利于 CPU 缓存命中。

avc_has_perm_noaudit 是 SELinux 性能的心脏。它确保了在绝大多数情况下（缓存命中），权限检查对系统性能的影响几乎可以忽略不计。同时，通过将审计剥离，它为内核其他子系统提供了灵活的调用时机，避免了潜在的死锁问题。


## 缓存查询入口 - avc_lookup


```c
/**
 * avc_lookup - Look up an AVC entry.
 * @ssid: source security identifier // 发起访问的进程的安全上下文 ID
 * @tsid: target security identifier // 被访问对象，如文件、端口、socket 的安全上下文 ID
 * @tclass: target security class // 被访问对象的类型，如 file, dir, tcp_socket 等
 *
 * Look up an AVC entry that is valid for the
 * (@ssid, @tsid), interpreting the permissions
 * based on @tclass.  If a valid AVC entry exists,
 * then this function returns the avc_node.
 * Otherwise, this function returns NULL.
 */
static struct avc_node *avc_lookup(u32 ssid, u32 tsid, u16 tclass)
{
	struct avc_node *node;

	avc_cache_stats_incr(lookups); // 统计计数器：增加“查找”操作的计数
	node = avc_search_node(ssid, tsid, tclass);

	if (node) // 如果找到匹配的缓存条目，返回指向 struct avc_node 的指针。该节点中包含了之前计算好的允许/拒绝决策
		return node;

	avc_cache_stats_incr(misses); // 统计计数器：增加“未命中”计数
	return NULL; // 如果未找到，返回 NULL。此时调用者通常需要调用更慢的策略服务器（Policy Server）进行完整计算，并将结果填入缓存。
}
```

* SELinux 策略可能包含数万条规则。每次系统调用（如 open, connect, bind）都涉及权限检查。如果每次都遍历整个策略数据库，系统性能会下降几个数量级
* 利用局部性原理。在实际运行中，相同的进程（ssid）访问相同的文件类型（tsid + tclass）的行为是高度重复的。
* avc_lookup 使得绝大多数权限检查能在微秒级完成（仅内存查找），只有在首次访问或策略重载时才会产生较大开销。
* avc_lookup 是 SELinux 性能优化的第一道防线。它是一个纯粹的读操作（在 RCU 保护下），设计目标是极致的速度。


### 哈希函数 - avc_hash

```c
static inline u32 avc_hash(u32 ssid, u32 tsid, u16 tclass)
{
	return (ssid ^ (tsid<<2) ^ (tclass<<4)) & (AVC_CACHE_SLOTS - 1);
}

```




### 核心查找动作 - avc_search_node

```c
static inline struct avc_node *avc_search_node(u32 ssid, u32 tsid, u16 tclass)
{
	struct avc_node *node, *ret = NULL;
	u32 hvalue;
	struct hlist_head *head;

	hvalue = avc_hash(ssid, tsid, tclass); // 计算hash值
	head = &selinux_avc.avc_cache.slots[hvalue]; // 定位哈希桶 (Hash Bucket)
	hlist_for_each_entry_rcu(node, head, list) { // RCU 安全遍历链表
		if (ssid == node->ae.ssid &&
		    tclass == node->ae.tclass &&
		    tsid == node->ae.tsid) { // 匹配三元组 (ssid, tsid, tclass)
			ret = node; // 找到即退出
			break;
		}
	}

	return ret;
}
```

* 在高并发场景下，快速判断是否已经缓存了某个“源安全ID (ssid)”对“目标安全ID (tsid)”在特定“目标类别 (tclass)”下的访问决策结果。
* 该函数被设计为 无锁读取 (Lock-free)，利用 RCU (Read-Copy-Update) 机制，确保在多核CPU上高频调用时不会成为性能瓶颈。



### 核心查找算法

* 核心算法可以概括为：基于哈希表的无锁查找（Lock-free Hash Table Lookup），并辅以 RCU (Read-Copy-Update) 机制来保证高并发下的数据一致性。


1. 数据结构基础：哈希表 (Hash Table)

*   **目的**：将 $O(N)$ 的线性查找复杂度降低到平均 $O(1)$。
*   **键值 (Key)**：由三元组构成 `(ssid, tsid, tclass)`。
    *   `ssid`: 源安全 ID (Subject Security ID)，即发起访问的进程。
    *   `tsid`: 目标安全 ID (Target Security ID)，即被访问的对象（如文件、端口）。
    *   `tclass`: 目标类别 (Target Class)，即对象的类型（如文件、目录、TCP socket）。
*   **哈希函数 (`avc_hash`)**：
    *   代码首先调用 `avc_hash(ssid, tsid, tclass)` 计算出一个哈希值 `hvalue`。
    *   这个值用于映射到哈希表 `selinux_avc.avc_cache.slots` 中的具体桶（Bucket/Slot）索引。
    *   *设计意图*：优秀的哈希函数能确保不同的三元组均匀分布在不同桶中，减少哈希冲突（碰撞）。

1. 冲突解决：链地址法 (Chaining)
*   **结构**：每个哈希桶 (`head`) 实际上是一个链表头 (`struct hlist_head`)。
*   **逻辑**：
    *   当多个不同的三元组计算出相同的 `hvalue` 时，它们会被挂在同一个桶的链表上。
    *   代码通过 `hlist_for_each_entry_rcu` 遍历该链表。
    *   在遍历过程中，逐个比对节点中的 `ssid`, `tsid`, `tclass` 是否与查询条件完全匹配。
    *   一旦匹配成功，立即 `break` 并返回该节点指针。

1. 并发控制核心：RCU (Read-Copy-Update)
这是该算法在高并发场景下性能卓越的关键。

*   **问题背景**：在多核 CPU 上，如果有成千上万个进程同时发起系统调用（如 `open`, `connect`），它们都需要查询 AVC 缓存。如果使用传统的读写锁（rwlock）或互斥锁（mutex），大量的锁竞争（Lock Contention）会导致严重的性能下降，甚至成为系统瓶颈。
*   **解决方案**：
    *   **读端无锁**：代码中使用 `hlist_for_each_entry_rcu` 进行遍历。这意味着读取操作**不需要获取任何锁**。
    *   **内存屏障与原子性**：RCU 机制保证了读者在遍历链表时，即使写者（正在插入新缓存项或删除旧项）同时在修改链表结构，读者也能看到一个“一致”的快照，或者安全地完成遍历而不会读到半更新的数据（如悬空指针）。
    *   **写端策略**：写操作（插入/删除）会在新的内存副本上进行修改，然后原子地更新指针指向新数据，最后等待所有当前的读操作完成（Grace Period）后再释放旧数据。

1. 算法流程总结

2.  **输入**：接收访问请求的三元组 `(ssid, tsid, tclass)`。
3.  **哈希定位**：计算哈希值，直接跳转到对应的哈希桶。
4.  **RCU 临界区进入**：隐式地进入 RCU 读侧临界区（通常由调用者在外部包裹 `rcu_read_lock()`，或者依赖上下文保证）。
5.  **链表遍历**：
    *   沿着链表逐个节点检查。
    *   **精确匹配**：只有当三个字段全部相等时，才视为命中（Cache Hit）。
6.  **结果返回**：
    *   **命中**：返回节点指针，上层逻辑直接使用该节点中缓存的允许/拒绝决策，无需再次咨询 SELinux 策略引擎。
    *   **未命中**：遍历结束未找到，返回 `NULL`。上层逻辑将执行完整的策略检查，并将结果**插入**到此哈希表中供后续使用。

7. 为什么这个设计如此重要？

*   **热点路径优化**：在运行稳定的系统中，绝大多数访问决策都是重复的（例如，Web 服务器进程反复读取同一个配置文件）。AVC 缓存命中率通常极高（>90%）。
*   **极低的延迟**：由于去除了锁开销，查找过程仅仅是几次内存访问和整数比较，速度极快。
*   **可扩展性**：随着 CPU 核数增加，传统锁机制的性能会急剧下降，而基于 RCU 的无锁查找性能几乎呈线性扩展，非常适合现代多核服务器环境。

### 潜在风险与应对
*   **哈希冲突过多**：如果哈希函数设计不佳或缓存表太小，链表会变长，退化为 $O(N)$。Linux 内核会根据负载动态调整哈希表大小或重新哈希。
*   **缓存污染/淘汰**：虽然此函数只负责查，但配套的插入逻辑通常包含淘汰策略（如 LRU 变种），防止缓存无限膨胀占用内核内存。

综上所述，`avc_search_node` 是典型的**空间换时间** + **无锁并发**的工程杰作，它是 SELinux 能够在生产环境中高效运行的基石。





## 查询服务(处理缓存未命中) - avc_perm_nonode

```c
	node = avc_lookup(ssid, tsid, tclass);
	if (unlikely(!node)) {
		rcu_read_unlock(); // 缓存未命中
		return avc_perm_nonode(ssid, tsid, tclass, requested,
				       flags, avd);
	} // 否则缓存命中，返回结果

```


```c
/**
 * avc_perm_nonode - Add an entry to the AVC
 * @ssid: subject
 * @tsid: object/target
 * @tclass: object class
 * @requested: requested permissions
 * @flags: AVC flags
 * @avd: access vector decision
 *
 * This is the "we have no node" part of avc_has_perm_noaudit(), which is
 * unlikely and needs extra stack space for the new node that we generate, so
 * don't inline it.
 */
static noinline int avc_perm_nonode(u32 ssid, u32 tsid, u16 tclass,
				    u32 requested, unsigned int flags,
				    struct av_decision *avd)
{
	u32 denied;
	struct avc_xperms_node xp_node;

	avc_compute_av(ssid, tsid, tclass, avd, &xp_node);
	denied = requested & ~(avd->allowed); // 如果 denied 非零，说明请求中包含至少一项被策略禁止的操作
	if (unlikely(denied))
		return avc_denied(ssid, tsid, tclass, requested, 0, 0,
				  flags, avd);
	return 0;
}

static noinline int avc_denied(u32 ssid, u32 tsid,
			       u16 tclass, u32 requested,
			       u8 driver, u8 xperm, unsigned int flags,
			       struct av_decision *avd)
{
	if (flags & AVC_STRICT)
		return -EACCES;

	if (enforcing_enabled() &&
	    !(avd->flags & AVD_FLAGS_PERMISSIVE))
		return -EACCES;

	avc_update_node(AVC_CALLBACK_GRANT, requested, driver,
			xperm, ssid, tsid, tclass, avd->seqno, NULL, flags); // 更新cache
	return 0;
}
```


### static noinline 修饰符

缓存未命中是低频事件（Hot path 应该尽可能快）。此函数需要分配新节点、调用复杂的策略引擎，栈帧较大。如果不禁止内联，编译器可能会将这个庞大的函数体嵌入到高频调用的 avc_has_perm 中，导致热路径的指令缓存（I-Cache）效率降低且栈空间浪费。将其标记为 noinline 确保它作为一个独立的函数调用存在，优化了常见路径（缓存命中）的性能。





### 查询安全服务器 - avc_compute_av

```c
/**
 * avc_compute_av - Add an entry to the AVC based on the security policy
 * @ssid: subject
 * @tsid: object/target
 * @tclass: object class
 * @avd: access vector decision
 * @xp_node: AVC extended permissions node
 *
 * Slow-path helper function for avc_has_perm_noaudit, when the avc_node lookup
 * fails.  Don't inline this, since it's the slow-path and just results in a
 * bigger stack frame.
 */
static noinline void avc_compute_av(u32 ssid, u32 tsid, u16 tclass,
				    struct av_decision *avd,
				    struct avc_xperms_node *xp_node)
{
	INIT_LIST_HEAD(&xp_node->xpd_head);
	security_compute_av(ssid, tsid, tclass, avd, &xp_node->xp);
	avc_insert(ssid, tsid, tclass, avd, xp_node);
}
```


```c
/**
 * security_compute_av - Compute access vector decisions.
 * @ssid: source security identifier
 * @tsid: target security identifier
 * @orig_tclass: target security class
 * @avd: access vector decisions
 * @xperms: extended permissions
 *
 * Compute a set of access vector decisions based on the
 * SID pair (@ssid, @tsid) for the permissions in @tclass.
 */
void security_compute_av(u32 ssid,
			 u32 tsid,
			 u16 orig_tclass,
			 struct av_decision *avd,
			 struct extended_perms *xperms)
{
	struct selinux_policy *policy;
	struct policydb *policydb;
	struct sidtab *sidtab;
	u16 tclass;
	struct context *scontext = NULL, *tcontext = NULL;

	rcu_read_lock();
	policy = rcu_dereference(selinux_state.policy);
	avd_init(policy, avd);
	xperms->len = 0;
	if (!selinux_initialized())
		goto allow;

	policydb = &policy->policydb;
	sidtab = policy->sidtab;

	scontext = sidtab_search(sidtab, ssid);
	if (!scontext) {
		pr_err("SELinux: %s:  unrecognized SID %d\n",
		       __func__, ssid);
		goto out;
	}

	/* permissive domain? */
	if (ebitmap_get_bit(&policydb->permissive_map, scontext->type))
		avd->flags |= AVD_FLAGS_PERMISSIVE;

	tcontext = sidtab_search(sidtab, tsid);
	if (!tcontext) {
		pr_err("SELinux: %s:  unrecognized SID %d\n",
		       __func__, tsid);
		goto out;
	}

	tclass = unmap_class(&policy->map, orig_tclass);
	if (unlikely(orig_tclass && !tclass)) {
		if (policydb->allow_unknown)
			goto allow;
		goto out;
	}
	context_struct_compute_av(policydb, scontext, tcontext, tclass, avd,
				  xperms);
	map_decision(&policy->map, orig_tclass, avd,
		     policydb->allow_unknown);
out:
	rcu_read_unlock();
	return;
allow:
	avd->allowed = 0xffffffff;
	goto out;
}
```

### 更新缓存 - avc_update_node

```c
/**
 * avc_update_node - Update an AVC entry
 * @event : Updating event
 * @perms : Permission mask bits
 * @driver: xperm driver information
 * @xperm: xperm permissions
 * @ssid: AVC entry source sid
 * @tsid: AVC entry target sid
 * @tclass : AVC entry target object class
 * @seqno : sequence number when decision was made
 * @xpd: extended_perms_decision to be added to the node
 * @flags: the AVC_* flags, e.g. AVC_EXTENDED_PERMS, or 0.
 *
 * if a valid AVC entry doesn't exist,this function returns -ENOENT.
 * if kmalloc() called internal returns NULL, this function returns -ENOMEM.
 * otherwise, this function updates the AVC entry. The original AVC-entry object
 * will release later by RCU.
 */
static int avc_update_node(u32 event, u32 perms, u8 driver, u8 xperm, u32 ssid,
			   u32 tsid, u16 tclass, u32 seqno,
			   struct extended_perms_decision *xpd,
			   u32 flags)
{
	u32 hvalue;
	int rc = 0;
	unsigned long flag;
	struct avc_node *pos, *node, *orig = NULL;
	struct hlist_head *head;
	spinlock_t *lock;

	node = avc_alloc_node();
	if (!node) {
		rc = -ENOMEM;
		goto out;
	}

	/* Lock the target slot */
	hvalue = avc_hash(ssid, tsid, tclass);

	head = &selinux_avc.avc_cache.slots[hvalue];
	lock = &selinux_avc.avc_cache.slots_lock[hvalue];

	spin_lock_irqsave(lock, flag);

	hlist_for_each_entry(pos, head, list) {
		if (ssid == pos->ae.ssid &&
		    tsid == pos->ae.tsid &&
		    tclass == pos->ae.tclass &&
		    seqno == pos->ae.avd.seqno){
			orig = pos;
			break;
		}
	}

	if (!orig) {
		rc = -ENOENT;
		avc_node_kill(node);
		goto out_unlock;
	}

	/*
	 * Copy and replace original node.
	 */

	avc_node_populate(node, ssid, tsid, tclass, &orig->ae.avd);

	if (orig->ae.xp_node) {
		rc = avc_xperms_populate(node, orig->ae.xp_node);
		if (rc) {
			avc_node_kill(node);
			goto out_unlock;
		}
	}

	switch (event) {
	case AVC_CALLBACK_GRANT:
		node->ae.avd.allowed |= perms;
		if (node->ae.xp_node && (flags & AVC_EXTENDED_PERMS))
			avc_xperms_allow_perm(node->ae.xp_node, driver, xperm);
		break;
	case AVC_CALLBACK_TRY_REVOKE:
	case AVC_CALLBACK_REVOKE:
		node->ae.avd.allowed &= ~perms;
		break;
	case AVC_CALLBACK_AUDITALLOW_ENABLE:
		node->ae.avd.auditallow |= perms;
		break;
	case AVC_CALLBACK_AUDITALLOW_DISABLE:
		node->ae.avd.auditallow &= ~perms;
		break;
	case AVC_CALLBACK_AUDITDENY_ENABLE:
		node->ae.avd.auditdeny |= perms;
		break;
	case AVC_CALLBACK_AUDITDENY_DISABLE:
		node->ae.avd.auditdeny &= ~perms;
		break;
	case AVC_CALLBACK_ADD_XPERMS:
		rc = avc_add_xperms_decision(node, xpd);
		if (rc) {
			avc_node_kill(node);
			goto out_unlock;
		}
		break;
	}
	avc_node_replace(node, orig);
out_unlock:
	spin_unlock_irqrestore(lock, flag);
out:
	return rc;
}
```
