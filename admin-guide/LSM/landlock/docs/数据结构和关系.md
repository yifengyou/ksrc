# 数据结构和关系

## landlock_ruleset

```c

/**
 * struct landlock_ruleset - Landlock ruleset
 *
 * This data structure must contain unique entries, be updatable, and quick to
 * match an object.
 */
struct landlock_ruleset {
	/**
	 * @root: Root of a red-black tree containing &struct landlock_rule
	 * nodes.  Once a ruleset is tied to a process (i.e. as a domain), this
	 * tree is immutable until @usage reaches zero.
	 */
	struct rb_root root;
	/**
	 * @hierarchy: Enables hierarchy identification even when a parent
	 * domain vanishes.  This is needed for the ptrace protection.
	 */
	struct landlock_hierarchy *hierarchy;
	union {
		/**
		 * @work_free: Enables to free a ruleset within a lockless
		 * section.  This is only used by
		 * landlock_put_ruleset_deferred() when @usage reaches zero.
		 * The fields @lock, @usage, @num_rules, @num_layers and
		 * @fs_access_masks are then unused.
		 */
		struct work_struct work_free;
		struct {
			/**
			 * @lock: Protects against concurrent modifications of
			 * @root, if @usage is greater than zero.
			 */
			struct mutex lock;
			/**
			 * @usage: Number of processes (i.e. domains) or file
			 * descriptors referencing this ruleset.
			 */
			refcount_t usage;
			/**
			 * @num_rules: Number of non-overlapping (i.e. not for
			 * the same object) rules in this ruleset.
			 */
			u32 num_rules;
			/**
			 * @num_layers: Number of layers that are used in this
			 * ruleset.  This enables to check that all the layers
			 * allow an access request.  A value of 0 identifies a
			 * non-merged ruleset (i.e. not a domain).
			 */
			u32 num_layers;
			/**
			 * @fs_access_masks: Contains the subset of filesystem
			 * actions that are restricted by a ruleset.  A domain
			 * saves all layers of merged rulesets in a stack
			 * (FAM), starting from the first layer to the last
			 * one.  These layers are used when merging rulesets,
			 * for user space backward compatibility (i.e.
			 * future-proof), and to properly handle merged
			 * rulesets without overlapping access rights.  These
			 * layers are set once and never changed for the
			 * lifetime of the ruleset.
			 */
			access_mask_t fs_access_masks[];
		};
	};
};

```

这是 Landlock 最核心的数据结构，代表一个**规则集（Ruleset）**。每个规则集包含一组访问控制规则，用于描述允许或拒绝哪些操作。

- **作用**：  
  存储一组访问权限规则（如读、写、执行等），并关联到特定的文件系统对象（如 inode）。

- **关键字段（基于内核源码 `security/landlock/ruleset.h`）**：
  - `usage`: 引用计数，用于内存管理（RCU + refcount）。
  - `num_layers`: 表示该规则集包含多少个“层”（layer）。Landlock 支持规则叠加，每添加一次规则就形成新的一层。
  - `access_masks`: 一个数组，记录每一层所支持的访问权限掩码（如 `LANDLOCK_ACCESS_FS_READ_FILE`）。
  - `root`: 指向一个 **红黑树（rb_root）**，用于高效存储和查找规则。树中的每个节点是一个 `struct landlock_rule`。
  - `lock`: 读写锁（`rwlock_t`），保护规则集在并发访问时的一致性。

- **生命周期**：  
  通过 `landlock_create_ruleset()` 系统调用创建，返回一个文件描述符（fd），用户空间可通过该 fd 添加规则。



## landlock_rule


```c

/**
 * struct landlock_rule - Access rights tied to an object
 */
struct landlock_rule {
	/**
	 * @node: Node in the ruleset's red-black tree.
	 */
	struct rb_node node;
	/**
	 * @object: Pointer to identify a kernel object (e.g. an inode).  This
	 * is used as a key for this ruleset element.  This pointer is set once
	 * and never modified.  It always points to an allocated object because
	 * each rule increments the refcount of its object.
	 */
	struct landlock_object *object;
	/**
	 * @num_layers: Number of entries in @layers.
	 */
	u32 num_layers;
	/**
	 * @layers: Stack of layers, from the latest to the newest, implemented
	 * as a flexible array member (FAM).
	 */
	struct landlock_layer layers[] __counted_by(num_layers);
};

```

表示一条具体的访问控制规则，存储在 `landlock_ruleset` 的红黑树中。

- **作用**：  
  将一个 **文件系统对象（通常是 inode）** 与一组 **允许的访问权限** 关联起来。

- **关键字段**：
  - `object`: 指向 `struct landlock_object`，封装了目标 inode。
  - `access`: 权限掩码（如 `READ_FILE | WRITE_FILE`），表示对该对象允许的操作。
  - `node`: 红黑树节点（`struct rb_node`），用于在规则集中快速查找。

- **特点**：  
  规则是**前缀匹配**的——如果一个路径 `/a/b/c` 被允许，那么其子路径（如 `/a/b/c/d`）默认继承该权限，除非被更具体的规则覆盖。


## landlock_object

```c

/**
 * struct landlock_object - Security blob tied to a kernel object
 *
 * The goal of this structure is to enable to tie a set of ephemeral access
 * rights (pertaining to different domains) to a kernel object (e.g an inode)
 * in a safe way.  This implies to handle concurrent use and modification.
 *
 * The lifetime of a &struct landlock_object depends on the rules referring to
 * it.
 */
struct landlock_object {
	/**
	 * @usage: This counter is used to tie an object to the rules matching
	 * it or to keep it alive while adding a new rule.  If this counter
	 * reaches zero, this struct must not be modified, but this counter can
	 * still be read from within an RCU read-side critical section.  When
	 * adding a new rule to an object with a usage counter of zero, we must
	 * wait until the pointer to this object is set to NULL (or recycled).
	 */
	refcount_t usage;
	/**
	 * @lock: Protects against concurrent modifications.  This lock must be
	 * held from the time @usage drops to zero until any weak references
	 * from @underobj to this object have been cleaned up.
	 *
	 * Lock ordering: inode->i_lock nests inside this.
	 */
	spinlock_t lock;
	/**
	 * @underobj: Used when cleaning up an object and to mark an object as
	 * tied to its underlying kernel structure.  This pointer is protected
	 * by @lock.  Cf. landlock_release_inodes() and release_inode().
	 */
	void *underobj;
	union {
		/**
		 * @rcu_free: Enables lockless use of @usage, @lock and
		 * @underobj from within an RCU read-side critical section.
		 * @rcu_free and @underops are only used by
		 * landlock_put_object().
		 */
		struct rcu_head rcu_free;
		/**
		 * @underops: Enables landlock_put_object() to release the
		 * underlying object (e.g. inode).
		 */
		const struct landlock_object_underops *underops;
	};
};

```

封装受控的内核对象（目前主要是文件系统的 inode）。

- **作用**：  
  抽象化受控资源，便于扩展（未来可能支持网络、进程等对象）。

- **关键字段**：
  - `usage`: 引用计数。
  - `underlying`: 指向实际的内核对象（如 `struct inode *`）。
  - `type`: 对象类型（当前仅 `LANDLOCK_OBJECT_FS`）。

- **设计意义**：  
  通过抽象层，Landlock 可在未来支持更多类型的资源控制（如套接字、进程间通信等）。


## 调用关系

```text
task_struct
    └── cred
        └── security → [landlock_domain] → ruleset (immutable)

ruleset
    ├── num_layers
    ├── access_masks[0..num_layers-1]
    └── rb_root (rules)
            └── landlock_rule
                    ├── object → landlock_object → inode
                    └── access (bitmask)
```


整体目标回顾

Landlock 的核心思想是：**一个进程可以主动限制自己（及其子进程）对文件系统的访问能力**。这种限制通过一组“规则”实现，这些规则最终会绑定到进程的“安全上下文”中，并在每次文件操作（如 open、stat、unlink 等）时被检查。

为了实现这一点，内核引入了几个关键数据结构，并通过 **`task_struct → cred → security → ruleset`** 这条链路将规则与进程关联起来。

---

### 第一层：`task_struct`

每个运行中的进程在内核中都有一个 `struct task_struct` 实例，它包含了该进程的所有信息（PID、状态、调度信息等）。

- **关键字段**：
```c
struct task_struct {
    ...
    const struct cred *cred;  // 指向进程的凭证（credentials）
    ...
};
```

> ✅ **作用**：`task_struct` 是进程的“身份证”，而 `cred` 字段则记录了这个进程的权限身份（比如 UID、GID、capabilities、以及安全模块的数据）。

---

### 第二层：`struct cred`

`cred`（credentials）结构体存储了进程的**安全凭证**。它不仅包含传统的用户/组 ID，还包含 LSM（Linux Security Module）使用的安全上下文。

- **关键字段**：
  ```c
  struct cred {
      kuid_t uid;            // 用户 ID
      kgid_t gid;            // 组 ID
      struct user_namespace *user_ns;
      ...
      void *security;        // ← 这里存放 LSM（如 SELinux、AppArmor、Landlock）的私有数据
  };
  ```

> ✅ **重点**：`cred->security` 是一个 `void*` 指针，不同 LSM 用它存储自己的数据。对于 Landlock，这里指向一个 **Landlock 域（domain）**。

---

### 第三层：Landlock Domain（域）

虽然内核源码中没有显式定义 `struct landlock_domain`，但 **“domain” 是 Landlock 文档和设计中的核心概念**，它实际上就是：

> **一个或多个不可变（immutable）的 `landlock_ruleset` 的集合**。

当你调用 `landlock_restrict_self(fd, 0)` 时：

1. 内核会复制当前进程的 `cred`（因为 `cred` 是只读共享的）；
2. 在新 `cred` 的 `security` 字段中，**保存当前规则集的指针**；
3. 这个新 `cred` 就构成了一个新的“安全域”——从此该进程只能按规则集中的权限访问文件系统。

> ⚠️ **重要特性**：
> - 一旦设置，domain **不能被修改或撤销**（不可变性）。
> - 可以多次调用 `landlock_restrict_self()`，每次都会**叠加一个新的规则集层（layer）**，形成多层检查。

所以你可以把 `cred->security` 看作指向一个 **Landlock 安全域对象**，而这个域内部包含一个或多个 `landlock_ruleset`。

---

### 第四层：`struct landlock_ruleset`

这是 Landlock 的核心容器，代表**一组访问控制规则**。

### 结构详解：

```c
struct landlock_ruleset {
    refcount_t usage;               // 引用计数
    u32 num_layers;                 // 规则层数（每 restrict 一次 +1）
    access_mask_t access_masks[];   // 每层支持的权限掩码（如 READ_FILE）
    struct rb_root root;            // 红黑树根节点，存储所有规则
    rwlock_t lock;                  // 读写锁，保护并发访问
};
```

- **`num_layers` 和 `access_masks`**：  
  每次你创建一个规则集并调用 `restrict_self`，就形成一层。每一层在创建时就固定了它能处理哪些权限（比如只允许 `READ_FILE` 和 `READ_DIR`）。后续不能添加超出范围的权限。

- **`root`（红黑树）**：  
  所有规则（`landlock_rule`）都以 **inode 地址为 key** 存储在这棵平衡二叉树中，确保 O(log n) 快速查找。

---

### 第五层：`struct landlock_rule`

每条规则表示：“对某个文件系统对象（如目录 /home/user），允许哪些操作”。

```c
struct landlock_rule {
    struct landlock_object *object;  // 指向受控对象（通常是 inode）
    access_mask_t access;            // 允许的权限（bitmask）
    struct rb_node node;             // 红黑树节点
};
```

- **`object`**：封装了内核的 `struct inode *`（通过 `landlock_object` 抽象）。
- **`access`**：例如 `LANDLOCK_ACCESS_FS_READ_FILE | LANDLOCK_ACCESS_FS_READ_DIR`。

> ✅ **路径继承语义**：  
> 如果你允许访问 `/tmp`，那么默认也允许访问 `/tmp/foo`、`/tmp/foo/bar`，除非有更具体的规则覆盖（比如禁止 `/tmp/secret`）。

---

### 第六层：`struct landlock_object`

这是一个抽象包装器，目前主要用于封装 `inode`，但为未来扩展（如网络 socket、进程等）预留接口。

```c
struct landlock_object {
    union {
        struct inode *inode;     // 当前只支持文件系统对象
        // 未来可能加入: struct sock *sk; 等
    } underlying;
    enum landlock_object_type type; // 如 LANDLOCK_OBJECT_FS
    refcount_t usage;
};
```

---

### 访问检查流程（举例）

当进程执行 `open("/home/user/data.txt", O_RDONLY)` 时：

1. VFS 层触发 LSM 钩子（如 `inode_permission`）；
2. Landlock 的钩子函数被调用；
3. 从当前 `task_struct → cred → security` 获取 Landlock 域；
4. 遍历域中的每一层 `ruleset`（从最新到最旧）；
5. 对 `data.txt` 的 inode，在红黑树中查找匹配的 `landlock_rule`；
6. 如果找到规则，检查 `access` 是否包含 `READ_FILE`；
7. 如果所有层都未明确允许 → **拒绝访问（-EACCES）**。

> 🔒 **默认拒绝**：Landlock 遵循“最小权限”原则——未明确允许即拒绝。

## 重新理解关系图

现在再看这张图，应该清晰多了：

```
task_struct
    └── cred
        └── security → [Landlock Domain] → landlock_ruleset (immutable)
                                            ├── num_layers = 2
                                            ├── access_masks[0] = READ_FILE
                                            ├── access_masks[1] = READ_FILE | WRITE_FILE
                                            └── rb_root
                                                    ├── rule1: object=/home → READ_FILE
                                                    └── rule2: object=/tmp  → READ_FILE|WRITE_FILE
                                                            └── object → landlock_object → inode of /tmp
```

- 一个进程 → 一个 `cred` → 一个 Landlock 安全域 → 一个或多个规则集（layers）→ 多条规则 → 每条规则绑定一个 inode 和权限。

---

## 总结

| 层级 | 数据结构 | 作用 |
|------|--------|------|
| 进程 | `task_struct` | 代表运行中的进程 |
| 凭证 | `cred` | 存储进程的安全身份 |
| 安全上下文 | `cred->security` | 指向 Landlock 域 |
| 规则容器 | `landlock_ruleset` | 存储一组不可变的访问规则（分层） |
| 单条规则 | `landlock_rule` | 定义对某个 inode 的权限 |
| 受控对象 | `landlock_object` | 封装 inode（或其他未来对象） |

这种设计使得 Landlock 既**高效**（红黑树查找）、又**安全**（不可变域、默认拒绝）、还**灵活**（支持多层策略叠加）。
