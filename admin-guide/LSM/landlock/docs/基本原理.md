# 基本原理

用一个**生活中的比喻**来解释 Landlock 的本质，避免技术术语，让你一听就懂。

---

### 🧒 比喻：孩子和玩具箱

想象你是一个家长（相当于操作系统内核），家里有一个大玩具箱（相当于整个文件系统，比如 `/home`、`/etc`、`/tmp` 等）。

- **传统 LSM（如 SELinux/AppArmor）**：  
  就像**家长自己制定规则**：“只有小明可以玩积木，小红只能玩画笔”，而且这些规则要家长提前写好、配置好。孩子自己不能改，也不能给自己设限。**必须靠大人管。**

- **Landlock 呢？**  
  它允许**孩子自己主动说**：“我现在只想玩积木，其他玩具我都不碰了！”  
  而且一旦他说出口，就**不能再反悔**——即使他后来想偷偷拿遥控车，也不行了。

> 更关键的是：**这个孩子不需要家长同意**，他自己就能做这个决定！

---

### 🔍 对应回计算机：

- “孩子” = 一个普通用户运行的程序（比如浏览器、Python 脚本、AI Agent）
- “玩具箱” = 整个文件系统（所有文件和目录）
- “只玩积木” = 只允许访问 `/tmp` 或某个特定目录
- “自己主动说” = 程序调用 `landlock_restrict_self()` 系统调用
- “不能反悔” = 限制一旦生效，无法撤销（安全设计）
- “不需要家长同意” = 不需要 root 权限，普通用户就能用

---

### ✅ 所以，Landlock 的本质就是：

> **让普通程序像“自律的孩子”一样，主动给自己戴上“权限手铐”，哪怕它被黑客控制了，也只能在很小的范围内搞破坏。**

而 LSM 是底层的“法律框架”，Landlock 是在这个框架下，**给每个程序发了一张“自我约束承诺书”**，让它能合法地、安全地限制自己。

---

### 💡 再举个真实例子：

你写了一个 Python 脚本，用来处理用户上传的图片。  
你担心万一脚本有漏洞（比如路径遍历），黑客会读取 `/etc/passwd`。

于是你在脚本开头加几行代码（使用 Landlock）：
```python
# （伪代码）只允许访问 /tmp/uploads 目录
landlock.allow("/tmp/uploads")
landlock.lock_down()  # 锁死！
```

从此以后，**就算黑客控制了你的脚本，它也看不到 `/home`、`/etc`、甚至当前目录**——因为它自己“发誓”只碰 `/tmp/uploads`，内核会强制它守信。

---

### 总结一句话：

> **Landlock 就是让普通程序能“自废武功”——主动放弃大部分系统权限，只保留干活必需的那一点点，从而即使被黑，危害也极小。**

这就是“将 LSM 的能力下放给应用程序”的真正含义：**不是让系统管你，而是让你自己管住自己。**
