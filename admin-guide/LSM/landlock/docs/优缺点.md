# 优缺点

Landlock 作为 Linux 内核中一个相对较新的安全模块（LSM），其设计目标是为非特权进程提供一种简单、高效、可组合的沙箱机制。然而，尽管它在易用性和安全性方面取得了显著进步，但仍存在一些固有的**缺陷和限制**。以下是基于 Linux 内核（包括 6.6 及后续版本）官方文档、开发者讨论和社区实践总结出的主要缺陷：

---

### 1. **仅支持目录级粒度（Directory-Only Granularity）**
这是最核心的限制。
- **无法对单个文件设置规则**：`landlock_add_rule()` 系统调用强制要求传入的路径必须是一个目录（通过 `d_is_dir()` 检查）。这意味着你不能为 `/etc/passwd` 这样的具体文件单独授权或拒绝访问。
- **影响**：对于需要精细控制特定配置文件或敏感文件的场景，Landlock 显得力不从心。

---

### 2. **硬链接（Hard Links）绕过风险**
- **问题根源**：Linux 文件系统中，一个 inode 可以有多个硬链接（即多个路径名指向同一个文件）。
- **Landlock 的局限**：Landlock 的规则是基于路径解析过程中遇到的 **dentry**（目录项）来检查的。如果攻击者能通过另一个未被限制的硬链接访问到受保护文件，Landlock **无法阻止**。
- **官方承认**：内核文档明确指出，由于性能和复杂性原因，Landlock **不处理硬链接带来的策略绕过问题**。这是其“有意为之”的设计取舍。

---

### 3. **不支持网络访问控制**
- **纯文件系统 LSM**：Landlock **只关注文件系统相关的操作**（如打开、读写、执行、删除等）。
- **无网络能力**：它**完全无法控制**网络套接字（TCP/UDP）、Unix 域套接字、命名管道（FIFO）等 IPC 机制。
- **后果**：一个被 Landlock 沙箱化的恶意程序，依然可以向外发起网络连接、监听端口或与其他进程通信。要实现完整的沙箱，必须结合其他机制（如 seccomp-BPF、网络命名空间、iptables/nftables）。

---

### 4. **特殊文件系统和挂载点不受限**
- **不受控的文件系统**：Landlock 对某些虚拟文件系统（如 `procfs`、`sysfs`、`devtmpfs`、`cgroupfs` 等）的访问**通常不进行限制**，或者限制效果有限。
- **挂载点逃逸**：如果沙箱内的进程拥有 `CAP_SYS_ADMIN` 能力（即使是部分受限的），它可能通过挂载新的文件系统来绕过现有规则。虽然 Landlock 本身会限制 `mount` 系统调用（通过 `LANDLOCK_ACCESS_FS_REFER` 权限控制），但这增加了配置复杂性。

---

### 5. **继承与组合的复杂性**
- **规则集是“允许列表”**：Landlock 使用的是“白名单”模型。你必须显式地添加所有允许访问的目录。遗漏任何一个必要目录都会导致应用程序崩溃。
- **多层沙箱困难**：虽然 Landlock 支持将多个规则集叠加（通过 `landlock_restrict_self()` 多次调用，权限取交集），但正确地组合多个独立的沙箱策略非常容易出错，且缺乏高级工具支持。

---

### 6. **动态文件系统操作的挑战**
- **符号链接（Symlinks）**：Landlock 在路径解析时会正确处理符号链接，但如果符号链接的目标在沙箱创建后才被创建或移动，可能会导致意外的访问被允许或拒绝。
- **重命名/移动文件**：如果一个被允许的文件被移动到一个未被允许的目录下，Landlock 的行为取决于具体的访问方式和内核实现细节，可能导致不一致。

---

### 7. **缺乏对内存映射（mmap）的细粒度控制**
- 虽然 `LANDLOCK_ACCESS_FS_EXECUTE` 和 `LANDLOCK_ACCESS_FS_READ_FILE` 可以间接控制 `mmap` 的源文件，但对于已经映射到内存的区域，Landlock **没有额外的运行时检查**。这在某些高级攻击场景下可能成为隐患。

---

### 总结

| 缺陷类别 | 具体表现 | 影响 |
| :--- | :--- | :--- |
| **粒度限制** | 仅目录级，不支持单个文件 | 无法精细控制敏感文件 |
| **文件系统特性** | 硬链接可绕过策略 | 安全边界可能被破坏 |
| **功能范围** | 无网络、IPC 控制 | 需要与其他安全机制配合 |
| **特殊FS** | `proc`/`sys` 等可能不受限 | 信息泄露或提权风险 |
| **可用性** | 白名单模型易出错 | 开发和部署复杂度高 |

因此，Landlock 并不是一个万能的沙箱解决方案，而是一个**专注于文件系统访问控制的强大组件**。在实际应用中，它通常需要与 **seccomp-BPF**（控制系统调用）、**Capabilities**（限制特权）、**Namespaces**（隔离视图）等机制**协同工作**，才能构建一个真正健壮的安全沙箱。
