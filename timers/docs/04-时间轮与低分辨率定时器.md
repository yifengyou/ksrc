# 时间轮与低分辨率定时器（Linux 6.6）

> 阅读目标：掌握 `timer_list` API 家族的精确语义（含 6.6 的 `timer_delete`/`timer_shutdown` 更名）；逐行吃透 6.6 的**非级联时间轮**——层级粒度表（LVL_GRAN）、bucket 计算的数学、为什么它比经典级联轮好；走通 `__mod_timer → internal_add_timer` 入队链与 `tick → run_local_timers → TIMER_SOFTIRQ → __run_timers → call_timer_fn` 触发链；理解 per-CPU `timer_base` 的并发保护（running_timer/MIGRATING 迁移锁）与 NOHZ 的迁延到期（`is_idle`/`next_expiry_recalc`）。

代码出自 Linux 6.6 `kernel/time/timer.c` 与 `include/linux/timer.h`。

## 🧰 一、API 家族与精确语义

```c
// include/linux/timer.h (v6.6)
struct timer_list {
	struct hlist_node	entry;        /* 挂 bucket 用 hlist: 删除 O(1) */
	unsigned long		expires;      /* 绝对到期 jiffies */
	void			(*function)(struct timer_list *);
	u32			flags;        /* CPU 号 18bit + 属性位 + bucket 序号 10bit */
};

#define TIMER_CPUMASK		0x0003FFFF   /* 低 18 位: 归属 CPU */
#define TIMER_MIGRATING		0x00040000   /* 正在换 base(迁移窗口标记) */
#define TIMER_DEFERRABLE	0x00080000   /* 空闲 CPU 不为它醒来 */
#define TIMER_PINNED		0x00100000   /* 禁止迁移启发式 */
#define TIMER_IRQSAFE		0x00200000   /* 回调关中断执行 + 可从硬中断等它完成 */
#define TIMER_ARRAYSHIFT	22           /* 高 10 位: 当前所在 bucket 序号 */
#define TIMER_ARRAYMASK		0xFFC00000
```

| API | 语义要点 | 返回值 |
| :--- | :--- | :--- |
| `timer_setup(t, fn, flags)` / `DEFINE_TIMER` | 初始化（`do_init_timer` 记下启动 CPU，flags 只接受三个属性位） | — |
| `add_timer(t)` | **只能用于未挂载**的 timer（`WARN_ON_ONCE(timer_pending)`），等效 `__mod_timer(expires, MOD_TIMER_NOTPENDING)` | — |
| `add_timer_on(t, cpu)` | 指定 CPU 挂载（真"钉死"的唯一方式） | — |
| `mod_timer(t, expires)` | 万能重挂（挂载/未挂载皆可）；同桶快速路径 | 0=原先未挂载，1=原先已挂载 |
| `timer_reduce(t, expires)` | 只提前不推迟（省电场景防"被推迟"） | 同上 |
| `mod_timer_pending(t, expires)` | 只改已挂载者 | 同上 |
| `timer_delete()`（旧名 `del_timer`，6.6 起 inline 别名） | 摘链，**不等**正在跑的回调 | 0/1 |
| `timer_delete_sync()`（旧名 `del_timer_sync`） | 摘链并等回调在所有 CPU 上结束；禁止在中断上下文用（除非 IRQSAFE） | 0/1 |
| `timer_shutdown()` / `timer_shutdown_sync()` | 6.x 新增：摘链 + 置 `function=NULL`，此后任何 rearm **静默丢弃**——解决定时器/工作队列循环依赖的拆卸死锁 | 0/1 |

`TIMER_DEFERRABLE`（头文件注释）：系统忙时正常工作；CPU 空闲时**不**把它当唤醒理由，等下一个非延迟定时器顺路捎带。`TIMER_IRQSAFE`：回调在关中断下执行（为 workqueue 的锁序特设，注释原话"Abuse is monitored!"）。`TIMER_PINNED` 只是"不参与迁移启发式"，跟随**调用所在 CPU**——要钉到特定 CPU 必须用 `add_timer_on()`。

## 🛞 二、非级联时间轮：设计哲学

`timer.c` 头部大注释（Thomas Gleixner, 4.8 重写）的核心论点，忠实转述：

1. **时间轮的绝大多数用户是超时（timeout）**：网络重传、磁盘 IO、锁超时……绝大多数在到期**前就被取消**。真正到期的属于"异常路径"，晚一点触发无关痛痒。
2. 旧的"经典级联轮"追求**精确到期**，代价是级联（cascade）：高层桶到期时要把整桶定时器重新散列进低层——O(n) 抖动、缓存不友好、且大多数工作白做（因为马上又被取消了）。
3. 新设计**放弃级联**：定时器入队时直接按"到期远近"放进对应粒度的层级，永久住在那里直到触发。越远的定时器粒度越粗——**粒度即批处理**（隐式 slack）。
4. 例外是网络栈的短时定时器：它们真的依赖精度，而它们全落在 0 级（HZ 粒度）里，不受影响。
5. 超出最高层级容量的定时器（`WHEEL_TIMEOUT_CUTOFF`）被**强制钳位**在容量上限到期。实测（注释原文）最长观测是 conntrack 的 ~5 天，容量足够。

```c
// kernel/time/timer.c (v6.6)
#define LVL_CLK_SHIFT	3                 /* 相邻层级粒度比 8:1 */
#define LVL_GRAN(n)	(1UL << (3*n))       /* L0:1j, L1:8j, L2:64j, ... L8:8^8 j */
#define LVL_BITS	6
#define LVL_SIZE	(1UL << 6)          /* 每层 64 个 bucket */
#define LVL_DEPTH	(HZ > 100 ? 9 : 8)  /* HZ>100: 9 层; 否则 8 层 */
#define WHEEL_SIZE	(LVL_SIZE * LVL_DEPTH)   /* 576 (HZ>100) */
#define WHEEL_TIMEOUT_CUTOFF   (LVL_START(LVL_DEPTH))
#define WHEEL_TIMEOUT_MAX      (WHEEL_TIMEOUT_CUTOFF - LVL_GRAN(LVL_DEPTH - 1))
#define NR_BASES	2   /* NO_HZ_COMMON: STD + DEF(延迟桶); 否则 1 */
```

注释中的粒度/覆盖表（HZ=1000，9 层）：

```
Level Offset Granularity   Range
  0     0       1 ms       0 ms -          63 ms
  1    64       8 ms      64 ms -         511 ms
  2   128      64 ms     512 ms -        4095 ms
  3   192     512 ms    4096 ms -       32767 ms
  4   256    4096 ms   32768 ms -      262143 ms (~32s-~4m)
  5   320   32768 ms  262144 ms -     2097151 ms (~4m-~34m)
  6   384  262144 ms  2097152 ms -    16777215 ms (~34m-~4h)
  7   448 2097152 ms 16777216 ms -   134217727 ms (~4h-~1d)
  8   512 16777216 ms 134217728 ms - 1073741822 ms (~1d-~12d)
```

读法：第 n 层的 bucket 由"右移 3n 位后的 jiffies"的低 6 位索引——即该层自己的时钟只有 `HZ/8^n` 的频率，转一圈覆盖 64 个该层粒度。总容量 ≈ 12.4 天（HZ=1000）。

**对比经典级联轮**：

| | 经典 TV 级联轮（≤4.7） | 6.6 非级联轮 |
| :--- | :--- | :--- |
| 入队 | 总放当前层，到期临近时逐级 cascade | 一次到位，住在入队时的桶里 |
| 触发开销 | cascade O(整桶) 且不可预测 | O(1)：每 jiffy 只看各层"当前位" |
| 精度 | 名义精确 | 按距离分层放宽（+1 粒度内） |
| 取消 | cascade 白做的工作 | 取消就是 O(1) 摘链——契合"超时多数被取消"的事实 |
| bucket 内顺序 | 按到期排序的链 | **无序 hlist**（同桶共享 bucket_expiry） |

## 🪣 三、bucket 计算：calc_wheel_index 的数学

```c
// kernel/time/timer.c (v6.6)
static inline unsigned calc_index(unsigned long expires, unsigned lvl,
				  unsigned long *bucket_expiry)
{
	/* 防"早到": 入队边界截断 + 外层粒度截断, 都向上取整 */
	expires = (expires >> LVL_SHIFT(lvl)) + 1;
	*bucket_expiry = expires << LVL_SHIFT(lvl);
	return LVL_OFFS(lvl) + (expires & LVL_MASK);
}

static int calc_wheel_index(unsigned long expires, unsigned long clk,
			    unsigned long *bucket_expiry)
{
	unsigned long delta = expires - clk;

	if (delta < LVL_START(1))        idx = calc_index(expires, 0, ...);
	else if (delta < LVL_START(2))   idx = calc_index(expires, 1, ...);
	/* ... 逐级判定 ... */
	else if ((long) delta < 0) {            /* 已过期: 进当前桶, 立刻到期 */
		idx = clk & LVL_MASK;
		*bucket_expiry = clk;
	} else {                                /* 超容量: 钳位到最后一层上限 */
		if (delta >= WHEEL_TIMEOUT_CUTOFF)
			expires = clk + WHEEL_TIMEOUT_MAX;
		idx = calc_index(expires, LVL_DEPTH - 1, ...);
	}
	return idx;
}
```

* `LVL_START(n) = 63 << (3*(n-1))`：第 n 层**只服务** delta 落在 `[LVL_START(n), LVL_START(n+1))` 的定时器——每层独占自己的 delta 范围，永不越界（无 cascade 的根源）。
* **`+1` 的语义**：`expires` 按 3n 位右移后加一再放回，保证触发时刻 ≥ 请求时刻——第 2 层的 100ms 定时器实际落点可能是 128ms，但**绝不早于** 100ms。
* **`bucket_expiry` 与 `expires` 分离**：同桶所有定时器共享桶粒度对齐后的到期时刻；`base->next_expiry` 用桶时刻（粗），而 mod_timer 的"同桶快速路径"用 `timer->expires`（细）比对。
* **过期 delta<0**：放进当前 clk 指向的 0 级桶，`bucket_expiry=clk`——下一个 tick 立即触发。

## 🏠 四、per-CPU timer_base：数据与并发

```c
// kernel/time/timer.c (v6.6)
struct timer_base {
	raw_spinlock_t		lock;             /* 保护本 base 全部状态 */
	struct timer_list	*running_timer;   /* 正在执行的回调(删除同步的判据) */
#ifdef CONFIG_PREEMPT_RT
	spinlock_t		expiry_lock;      /* RT: 删除者与回调的进度握手 */
	atomic_t		timer_waiters;
#endif
	unsigned long		clk;              /* 本轮的"当前 jiffies"锚 */
	unsigned long		next_expiry;      /* 下一个要处理的桶时刻 */
	unsigned int		cpu;
	bool			next_expiry_recalc;  /* 桶空了, 需重扫全轮 */
	bool			is_idle;             /* NOHZ: 本 base 正随 CPU 沉睡 */
	bool			timers_pending;      /* 轮上还有定时器吗 */
	DECLARE_BITMAP(pending_map, WHEEL_SIZE);  /* ★ 非空桶位图: 扫描 O(位图) */
	struct hlist_head	vectors[WHEEL_SIZE];  /* 576 个桶本体 */
} ____cacheline_aligned;

static DEFINE_PER_CPU(struct timer_base, timer_bases[NR_BASES]);
```

* **`pending_map` 是非级联轮的第二根支柱**：找"下一个到期桶"不再扫 576 条链，而是 `find_next_bit` 在 72 字节位图上跳——这让 `__next_timer_interrupt()`（NOHZ 睡前必算）便宜到可以每次都算。
* **`base->clk` 是轮子的时间锚**，可以落后于 jiffies（NOHZ 睡醒后由 `forward_timer_base()` 追平）——所有 delta 计算都以它为基准，而非全局 jiffies。
* **`running_timer` 的三个作用**：`timer_delete_sync()` 的完成判据；`__mod_timer` 拒绝迁移正在执行的定时器（保证回调与重挂的串行）；`try_to_del_timer_sync` 返回 -1 的依据。
* **迁移协议（`TIMER_MIGRATING`）**：换 base 时旧锁未放新锁已取的窗口里，`lock_timer_base()` 用 `READ_ONCE(flags)` 检测 MIGRATING 位并自旋等待；随后校验 `timer->flags == tf` 防止"锁错了 base"。这是两锁交接的无死锁标准姿势（拿锁顺序由迁移方向全局约定）。

**入队链完整版**：

```
__mod_timer(timer, expires, options)
  ├─ 快速路径: 已挂载 && expires 相同 → return 1 (网络栈高频命中)
  ├─ lock_timer_base()                      /* 循环解决 MIGRATING 竞态 */
  ├─ timer->function==NULL? → out            /* shutdown 后静默丢弃 */
  ├─ forward_timer_base(base)                /* 追平 clk 到 jiffies(或 next_expiry) */
  ├─ (已挂载时) 同桶判定: calc_wheel_index 结果 == 旧 bucket 序号?
  │     是 → 只改 timer->expires, 免一次摘挂
  ├─ detach_if_pending()
  ├─ new_base = get_target_base(base, timer->flags)
  │     /* SMP+NOHZ: timers_migration_enabled && !PINNED
  │        → get_nohz_timer_target()  [kernel/sched/core.c: 选半空闲/孤岛 CPU] */
  ├─ base != new_base && running_timer != timer?
  │     → TIMER_MIGRATING 双锁交接 + 改写 flags 的 CPU 位
  ├─ timer->expires = expires
  └─ internal_add_timer(base, timer)
        ├─ calc_wheel_index(expires, base->clk, &bucket_expiry)
        └─ enqueue_timer(base, timer, idx, bucket_expiry)
              ├─ hlist_add_head(&timer->entry, base->vectors+idx)
              ├─ __set_bit(idx, base->pending_map); timer_set_idx(timer, idx)
              ├─ trace_timer_start(timer, expires, flags)     /* tracepoint */
              ├─ bucket_expiry < base->next_expiry ?
              │     → 更新 next_expiry; timers_pending=true;
              │       next_expiry_recalc=false
              └─ trigger_dyntick_cpu(base, timer)   /* 目标 CPU 在睡? 叫醒它! */
```

## 🎯 五、触发链：从 tick 到回调

```c
// kernel/time/timer.c (v6.6) —— 每 tick 的串联(kernel/time/tick-* 调用)
void update_process_times(int user_tick)
{
	account_process_tick(p, user_tick);   /* CPU 时间记账 */
	run_local_timers();                   /* ★ 定时器入口 */
	rcu_sched_clock_irq(user_tick);       /* RCU 的 tick 义务 */
	if (in_irq()) irq_work_tick();
	scheduler_tick();                     /* 调度器 tick */
	run_posix_cpu_timers();               /* CPU 定时器采样(第 7 章) */
}

static void run_local_timers(void)
{
	struct timer_base *base = this_cpu_ptr(&timer_bases[BASE_STD]);

	hrtimer_run_queues();                 /* ① 先跑 hrtimer(低精度模式) */
	/* ② 未到期就不 raise softirq —— 每 tick 必做的最小工作 */
	if (time_before(jiffies, base->next_expiry)) {
		if (!IS_ENABLED(CONFIG_NO_HZ_COMMON))
			return;
		base++;                           /* CPU 醒着, 顺带看延迟桶 */
		if (time_before(jiffies, base->next_expiry))
			return;
	}
	raise_softirq(TIMER_SOFTIRQ);         /* ③ 真正的执行推迟到软中断 */
}
/* → 中断退出路径 irq_exit → invoke_softirq → (或 ksoftirqd) */
static void run_timer_softirq(struct softirq_action *h)
{
	__run_timers(this_cpu_ptr(&timer_bases[BASE_STD]));
	if (IS_ENABLED(CONFIG_NO_HZ_COMMON))
		__run_timers(this_cpu_ptr(&timer_bases[BASE_DEF]));  /* 延迟桶同场结算 */
}
```

设计要点：**检查在硬中断、执行在软中断**。`raise_softirq` 只是置位，真正跑 `__run_timers` 在中断退出（或 ksoftirqd 线程，负载高时）——定时器回调里允许拿进程态锁/做重活，这是时间轮回调比 hrtimer 硬中断回调"宽容"的根源。

```c
// kernel/time/timer.c (v6.6)
static inline void __run_timers(struct timer_base *base)
{
	struct hlist_head heads[LVL_DEPTH];   /* 栈上暂存, 回调期间不持桶 */

	if (time_before(jiffies, base->next_expiry))
		return;                            /* 快速出门 */
	raw_spin_lock_irq(&base->lock);
	while (time_after_eq(jiffies, base->clk) &&
	       time_after_eq(jiffies, base->next_expiry)) {
		levels = collect_expired_timers(base, heads);  /* 摘桶进 heads[] */
		base->clk++;                                    /* 轮子推进 1 jiffy */
		base->next_expiry = __next_timer_interrupt(base); /* 重扫位图 */
		while (levels--)
			expire_timers(base, heads + levels);     /* 逐桶执行 */
	}
	raw_spin_unlock_irq(&base->lock);
}

static int collect_expired_timers(struct timer_base *base, struct hlist_head *heads)
{
	unsigned long clk = base->clk = base->next_expiry;   /* ★ 跳到下个到期桶
                                                           (NOHZ 补账的关键) */
	for (i = 0; i < LVL_DEPTH; i++) {
		idx = (clk & LVL_MASK) + i * LVL_SIZE;
		if (__test_and_clear_bit(idx, base->pending_map))
			hlist_move_list(base->vectors + idx, heads++); /* 整桶搬走 */
		if (clk & LVL_CLK_MASK)      /* clk 低 3 位非 0: 高层"分钟针"没到整格 */
			break;                    /* —— 高层只在每 8 个 jiffy 对齐时才检查 */
		clk >>= LVL_CLK_SHIFT;       /* 换算到上一层自己的时钟 */
	}
	return levels;
}

static void expire_timers(struct timer_base *base, struct hlist_head *head)
{
	unsigned long baseclk = base->clk - 1;   /* 过期时刻是推进前的 clk */
	while (!hlist_empty(head)) {
		timer = hlist_entry(head->first, struct timer_list, entry);
		base->running_timer = timer;         /* 同步协议的旗帜 */
		detach_timer(timer, true);
		fn = timer->function;
		if (timer->flags & TIMER_IRQSAFE) {
			raw_spin_unlock(&base->lock);    /* 关中断保持 */
			call_timer_fn(timer, fn, baseclk);
			raw_spin_lock(&base->lock);
		} else {
			raw_spin_unlock_irq(&base->lock); /* 开中断执行(可被抢占/中断) */
			call_timer_fn(timer, fn, baseclk);
			raw_spin_lock_irq(&base->lock);
		}
		base->running_timer = NULL;
	}
}
```

`call_timer_fn()` 的防御：回调前后比对 `preempt_count()`，不等则 `WARN` 并强制恢复（回调里非法开/关了抢占）；lockdep 副本 map 让"回调持锁、删除者等锁"形成正确的依赖链。回调里 rearm 自己是**允许且常见**的（周期任务惯用法）——`__run_timers` 持 base 锁，rearm 的 `__mod_timer` 会在同锁上排队，无递归风险。

### `__next_timer_interrupt`：位图扫描与"层针进位"

```
__next_timer_interrupt(base)
  对每一层 lvl:
      pos = next_pending_bucket(base, offset, clk & LVL_MASK)
          /* find_next_bit 从 clk&63 起找本层位图的下一个置位位;
             找不到再从层头绕回 —— 模拟环形位图 */
      if (pos >= 0):
          tmp = (clk + pos) << LVL_SHIFT(lvl);   /* 换算回 jiffies 域 */
          next = min(next, tmp)
          if (pos 足够小, 本层结果已早于下次层针进位) break;  /* 剪枝 */
      adj = (clk & LVL_CLK_MASK) ? 1 : 0;        /* 层针未对齐要 +1 进位 */
      clk = (clk >> 3) + adj;                     /* 走向上一层 */
```

源码注释用六位"层针"图解释进位：`LVL1..LVL0 = 0 0 0 0 0 2` 时 LVL0 下一个桶是 2，而所有高层要看 **index 1**（下层针过半，高层桶按"下一个整格"算）；`... = 0 0 0 0 F 2` 则 LVL1 进位到 LVL2。这段"位图上的时钟进位"是非级联轮最精巧的部分——建议对照源码注释逐行读。

## 😴 六、NOHZ：迁延到期与"睡到下个定时器"

CPU 进 idle 前要回答"多久后有活干"。时间轮的回答：

```c
// kernel/time/timer.c (v6.6, NO_HZ_COMMON)
u64 get_next_timer_interrupt(unsigned long basej, u64 basem)
{
	raw_spin_lock(&base->lock);
	if (base->next_expiry_recalc)          /* 桶被动空过(删除) → 重扫 */
		base->next_expiry = __next_timer_interrupt(base);
	nextevt = base->next_expiry;

	/* 把落后于 jiffies 的 clk 追平(最多追到 next_expiry, 防倒拨) */
	if (time_after(basej, base->clk)) { ... base->clk = ... }

	if (time_before_eq(nextevt, basej)) {  /* 已过期: 立刻要 tick */
		expires = basem;
		base->is_idle = false;
	} else {
		if (base->timers_pending)
			expires = basem + (nextevt - basej) * TICK_NSEC;
		if ((expires - basem) > TICK_NSEC) /* 睡超过一个 tick 才值得停 */
			base->is_idle = true;          /* ★ 标记: 远程 enqueue 要叫醒我 */
	}
	raw_spin_unlock(&base->lock);
	return cmp_next_hrtimer_event(basem, expires);
	   /* 无 hres 时还要与 hrtimer 队列的下一个到期取 min
	      (向上取整到整 tick, 防 nohz 停启乒乓) */
}
```

配套的三个机制：

1. **`is_idle` + IPI**：base 睡着后，远程 CPU 的 `enqueue_timer()` 发现新桶比 `next_expiry` 更早且 `base->is_idle`——`trigger_dyntick_cpu()` → `wake_up_nohz_cpu()` **IPI 叫醒**沉睡 CPU 重编程 clockevent。否则睡过头的定时器会等到 CPU 自然醒才结算。CPU 醒来 `timer_clear_idle()` 清标记（免无谓 IPI）。
2. **延迟桶（BASE_DEF）的懒政**：注释明言 idle 逻辑只维护 STD base；`is_idle` 期间**延迟定时器不叫醒 CPU**（`trigger_dyntick_cpu` 对 DEFERRABLE 直接返回，除非对方是 nohz_full CPU）。它们醒后由 `run_timer_softirq` 一次性补结算——这就是"deferrable 粒度可能大范围漂移(by design)"的出处。
3. **结算补账**：醒来后 `__run_timers` 的 `collect_expired_timers()` 把 `base->clk` 直接**跳到 next_expiry**（不是一 jiffy 一 jiffy 走）——睡眠期间错过的"虚拟 tick"不逐个模拟，而是把到期的桶整批摘走，`expires` 粒度内的偏差就此消失。

## 🧹 七、CPU 热插拔与迁移

```c
int timers_dead_cpu(unsigned int cpu)      /* CPUHP 状态机调用, 全局串行 */
{
	for (b = 0; b < NR_BASES; b++) {
		old_base = per_cpu_ptr(&timer_bases[b], cpu);
		new_base = get_cpu_ptr(&timer_bases[b]);   /* 双锁: new→old(嵌套) */
		forward_timer_base(new_base);
		WARN_ON_ONCE(old_base->running_timer);      /* 死 CPU 上不该有回调 */
		for (i = 0; i < WHEEL_SIZE; i++)
			migrate_timer_list(new_base, old_base->vectors + i);
			/* 逐个 detach → 改 flags 的 CPU 位 → 在新 base 重新入轮
			   (bucket 重算, 粒度语义保持) */
	}
}
```

运行时迁移开关：`/proc/sys/kernel/timer_migration`（默认 1）。它由 static key `timers_migration_enabled` 控制 `get_target_base()` 的分支——写 0 后所有定时器钉死在 arming CPU（调试图利器）。

## 💭 九、思考题

1. `calc_index()` 里 `+1` 保证不早到，但代价是同层定时器最坏晚近一个粒度。一个 3 级层（512ms 粒度）的 4096ms 定时器，实际触发时刻在什么区间？`bucket_expiry` 与 `timer->expires` 的差如何被 `timer_gettime` 类观察者感知？
   <details><summary>提示</summary>落在 [4096, 4096+512)ms 的桶边界上，即 [4096,4608)ms 内。观察者（如 /proc/timer_list）看到的是桶粒度；posix 层的 timer_gettimeofday 族看不到（时间轮无用户态直查接口），但 tracepoint timer_start 的 expires 字段是原始值。</details>
2. 为什么 `expire_timers` 要先把桶整体搬到栈上的 `heads[]`，而不是逐个在桶里摘？回调里 rearm 同一个 timer 时，两种实现分别会发生什么？
   <details><summary>提示</summary>回调执行期间 base 锁是放开的：rearm 的 `__mod_timer` 会拿到锁并把这个 timer 挂进某个新桶——若桶还在 base->vectors 里被遍历，"正在被遍历的链"与"新挂入"就会在同一 hlist 上打架。搬栈后原桶已空（pending_map 已清），重挂安全。</details>
3. `collect_expired_timers` 里 `if (clk & LVL_CLK_MASK) break;` 的含义是什么？如果删掉这个 break，高层桶会在什么错误时机被收割？
   <details><summary>提示</summary>LVL_CLK_MASK=低 3 位。非 0 表示本 jiffy 不在 8-jiffy 网格上，高层（层针）"还没走到下一格"——此时高层 idx 处的桶属于未来时刻（bucket_expiry>now），提前收割会触发还没到期的定时器（违反"不早到"承诺）。对照 __next_timer_interrupt 的 adj 进位逻辑。</details>
4. NOHZ idle 中远程 CPU enqueue 一个更早的定时器：IPI 唤醒后那个 CPU 醒来做的第一件时间子系统的事是什么？如果 IPI 丢失（不可能，但假设），超时会推迟到什么时候？
   <details><summary>提示</summary>IPI 的 irq_exit → tick_nohz_irq_exit → （idle 循环里）重新评估停 tick：get_next_timer_interrupt 重算 next_expiry → 重编程 clockevent。丢失则要等 clockevent 原程序点醒来——`base->next_expiry`（IPI 前的旧值），差值就是这次 enqueue 的提前量。</details>
5. `timer_shutdown_sync()` 解决什么 `timer_delete_sync()` 解决不了的拆卸问题？用"定时器调度 work、work 又 rearm 定时器"的循环依赖具体推演一遍死锁。
   <details><summary>提示</summary>delete_sync 返回后 callback 不会再跑，但**已排队的 work 仍会跑**并 rearm 定时器——若内存即将释放就 UAF；为防 UAF 先销毁 workqueue 又会死等 work，而 work 在等定时器锁。shutdown_sync 在 base 锁内置 function=NULL：此后 rearm 静默丢弃，链条从定时器端剪断。源码注释给出了 `timer_shutdown_sync(); workqueue_destroy();` 的标准顺序。</details>
6. 时间轮与 hrtimer 框架在"回调上下文"上的根本区别是什么？为什么 `msleep()` 可以在回调语义上直接复用时间轮（`schedule_timeout`），而 `nanosleep` 走 hrtimer？
   <details><summary>提示</summary>时间轮回调在 TIMER_SOFTIRQ（软中断上下文，不能睡眠但可被延迟到 ksoftirqd）；msleep 是**把当前任务挂上等待队列再睡**，定时器回调只做 `wake_up_process`——回调本身不睡。nanosleep 需要亚毫秒精度与绝对时间语义，时间轮的 jiffies 粒度给不了。</details>
