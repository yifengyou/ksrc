# workqueue 一页速查（Linux 6.6）

> 用法：与 scheduler/interrupt/timers/mm/block 速查同构。事实与分册各章交叉核对（基准 v6.6）。

---

| 结构 | 关键成员 | 详见 |
| :--- | :--- | :--- |
| `work_struct` | `data`（PENDING/INACTIVE 等标志+pwq 指针编码）、`entry`（链表节点）、`func` | [02-work生命周期](02-work生命周期与flush-cancel.md) |
| `workqueue_struct` | `pwqs[]`（per-cpu/unbound 池租约）、`saved_max_active`、flags | [01-cmwq设计](01-cmwq设计与worker-pool.md) |
| `worker_pool` | `worklist`（池级 FIFO）、`nr_running`、`idle_list`、per-CPU 静态双池 | [01](01-cmwq设计与worker-pool.md) |

## 2. 执行模型速记（[01](01-cmwq设计与worker-pool.md)）

```
并发管理：nr_running 追踪未睡眠 worker；per-CPU 池默认只保 1 个
  running——work 睡→池补人（keep_working：worklist 非空 &&
  nr_running<=1）
生灭：有活无人 → maybe_create_worker；idle 超时自杀
  （白送 2 个公式：nr_idle>2 && (nr_idle-2)*4>=nr_busy，
  MAX_IDLE_WORKERS_RATIO=4）
线程名：kworker/u<id>:0H（unbound 高优）/ kworker/<cpu>:<id>
```

## 3. API 三层速记

```
最简：schedule_work(w)  == queue_work(system_wq, w)
延迟：schedule_delayed_work(dw, delay)；mod_delayed_work 改期
自有 wq：alloc_workqueue(name, flags, max_active)；ordered 用
  alloc_ordered_workqueue（=UNBOUND+max_active=1）
flush/cancel：flush_work/flush_workqueue（batch barrier）；
  cancel_work_sync/cancel_delayed_work_sync（状态机见 02 章）
```

## 4. WQ flags 表（本轮补核 v6.6）

| flag | 值 | 语义 |
| :--- | :--- | :--- |
| WQ_UNBOUND | 1<<1 | 不绑 CPU |
| WQ_FREEZABLE | 1<<2 | suspend 冻结 |
| WQ_MEM_RECLAIM | 1<<3 | 回收路径可用（预留 rescuer 线程） |
| WQ_HIGHPRI | 1<<4 | nice=-20 池 |
| WQ_CPU_INTENSIVE | 1<<5 | 脱离并发管理（防饿死他人） |
| WQ_SYSFS | 1<<6 | /sys/bus/workqueue 可见 |
| WQ_POWER_EFFICIENT | 1<<7 | per-cpu 或 unbound 按 wq_power_efficient 切换 |

## 5. system_* 家族（7 个，本轮补核）

```
system_wq("events")——最通用（alloc_workqueue("events",0,0)）
system_highpri_wq / system_long_wq（长活）/ system_unbound_wq /
system_freezable_wq / system_power_efficient_wq /
system_freezable_power_efficient_wq
```

## 6. 数值速记（本轮补核 v6.6）

| 量 | 值 | 出处 |
| :--- | :--- | :--- |
| WQ_MAX_ACTIVE | **512**（注释"I like 512, better ideas?"） | workqueue.h:397 |
| WQ_DFL_ACTIVE（max_active 默认） | **256**（=512/2） | workqueue.h:399 |
| MAX_IDLE_WORKERS_RATIO | 4（idle:busy ≤ 1:4，白送 2） | workqueue.c:95 |
| IDLE_WORKER_TIMEOUT | **300*HZ**（5 分钟） | workqueue.c:96 |
| per-CPU 标准池数 | NR_STD_WORKER_POOLS=2（normal+highpri） | workqueue.c:90 |

## 7. unbound 与 affn_scope（[03](03-unbound池与affinity-scope.md)）

```
unbound 池按 attrs（affinity/cpumask/nice）哈希共享；
affn_scope：cache（默认）/numa/system，WQ_AFFN_SCOPE 标志
wq_unbound_cpumask 全局上限；isolated CPU 的迁移语义见 03 章
```

## 8. 观测速记（★重要勘误）

```
★6.6 已无 workqueue debugfs（/sys/kernel/debug/workqueue 整目录
  不存在——git grep v6.6 全树零命中；老资料常引此路径，勿用）
现行观测面：
  /sys/bus/workqueue/devices/*/（WQ_SYSFS 注册的 wq：cpumask/
    nice/affn_scope 可调）
  tracepoints（include/trace/events/workqueue.h）：
    workqueue_queue_work / workqueue_activate_work /
    workqueue_execute_start / workqueue_execute_end
    —— perf record -e workqueue:workqueue_execute_start 定位执行者
  ps -eLf | grep kworker     # 池规模与命名速览
死锁排查四步（[04](04-使用规范与死锁分析.md)）：谁的池→谁在跑→
  lockdep splat→MEM_RECLAIM 缺失审计
```
